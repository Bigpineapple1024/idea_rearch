## 方法

- **fill**：CDPruner 在 LLM 之前留 64 个（选择不变，按原顺序送进 LLM）。每个剪掉的 patch 的代表 = 投影后特征余弦最大的保留 token（CDPruner 的核用的也是这个相似度）。在每一层，576 个 patch 槽的 K、V 是代表的 K、V（RoPE 之前），按槽自己的位置（35 + patch 编号）旋转；保留的图像 token 在原始位置，图像之后的文字按不剪枝时的编号（35 + 576 + t）；每个 query 看位置不大于自己的槽与 token；生成的 token 也看这 576 个槽。只有 64 个保留 token 计算 query、注意力输出与 MLP；槽的代价是每层一次取数与旋转、以及多出的注意力对，按结构算的 FLOPs 是 CDPruner-64 的约 1.01 倍（冒烟测试的提示上 1.0106）。
- **对照**：shuffle（剪掉的槽的代表在剪掉的槽之间打乱：每个保留 token 代表的槽数与 fill 相同、位置错开）；orig（只换成原始编号，缺口留着，注意力不变）；mass（编号与 CDPruner-64 相同；每个保留 token 作为 key 的注意力 logit 加 log c_i，c_i = 1 + 以它为代表的剪掉的 patch 数：只补注意力质量，不给布局）；b64 = CDPruner-64（EXP-0039）。
- fill − b64 回答“同样的计算量下，把剪掉的图以布局的形式还给 LLM 是否更好”；fill − shuffle 回答“复制的内容是否要紧”；fill − orig 回答“填上缺口是否比只换编号好”；mass − b64 是“只补注意力质量”。

## 机制与预测（推断，只为事后对照，不是判据）

- 位置题：GQA 位置题上 CDPruner-64 比不剪枝低 16.04（F101）；原始编号在 DivPrune 上补回 13.86（F89），位置要从第 1 层起的编号读出（F100）。fill 与 orig 都用原始编号，预测都大幅补回位置题（约 +6～+14）。
- 偏“是”：原始编号留下缺口时偏“是”（F88、F99），多留 token 时偏“是”变小（F105）。fill 没有缺口、视觉内容在注意力里又有 576 个 key，预测“否”题上答“是”不比 b64 多；orig 偏“是”。
- 内容：代表与剪掉的 patch 的平均余弦约 0.70（冒烟测试），复制的内容有误差；预测 fill − shuffle > 0。mass 把一个代表的 logit 加到约 +5（一个保留 token 平均最多代表 168 个槽），方向不确定。
- 整体：VQAv2 约 −0.5～+1，GQA 约 +0.5～+2（位置题约占 GQA 的 10.5%）。

## 风险与边界

- 视觉部分的 KV 缓存按本流程的实现是 9 倍（每层存下 576 个槽；更正：缓存里还有 64 个保留 token，是 (576 + 64) / 64 = 10 倍，DEC-0085）；只存 64 个代表与分配、解码时现算可回到 1 倍（DyMU 的 VTU 一类的高效算法），未实现，要同时报告（2026-11-01 补：紧凑实现已在 EXP-0044 验证，与普通实现逐位相同，图像 KV 缓存 1 倍，F119）。
- 复制同一内容到许多位置（一个保留 token 平均最多代表 168 个槽）可能让模型把一个物体看成多个（计数、存在题），要按题型看。
- 保留的图像 token 也看位置在它之前、但代表在它之后的槽（信息“提前”出现），与训练时的因果结构不同（实现照此预先写定）。
- 开发集多次使用（P14），任何结论都要在新数据与 MME、POPE 上确认（IDEA-0008 的教训，F94、F95）。
