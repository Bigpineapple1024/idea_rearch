# 六篇论文总结与视觉 Token 压缩趋势

阅读日期：2026-10-23。范围：此前推荐的 DUET、TQNet、WPMixer，以及用户指定的 FastV、SparseVLM、VisionZip；趋势分析只针对后三篇。已阅读原文的方法、主结果及相关消融/附录，并静态核对关键源码。未下载模型权重、未复现实验、未核实引用量排名。

> 定位更新（2026-10-23，[DEC-0014](version-evolution.md)）：用户确认用“近三年、效果差一点”的 baseline，视觉方向改为以 FastV 为主 baseline，VisionZip、SparseVLM 只作对照。下文“VisionZip 开发”的分工是写作时的定位，论文内容分析不受影响。

**判断：用户提出的“VisionZip 开发、FastV 与 SparseVLM 对照”分工合理。真正值得继续研究的是压缩后丢失了什么信息、在什么问题下丢失，以及节省是否转化成实际延迟收益。** 三篇只能说明这组工作的研究脉络，不能代表截至 2026 年整个领域的最新趋势或最强方法。

## 1. 六篇分别解决什么

| 论文 | 核心问题 | 方法与贡献 | 阅读后的判断 |
| --- | --- | --- | --- |
| [DUET，KDD 2025](https://arxiv.org/abs/2412.10859v3) | 时间分布变化、通道相关性复杂，统一建模容易混入噪声 | 时间端用路由器选择多个线性模式提取器；通道端在频域学习距离、产生软聚类掩码，再融合预测 | 适合研究“哪些通道/模式应该共享信息”；模块可拆分，但不是简单的通道分组。预测提升不能证明聚类找到了真实因果机制 |
| [TQNet，ICML 2025](https://arxiv.org/abs/2505.12917v2) | 单个样本的通道相关性容易被异常点、缺失和噪声干扰 | 周期平移的可学习向量作为 Q，当前样本作为 K/V，结合全局规律和当前输入；一层注意力配轻量 MLP | 三个时序候选中结构最简洁，便于单变量归因；依赖周期先验，弱相关或长历史场景收益可能下降 |
| [WPMixer，AAAI 2025](https://arxiv.org/abs/2412.17176v1) | 单一时间尺度难以同时表达低频趋势、高频细节和突变 | 多层小波分解，各分辨率独立做 patch/MLP mixing，预测系数后逆小波重建 | 适合研究频段与局部/全局信息；调参预算、损失函数和历史窗口必须控制，不能把收益全归因于小波 |
| [FastV，ECCV 2024](https://arxiv.org/abs/2403.06764v3) | 大量视觉 token 在 LLM 深层仍消耗计算 | 先让完整视觉输入经过前 K 层，再依注意力排名裁掉部分视觉 token | 是这组三篇中的早期代表和简单对照；不能据此称为所有视觉 token 压缩的首创 |
| [SparseVLM，ICML 2025](https://arxiv.org/abs/2410.04417v4) | 只按粗糙注意力删 token，可能丢掉当前问题需要的信息 | 选择与图像相关的文本 raters，给视觉 token 打分；逐步稀疏，并聚类回收部分被删信息 | 贡献包括文本选择、稀疏程度与回收；不能简化为“改一下 top-k 打分” |
| [VisionZip，CVPR 2025](https://openaccess.thecvf.com/content/CVPR2025/papers/Yang_VisionZip_Longer_is_Better_but_Not_Necessary_in_Vision_Language_CVPR_2025_paper.pdf) | 等进入 LLM 再剪枝，前几层已承担长视觉序列的成本；视觉特征本身已冗余 | 在视觉特征输出端保留 dominant tokens，把其余信息合成 contextual tokens，再进入 projector/LLM | 接口集中、免训练版本易做单卡研究，适合作为当前开发基线；高压缩下的细节保真、问题适应性仍需诊断 |

时序组三篇共同关心“怎样组织信息、减少不可靠交互”，视觉组三篇关心“有限计算预算下怎样保留必要信息”。这是概念上的联系，不足以证明小波、聚类或周期查询可以直接迁移到视觉压缩。

## 2. 前三篇的结果与边界

- **DUET：**正文报告 25 个数据集、10 个领域，正文主表列出 10 个常见数据集。Table 2 的 Traffic 四个预测长度平均 MSE，完整模型为 0.393，去掉通道聚类模块为 0.439；说明该模块在这个设置下有用。Table 3 从多个历史窗口选择各模型最好结果，不能与 TQNet 的固定窗口表直接排榜。路由权重和通道掩码的可视化是解释线索，尚不是分布或因果关系的真值。
- **TQNet：**Table 2 在 12 个数据集、固定历史长度 96 下，按四个预测长度平均后的 24 个 MSE/MAE 项中，22 项进入前二。例如 Electricity 的 MSE 为 0.164，iTransformer 为 0.178；并非所有数据集都第一。作者在 limitations 明确指出周期依赖、弱通道相关性和长历史窗口的边界。附录报告 RTX 4090 24GB，提供单卡可行性依据，但本项目还未在 3090 测试。
- **WPMixer：**有“优化历史窗口”和“统一设置”两套结果。统一设置 Table 4 中，ETTh1 平均 MSE 为 0.422±0.001，TimeMixer 为 0.447±0.002；Weather 为 0.243 对 0.240，Traffic 为 0.489 对 0.484，因此不能称为处处胜出。作者报告三种随机种子；模块消融还分别搜索超参数，不能视为完全保持其他设置不变的单变量实验。ETT/Weather 用单张 4090，Electricity/Traffic 用两张 A100，后两者不能直接承诺单张 3090 原配置复现。

## 3. 修正用户给出的视觉方法表

| 维度 | FastV | SparseVLM | VisionZip |
| --- | --- | --- | --- |
| 压缩位置 | LLM 已完成前 K 层之后，对后续层裁剪 | LLM 内多个位置逐步裁剪 | 视觉编码器选定层的输出特征处，进入 projector/LLM 之前 |
| 重要性来源 | LLM 注意力；官方代码有跨头平均后取最后一个 query token 的实现 | 预先挑选视觉相关文本 token，再平均这些 raters 到视觉 token 的注意力 | CLIP 的 CLS 注意力；无 CLS 的编码器使用平均被关注程度 |
| 被删信息 | 基本直接舍弃 | 回收部分高分待删 token，聚类重建 | 用 key 特征相似度把非主导信息合并为 contextual tokens |
| 问题依赖 | 最后 query 的注意力受上下文影响，不能严格称为与文本无关 | 明确依赖问题文本 | 选择过程与问题文本无关 |
| 训练 | 免训练 | 免训练 | 基础版免训练；带 ‡ 的成绩额外微调 projector |
| 开发代价 | 要进入 LLM，区分 mask 与真正缩短序列 | 涉及 raters、逐层 token 数、合并、位置和缓存 | 主要在视觉特征接口，但仍需核对 CLS、位置恢复和模型适配 |

**三处实现细节必须保留：**

1. FastV 原文 §4.1 描述平均接收注意力，官方代码则存在“跨头平均、取最后一个 query”的具体实现。论文中的“第 K 层后”和代码中零基索引 `idx == K` 前处理并不矛盾；复现要写清索引。旧 mask demo 不等于实际 token dropping，不能直接用它测加速。
2. SparseVLM 官方 `v1.5` 分支默认 `pruning_loc=[2,6,15]`，这是代码配置，不是所有模型固定的数学要求。论文有基于矩阵秩的自适应公式，而该分支 `score.py` 使用固定阶段保留数量；例如标为 192 的配置是 `[300,200,110]`，后面还会加入回收 token。**配置名称、最后一层 token 数和计算预算不能混为一谈。** 主分支已包含 SparseVLM+，本次没有把它的结果混入 ICML 2025。
3. VisionZip 的“编码器里压缩”更准确地说是利用选定视觉层的特征/注意力，在送入 LLM 前压缩。核验代码仍先执行视觉塔，不代表省掉了整个视觉编码器计算。LLaVA-1.5 的 64-token 设置为 54 dominant + 10 contextual；当前代码还包含 CLS 计数处理，实验时要记录实际张量长度。

## 4. 数字应该怎样读

| 来源及设置 | 作者报告的结果 | 正确解读 |
| --- | --- | --- |
| FastV Table 1，LLaVA-1.5-13B，K=2、剪掉 50% | 四个任务的表内 Avg 73.6→73.6；理论 FLOPs 154.6B→84.6B | 约 45% 是该理论计算口径的降幅；不是端到端延迟减半。四种原始指标的算术平均也不是统一“准确率” |
| SparseVLM Table 1，LLaVA-1.5-7B，标为 Retain 192 | 八个任务归一化平均保留 99.1%；延迟 57.82→36.50ms | 约 36.9% 延迟下降，作者单 A100-80GB 的口径；不是 3090 实测 |
| VisionZip Table 1，LLaVA-1.5，576→64 | 免训练保留归一化平均表现 94.0%；微调 projector 后 95.2% | 64/576=11.1% token；94% 是各任务分数相对原模型的比值再平均，不是原始准确率 94%，也不是损失 6 个准确率百分点 |
| VisionZip Table 4，LLaVA-NeXT-7B，2880→160，POPE、单 A800 | prefill 218→27.8ms；总时间 2293→756s | prefill 约 7.8 倍，总时间约 3.0 倍，两者不可互换 |

以上均为作者实验，不是本项目测得。不能把 FastV 的 B-FLOPs、SparseVLM 的 T-FLOPs 和 VisionZip 的整套数据集运行时间拼成统一排名。

**尤其不能拿 94.0%、99.1% 直接比较谁更强：**token 预算和任务集合不同。VisionZip Table 1 的对手明确标为 `SparseVLM(2024.10)`；SparseVLM 2025 年版本的结果有所变化。正式比较需要同一 checkpoint、图像分辨率、prompt、评估集、生成长度、精度、attention kernel，并同时展示实际延迟和质量的折中曲线。

## 5. 从这三篇看到的趋势

### 从证明冗余，到解释该保留什么

FastV 用浅层计算后的剪枝结果说明深层不必一直携带所有视觉 token。SparseVLM 进一步问“当前问题需要哪些视觉信息”；VisionZip 进一步问“信息实际上聚合在哪些视觉特征里”。这不是简单的更精巧 top-k：研究对象逐步转向信息的承载方式。

### 从纯删除，到保留代表信息并回收上下文

SparseVLM 的 recycling 和 VisionZip 的 contextual merging 都说明：低排名 token 不等于零价值。值得追问的是细节是否被混合、少数对象是否被忽略，以及信息损失集中在哪类任务。OCR、计数、空间关系可以作为诊断分组，**当前不能声称它们已在本项目失败**。

### 压缩位置前移，质量与系统成本一起评估

进入 LLM 前减小序列可以节省前几层开销，且较少侵入语言模型内部；LLM 内选择则能利用问题相关信号。两条路线各有条件，不能概括成“文本引导已经过时”。稀疏打分、聚类、attention 导出、缓存维护也有成本，应把理论 FLOPs、首 token 延迟、后续解码、端到端时间和显存分开。

### 从单轮平均分，转向复用与细节边界

VisionZip §4.3/Fig.7 指出问题相关缓存可能不适合下一轮问题，提供了案例和动机。这个证据尚不足以证明所有文本引导方法在所有多轮场景必然失败：重新编码、保留全量特征或不同缓存策略都会改变结论。未来问题可以围绕“同一压缩表示能否应对不同问题”“小信息是否在合并中消失”，但其新颖性须扩大检索核实。

### 一个现成组合已经做过

VisionZip §4.2/Table 5 在 TextVQA 上报告：SparseVLM 从原始 576 token 选到 64 得 51.1；先提供 VisionZip 选出的 128 token 再到 64 得 52.5。屏蔽前 50 个视觉高注意力 token 后，结果降至 46.4。这为“视觉信息承载与文本选择可能错位”提供了局部证据，**同时证明“VisionZip + SparseVLM”这个组合本身已经不是未做过的想法**。更深的机制、适用条件和反例仍可研究。

## 6. 对当前项目的定位

以用户的单张 RTX 3090 24GB 为资源约束，优先考虑 **LLaVA-1.5-7B + 免训练 VisionZip**。7B 的半精度语言权重约 14GB，还需要视觉塔、激活、KV cache 和框架开销；只能说值得先做 batch=1 的显存/延迟检查，不能在未运行时保证全评估配置可用。13B 全精度及论文中的 8 卡训练不作为单卡默认任务。

FastV 作为简单剪枝对照；SparseVLM 固定到原方法的 `v1.5` 分支，并核对论文与阶段预算差异。三者和不压缩模型在同一评估协议下比较，先找到可重复的失败类型，再进入 idea 设计。不要因为局部 attention 更集中就断言整体任务一定改善。

下一步的证据重点是：保留 token 的信息承载、被合并细节的可恢复性、问题切换后的变化，以及 3090 上真实成本。可交接的 P/F/M/E 矩阵见 [Mode C 分析](视觉Token压缩_ModeC.md)。这里只定位候选问题，尚未生成或执行实验方案。
