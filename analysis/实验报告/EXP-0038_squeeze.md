## 4. 解释与不确定性

- **最支持的解释**（AI，未检验）：只在第 0 层用稀疏的原始编号，就让是非判断偏“是”（nopeekc 的损失都在“否”题上）；借看（第 0 层看全图、被剪的只作 K、V）把它拉回，所以 peekc − nopeekc 的增益是补回 nopeekc 自己的损失；编号连续时（DivPrune-61）没有偏“是”可纠正，第 0 层看全图也没有带来可检出的增益（M23 定稿）。位置题要从第 1 层起的编号读出，第 0 层的位置与借看都不够（M24 的补充）。
- **替代解释**：peekc 第 0 层多算了被剪的 515 个的 K、V（按结构 FLOPs 0.998 倍，本实现第 0 层完整计算 1.106 / 1.104 倍），计算量与 DivPrune-61 不完全相同；开发集多次使用的偶然（P14）；只有 VQAv2、GQA 两个开发集。
- **当前证据不支持的强结论**：“借看能加在先剪后送之上带来增益”（peekc − DivPrune-61 没有检出）；“题目 token 在第 0 层读到了留下的 token 没有的信息”（M23）。
- **运行前的预期**（notes.md，推断，只为事后对照）：四条都符合——整体 peekc − DivPrune-61 两个区间都含 0；nopeekc 的损失主要在“否”题上、peekc 回到 DivPrune-61 附近；peekc − nopeekc 的对数几率在“否”题上为负、“是”题上更小；GQA 位置题上第 1 层起连续编号的四个配置相近、都比 peek、nopeek 低 10 分以上。预期写于读过 0038.md 之后（整体的 Q2 与 nopeekc − DivPrune-61 已知），只有本脚本算的量是没看过的。
