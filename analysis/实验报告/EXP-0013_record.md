### 开发集 coco_dev3

- 生成：`make_coco_dev3.py`。保留 coco_dev 的 1800 题（编号、文字、标签都不变：900 个正样本、900 个 random 负样本）；在同样 300 张图上，每张图再加 3 个 popular、3 个 adversarial 负样本（编号 1801～3600）。
- 做法按 POPE 论文（arXiv 2305.10355 第 5.1 节）的描述：
  - popular：全数据集最常见、但图中没有的 3 个类别；
  - adversarial：与图中已有类别共现最多、但图中没有的 3 个类别（共现数 = 同时含两类的图像数，对图中已有的各类求和）。
  - 频率与共现在 POPE 没用到的 COCO val2014 图像上统计；“图中没有”以 COCO 标注为准，会漏掉少数未标注的物体（F27）。

- 只用于挑选，不用来报告准确率。

### 要回答的问题

1. **Q1 阈值偏移还是区分力下降**：把第一个回答 token 的 log P(▁Yes) − log P(▁No) 记作 margin，用它区分正负样本，算各 split 的 AUC。如果变体的 AUC 与 vanilla 相近、只是误报更多，误报主要来自判定阈值的偏移，一个常数偏置就能修正（H2）。如果 AUC 明显更低，说明选择本身丢掉了区分正负所需的信息。
2. **Q2 浓度**：保留的 30 个 token 中，按物体名余弦选的越少，误报是否越少（H1）？用同一预算的混合选择检验：20、15、10 个按物体名余弦，其余按强对照的分数（去位置 + 分块 + 排除填充区），第二轮先填第一轮没占的块，所以 30 个 token 仍在 30 个不同的块里。
3. **Q3 相似物体**（H3）：变体在 adversarial、popular 负样本上的误报，是不是因为保留的 token 落在图中另一个、与被问物体相似的物体上（例如问叉子时留下了刀）？描述：保留的 token 中，与 80 个 COCO 类名比、最像被问类名的比例；落在其他已标注物体框里的比例；比较误报题与非误报题。干预：**对比打分**，即物体名余弦减去同一个 token 与其他 79 个类名余弦的最大值（contrast_max）或均值（contrast_mean）。这是开放集识别里“与其他类别比、而不是只看相似度本身”的做法：刀的 token 更像“knife”，打分就低。H3 成立时，对比打分应在保住召回的同时减少误报，contrast_max 的效果应比 contrast_mean 明显。
4. **Q4 修正**：在开发集上，哪种同预算的修正 F1 最高？它在 POPE 上是否比变体好？

按用户的通用规则“方案的验证顺序应该优先考虑该方案是否可能成功，而不是改方案仅需改几行代码”（DEC-0009、DEC-0023），修正的候选不只限于改动小的混合与校准；对比打分改动更多，但机制上直接针对“相似物体被当成证据”。

### 离线计算（`analyze_fp.py`）

- **开发集 F1**：三个 split 的 F1 均值（yes 为正类），同时报告召回、各 split 的误报数与精确率。配对差用按图像重抽的 bootstrap（1000 次，种子 0）。
- **校准的变体**（离线）：答 yes 当且仅当 margin > b。b 在 [−4, 4] 内按 0.25 取值，取开发集 F1 最高的。
  - 判定用两折交叉：300 张图按文件名排序、按奇偶分两折，在一折上选 b、在另一折上计分，两折合并。
  - 同时报告在全部开发集上选 b 的结果（样本内，偏乐观），以及 vanilla 自己的最优 b（看校准是不是对所有模型都有用）。

- **Q3**：R01 的类名余弦 + R03 的保留集合 + COCO 物体框。
- **描述项**：开发集正样本上小物体（面积 ≤ 1.35%）至少保留一个 patch 的比例；物体上保留的 patch 数与答 yes 的关系。
