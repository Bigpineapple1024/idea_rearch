## 1. 事实与证据边界

- **研究问题**（记录内深挖，看过分析之后提出）：
  - VisionZip 上，定位框是否盖住题目点名的物体；覆盖的增益是否落在盖住的题上（FastV 一族上是这样，F50）；
  - 定位的作用落在哪类题上：题目是否点名图中的 COCO 物体，是不是颜色题；
  - 两种底座各有所长时，按题目句式拼接（被路由的题用 FastV K = 1 路由，其余用 VisionZip-64 + 覆盖 16）会怎样。
  - 本报告另从 0028.md 预先写定的“同时报告”中整理：只集中为什么没有作用，挪得更多（覆盖 32）会怎样，每题覆盖在被路由的题上，局部与整体收益和代价。
- **单位**：VQAv2 dev2 5192 题（1000 张图）、GQA val400 4786 题（400 张图）。定位分组（locate_dev2、locate_dev2b）只做了 VQAv2 dev2；拼接（splice_dev）两个开发集都做了。配对差按图像重抽（1000 次，种子 0），与 analyze_0028.py 用同一组重抽。
- **数据**：只读已封存的运行：答案（EXP-0028-R01、R02、R13～R16、R19～R22，EXP-0026-R03、R04）与 EXP-0028-R13 的覆盖记录（vz.json）；函数来自已提交的 analyze_0024.py、analyze_0028.py（code/token-pruning 7ba3657）。话题物体取 analyze_0024.topic_masks（题目点名、图中有的 COCO 物体的 patch），框盖住其中至少一半记为盖住。不调用模型。
- **数据质量**：
  - R03～R12 都在第一、二题因同一个 dtype 错误退出：visionzip_cover 把 float32 的视觉塔第 −2 层直接送进 float16 的投影层。R04、R06、R08、R12 各写出 1 个被路由题的答案，没有看、没有计分。修正后以 R13～R22 重跑，全部 completed，答案数完整（DEC-0047）。失败的 10 次不计入 IDEA-0006 的 30 次上限（DEC-0050）。R01、R02 不加载 visionzip_cover，不受影响。

## 4. 解释与不确定性

以下按 EXP-0028 当时的证据写；EXP-0029 之后的补注在本节末尾。

- **最支持的解释（AI）**：
  - **只集中为什么没有作用**：记录给的可能原因是，FastV 的选择偏向图像下部（EXP-0006、F16），把名额挪向中部本身就补上一部分；VisionZip 的 CLS 注意力不一定有这种偏差（没有检验）。S4 与此相符：同样大小的框，VisionZip 留在居中框里的主导 token 不比留在定位框里的少（32.3 / 34.8 对 31.5 / 33.6），居中框里它本来就留得不少，再挪进约 15 个，补不到新的证据。
  - **定位的作用在哪里**：主要在没有点名 COCO 物体的颜色题上（覆盖 16 − 居中框 +9.18，243 题，S3）。点名物体、框又盖住了物体的题上，定位部分与 FastV 一族相近（+0.69 对 +0.86，区间都含 0，S1）。所以 F57 的“来自定位”限定为主要在颜色题上（记录内深挖的结论）。
  - **挪得更多为什么没有更好**：覆盖 32 时 92% / 97% 的题 53 个主导 token 全进了框，框外的高注意力 token 被挤掉（IDEA-0006 的风险②，S5）。
  - **每题覆盖**：VQAv2 的 yes/no、计数题同样问到图中的物体，框里的证据也有用（F58）。GQA 的二选一题受损：题目点名两个物体时，一个框可能只盖住其中一个（推断，没有检验）。
  - **两种底座各有所长**（S7）：被路由的题上 K = 1 的题目查询路径更好，不路由的题上 VisionZip 的 CLS 排序加覆盖更好（VQAv2；GQA 上只有 +0.19）。IDEA-0007 卡片给的原因：FastV 第 0 层的注意力有位置偏差（F16），开放式题上它的排序不如编码器的 CLS 注意力（推断，没有检验）。
- **替代解释**：
  - ①开发集上的噪声与挑选：增益只有 +0.5～+1.4，GQA 上区间都含 0；从 3 个候选中选了最好的；dev2、val400 已用于 IDEA-0004～IDEA-0006 的开发。
