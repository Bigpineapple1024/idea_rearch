### 计算量的口径（三种都报）

- **每层的 token 数**（本项目一直用的口径）：DivPrune-64 每层 64；peek、nopeek、peektext 第 0 层 576 个、之后 61 个，层平均 (576 + 31 × 61) / 32 = 77.1。

### 观察与解释

- **peek 的增益可以拆成两部分**（同一批题的逐题得分，恒等）：peek − DivPrune-64 = (nopeek − DivPrune-64) + (peek − nopeek)：VQAv2 +0.18 = −1.95 + 2.13，GQA +2.34 = +0.38 + 1.96（四舍五入）。前一项是同样的 DivPrune 选择下“61 个按原始位置编号、第 0 层看不到被剪的”对“64 个连续编号”（原始位置编号与少 3 个 token 混在一起），后一项是“第 0 层看过被剪的 515 个”。
- **第 0 层看过被剪的 patch 在两个集上都有约 2 分的作用**（Q2），集中在是非题（+3.68 / +3.91）与 GQA 的 obj（+6.08）、logical（+5.38）、verify（+2.64）题，即“图中有没有某物”“两者是否都有”这类题；属性题没有检出，二选一、计数、颜色题为 0 左右（F85）。只让题目看（peektext）与 peek 几乎相同（−0.13 / +0.10），作用几乎全部经由题目 token 在第 0 层读到被剪的 patch；留下的 61 个在第 0 层“吸收邻居”没有可见的作用（F86）。
- **原始位置编号（与少 3 个）有方向相反的作用**（F87）：nopeek − DivPrune-64 在两个集的是非题上都约 −3.6，VQAv2 整体 −1.95；在 GQA 二选一、属性题上 +8.94、+4.41。F78（K = 1 留 47 在 GQA 属性、二选一题上补回约一半）在 nopeek 里同样出现，说明那部分增益多半来自 K = 1 的结构（原始位置编号），而不是第 0 层看过全部（AI；原始位置编号与少 3 个 token 没有分开的运行）。按 peek − K = 1 留 47（14 个 token 约 +1.5）推算，3 个约 0.3，nopeek − DivPrune-64 的大部分来自位置编号（AI，未检验）。
- **离不剪枝**：peek 在 GQA 上把距离从 6.25 缩到 3.91（属性题 −9.92 → −4.16，二选一 −11.42 → −2.48），VQAv2 上只从 3.78 缩到 3.61。第 1 层起多留 14 个（对 K = 1 留 47）补回了 VQAv2 的颜色题（+4.41 [+2.33, +6.80]），计数题仍比 DivPrune-64 低（−1.90，区间含 0）。
- 以上解释都是事后的，标 AI 的未检验；按题型的分组只作描述（分组多，没有多重比较校正；GQA 的属性、二选一两类是看过 EXP-0032 的分组之后挑出来的）。
