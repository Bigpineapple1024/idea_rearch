## 二、不能写的主张

| 不能写 | 原因 |
| --- | --- |
| “减少幻觉” | 误报比不剪枝还多（F41）；POPE F1 的提升来自召回 |
| “首次按题型剪枝 / 首次文本引导剪枝” | CLASP（arXiv 2604.12767）、VIP-Router（arXiv 2609.10346）；文本—图像相似度选 token 已有 CDPruner、AdaFV、TRIM 等（IDEA-0003 的检索） |
| “FastV 与文本无关” | 文献视其为受文本影响；本项目只测得“几乎不随题目变化” |
| “一般题目上提升 / 不伤害”（不加限定） | 只有路由版本在 VQAv2 上显著提升（CL-8），A′+B+V 本身在 VQAv2 上差异不显著；MME 差异不显著，没有非劣效界限 |
| “优于 VisionZip / SparseVLM”（不加限定） | 只在 POPE 64 档（及 128 档的 VisionZip）上成立；128 档与 SparseVLM 持平，192 档与两者持平；VQAv2 上低于 VisionZip-64（CL-10） |
| “oracle 上界还能再挖 6.9 个点” | 任意两种方法的逐题 oracle 都有同量级的“上界”（SQZ-EXP-0020 S5） |
| “可视性加权有效” | 在切分之外没有可检出的贡献（EXP-0016） |
| “题目焦点” | 问答术语的 focus 指答案所指的部分；被点名的物体是题目的话题 |

## 三、共同的限定（写进局限）

- 一个模型、一种剪枝位置（K = 2）、贪心解码，没有跨模型复验。
- IDF 与位置先验都在被评测的题目文字上估计（不用标签）；可视性只用 coco_dev 的图像。
- POPE 的题目只问 COCO 类别；VQAv2 用验证集的本地子集，图像可能出现在 LLaVA 的指令数据中（只影响绝对值）。
- 预算按 32 层平均的视觉 token 数计；每题耗时含 Python 与生成开销。
- 候选 1 到 EXP-0020 共用 55 次运行，EXP-0021 后 59 次（上限 60）；所有失败运行都保留。
- 路由规则在 VQAv2 test1 上看过结果后选定，只在 test2 上确认过一次；按句式区分只针对英文 VQA 式短问句。
