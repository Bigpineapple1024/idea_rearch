## 三、共同的限定（写进局限）

- 一个模型、一种剪枝位置（K = 2）、贪心解码，没有跨模型复验（2026-10-29 补注：IDEA-0005 起另有 K = 1（第 1 层剪、留 47 个），IDEA-0006 以 VisionZip-64 为底座；其余不变）。
- IDF 与位置先验都在被评测的题目文字上估计（不用标签）；可视性只用 coco_dev 的图像。
- POPE 的题目只问 COCO 类别；VQAv2 用验证集的本地子集，图像可能出现在 LLaVA 的指令数据中（只影响绝对值）；GQA 用 testdev-balanced 的全部 12578 题。
- 预算按 32 层平均的视觉 token 数计；每题耗时含 Python 与生成开销。
- 候选 1 到 EXP-0021 共用 59 次运行，EXP-0022（GQA，含失败的 R03 与重跑 R09）后 68 次，正好是上限（DEC-0034）；所有失败运行都保留。
- 路由规则在 VQAv2 test1 上看过结果后选定，在 test2 与 GQA testdev 上各确认一次（规则冻结）；按句式区分只针对英文 VQA 式短问句。
- （2026-10-29 补）开发集 VQAv2 dev2、GQA val400 用于 IDEA-0004～IDEA-0006 的开发与选择（反复使用）；确认集 VQAv2 test3、GQA testdev 用于 IDEA-0005、IDEA-0006 的确认；IDEA-0007 的确认改用新抽的 VQAv2 test4、GQA val400b（DEC-0051）。
- （2026-10-29 补）开发集上的小差别不可靠（CL-16，F59）：只用于选择，结论以新数据上的预注册检验为准。
- （2026-10-29 补）文献中的对比数字（CoverPruner、FSR 的表）从 HTML 页或摘要摘录，引用前对照 PDF；本项目没有在同一流程中运行这些方法（DivPrune-64 在 EXP-0032 的计划中；2026-10-30 补注：运行中；20 点补注：已完成，开发集上 DivPrune-64 − VisionZip-64 +2.20 / +1.63，EXP-0032）。
- （2026-10-29 补）每个配置只运行一次（贪心解码，结果确定）；区间都是按图像重抽的配对 bootstrap，多个分组与多次比较没有做多重比较校正。
