## 64 个 token 时的强方法（LLaVA-1.5-7B）

CoverPruner（arXiv 2609.03158 v1，EMNLP 2026 main）的 Table 1，保留 64 个 token（576 个中留 64 个，即剪掉 88.9%、保留 11.1%（原写“576 个中留 64 个，88.9%”，88.9% 是剪掉的比例，不是保留的比例；2026-10-29 完整阅读补注））。
按它的摘录，表中的数字是它自己的对比（来源与实现未逐一核对）：

| 方法 | VQAv2 | GQA | TextVQA | POPE | MME |
| --- | --- | --- | --- | --- | --- |
| FastV | 55.9 | 46.0 | 51.6 | 35.5 | 973.5 |
| PDrop | 56.3 | 46.1 | 49.2 | 40.8 | 982.2 |
| SparseVLM | 66.9 | 52.0 | 52.1 | 69.7 | 1190.4 |
| PruMerge | 71.3 | 55.4 | 52.0 | 75.7 | 1316.8 |
| DART | 71.3 | 54.7 | 54.7 | 73.8 | 1365.1 |
| TRIM | 72.4 | 56.1 | 49.7 | 85.9 | 1350.9 |
| VisionZip | 72.4 | 55.1 | 55.5 | 77.0 | 1365.2 |
| DivPrune | 74.1 | 57.5 | 54.5 | 85.5 | 1334.7 |
| MMTok | 75.2 | 58.3 | 56.0 | 85.8 | 1371.5 |
| CoverPruner | 75.9 | 58.4 | 55.6 | 86.1 | 1432.4 |
| 不剪枝 | 78.5 | 61.9 | 58.2 | 85.9 | 1506.5 |

- CoverPruner：在投影层输出空间上做“按题目加权的覆盖最大化”（facility location：f(S) = Σ_i w_i max_{j∈S} A_ij，A 为去均值后截到 0 的余弦相似度，贪心按边际增益选）；
  权重 w 来自“第一层注意力探针”：用第 0 层的 input LayerNorm 与各头的 W_Q、W_K，算题目 token 对视觉 token 的注意力（不跑整层）。在进入 LLM 之前选一次。
- 其余同类（只看了摘要或检索结果）：MMTok（arXiv 2508.18264，ICLR 2026，视觉与文本的覆盖最大化）；SCOPE（arXiv 2510.24214，显著性 + 覆盖，64 个时保留 96.0%）；
  HoloV（arXiv 2510.02912，64 个时 95.8%）；ZOO-Prune（arXiv 2509.24837，64 个时 95.2%，DivPrune 94.4%）。

**含义（推断）**：64 个 token 时，覆盖 / 多样性一类比 VisionZip 高约 +1.7～+3.5（VQAv2）、+2.4～+3.3（GQA）。
IDEA-0006 的所选在开发集上比 VisionZip-64 高 +1.36 / +0.52，小于 DivPrune 的差距；FastV 一族的最好配置与 VisionZip-64 持平或略好（F56）。
就“提升大”而言，我们目前的方法落在这一类之后。

## DivPrune（arXiv 2503.02175 v2，CVPR 2025）

- 选法：最大-最小多样性（Max-Min Diversity），余弦距离 d = 1 − cos。第一个 token 取“最近邻最远”的那个，之后每次加入“到已选集合的最小距离最大”的候选，
  距离矩阵只算一次。论文说 LLaVA-1.5 的视觉 token 是 4096 维，推断用的是投影层输出（没有明说）。
- 默认在进入 LLM 之前剪（Layer 0）。Table 3：同样的 TFLOPs（19.61%～19.80%）下，在第 0、1、2、3 层之后选，平均分 62.34、60.44、56.99、38.60
  （MMB、MMMU、POPE、SQA 四列的平均）。在 LLM 之内选时用解码层的特征（没有写清）。
  - **与 IDEA-0007 的关系**：Layer 1 一行相当于“第 0 层全看、之后少留”（K = 1，算力相同），比在 LLM 之前剪差约 1.9。这是不利于“一层全看有帮助”的旁证，
    但它同时换了选择所用的特征（解码层特征），放置位置与特征两件事没有分开。
- 它自己的表（约 13%～16% TFLOPs，约 56 个）：VQAv2 71.55（EM，不剪枝 76.65）、GQA 56.85（不剪枝 61.96）；FastV、VTW 在同样的算力下很低。

## 浅层剪枝与深层撤除

- ShaRP（arXiv 2512.05385 v2）：在第一个解码层剪（“we apply pruning at the first decoder layer”；FastV 在第 2 层、PDrop 在第 4 层起剪），
  按最后一个文本 token 的注意力排序；用全黑视频估计位置偏差并减去（λ = 0.6）；段内聚合；对高注意力 token 去冗余。只测了视频模型，按算力对齐的保留比例比较，
  报告保留约 97.2% 的性能。**与 IDEA-0007 的关系**：同样是“第 0 层全看、第 1 层起少留”，排序用去偏的 LLM 注意力加去冗余，不是编码器的 CLS 排序；
  IDEA-0007 的 K = 1 放置本身不新。
- FEATHER（arXiv 2412.13180）：早层注意力有位置偏差，去掉 RoPE 的影响并加均匀采样的 token 之后，早层之后的注意力排序可用。
- VTW（arXiv 2405.05803，AAAI 2025）：某一层之后撤除全部视觉 token（按 KL 选层），深层不需要视觉 token。
- PyramidDrop（arXiv 2410.17247）：分阶段按比例丢弃；浅层对丢弃敏感，第 16 层只留 10% 没有明显下降。
- HiDrop（arXiv 2602.23699）：视觉 token 晚注入、凹形金字塔剪枝、提前撤除。

## 对下一步的启示（推断，待用户决定）

1. 在我们的流程里先实现并跑一个 DivPrune-64（按论文描述自己实现，不下载代码），确定同一套数据上强方法的位置；
2. 干净地检验“一层全看”对多样性选择是否有用：同样用投影层输出算多样性，在 LLM 之前留 64 个，对比第 0 层全看、第 1 层起留 47 个（层平均 63.5）；
3. 若要“提升大”，底座应换成覆盖 / 多样性一类，再看我们的几个手段（K = 1 的放置、按题型路由、定位后覆盖）能否在它之上再加。
