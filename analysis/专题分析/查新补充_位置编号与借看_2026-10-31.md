## 2. 剪枝下的定位评测（RefCOCO 一类）

- 已有（子代理）：GAP、Layer-Aware（见上）；FEATHER（RefCOCO / + / g 与 OCID-Ref 的均值：不剪枝 53.2、FastV 5.9、FEATHER 39.3）；“Token Pruning in Multimodal Large Language Models: Are We Solving the Right Problem?”（ACL Findings 2025，arXiv 2502.11501）；D2Pruner（arXiv 2512.19443，称现有方法的定位“catastrophically fail”）；VScan（Qwen2.5-VL-7B 的 RefCOCO 全表，本地代码 qwen/eval/test_refcoco.py 只评 Qwen）；VisionTrim 的 Table 6 有一列 RefCOCO（Qwen2.5-VL，第二人复核读到）。

## 3. 被剪的 token 只在第一层作 key / value（借看）

- **没有找到直接先例**（查询：visual tokens keys values only first layer、pruned tokens attend only shallow layer KV、FastV K=1 equal FLOPs pre-LLM 等，含 extended）。最近的（子代理）：ShortV（ICCV 2025，arXiv 2504.00502）在“无效层”冻结视觉 token，只出 K / V、跳过 Q / O / FFN，但不剪 token；LLaVA-Mini（ICLR 2025，arXiv 2501.03895，需要训练）让文本先与 576 个视觉 token 过几层“预融合”再压成 1 个；S²Prune 让 576 个过第 0 层再剪（即 K = 1），按 token 数比较、没有借看；FastV 的 K 消融没有 K = 1。机制上的旁证：Cross-modal Information Flow（CVPR 2025，arXiv 2411.18620）说低层把整图特征送进题目 token。

## 4. 剪枝下是非题的偏移

- 偏“否”已有报告（子代理）：MI-Pruner（arXiv 2604.03072）的 Table 1：LLaVA-1.5-7B 的 POPE 答“是”比例不剪枝 0.56，留 64 个时 FastV 0.35、VisionZip 0.37、DART 0.33、随机 0.34。偏“是”（原始编号下）没有找到。

## 5. 对本项目的结论

- **定位方向**：剪枝后连续编号伤定位、原始编号补回，GAP（2025-06）已经做过，Layer-Aware（2026-09）在几乎相同的设置下做过并给出逐层切换的方法。DEC-0071 的条件不满足，不做 RefCOCO 诊断（DEC-0072）。
- **仍可能新的**（检索不到不等于没有）：①GQA 按细分题型的拆解（位置类题型的缺口约 19～21、原始编号补回 12～15，在新数据上预注册重现，F89、F93）；②原始编号下是非判断偏“是”（F88、F92）；③第 0 层只算 K / V 的借看与按 FLOPs 的比较、它“经由题目 token”的拆分、它在 POPE 上的“否”偏移（F84～F86、F91、F94、F95）。
- **不能声称**：首次发现或解释“先剪后送的连续编号毁定位、原始编号补回”；首次发现“原始编号以感知 / OCR 换定位”；关系题没有作用只能作补充；“剪枝让 POPE 偏否”是新现象；“K = 1 剪枝”或“视觉 token 只出 K / V 省约 5/6”本身；“没有人在 RefCOCO 上评过剪枝”。
- **混杂提醒**（子代理）：EXP-0034 的 peek − DivPrune-64 同时改了编号方案（原始对连续）与借看；借看本身的作用只能看 peek − nopeek（同样的编号）。要说借看能加在标准的先剪后送方法之上，需要“借看 + 连续编号”的对照。
