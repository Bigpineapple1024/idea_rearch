## 五、已知问题

- FastV 官方 KV-cache 版在 eager 注意力下会报错，必须打 rotary 补丁，而且会重复写入 KV cache；用本项目的 `fastv_llava.py` 可以避免这些问题。
- VisionZip 不要用 `pip install visionzip`：PyPI 包里没有代码。要传入论文的预算 (54,10)/(108,20)/(162,30)，默认值 (191,30) 不是论文设置。
- SparseVLM 只能用 batch size 1；脚本路径写死为作者集群路径，需要先修改。
- iTransformer 的 run.py 种子写死为 2023；测试集 batch size 为 1，`drop_last` 不会丢窗口。
- WPMixer 官方测试 `drop_last=True`，超参数是在测试集上调出来的；对比时用全部窗口计分。
- DUET 测试时通道 mask 随机，但影响很小；种子之间的波动较大，至少跑 3 个种子。
- `wpmixer` 环境装完后没有 `pkg_resources`（2026-10-23 实际遇到），WPMixer 内置的 pytorch_wavelets 依赖它；已装 `setuptools==69.5.1`。
- LLaVA 不固定 peft 版本，最新版 peft 与 LLaVA 固定的 accelerate 0.21.0 不兼容（`import peft` 报错）；`tp`、`sparsevlm` 已装 peft 0.10.0。
- 原生 Windows 上的差异（已在 EXP-0002 中实际运行，详见 code/README）：
  - PyPI 的 Windows 版 torch 只有 CPU 版，必须先从 PyTorch 的 CUDA 源安装；
  - LLaVA 的评测 DataLoader worker 在 Windows 上取不到模块级 `args`。`run_eval.py` 用自己的 DataLoader，在每个 worker 启动时把 `args` 传进去，默认 4 个 worker，答案与 0 个 worker 逐条相同（EXP-0002-R05、R34）。SparseVLM 也通过 `run_eval.py --method sparsevlm` 运行，不用它的官方脚本；
  - TQNet 的 run.py 没有 `__main__` 保护，时序命令一律加 `--num_workers 0`；
  - flash-attn 不装。SparseVLM 的每层注意力都调用 FlashAttention-2，在 Windows 上由 `code/token_pruning/sparsevlm_sdpa.py` 在运行时换成 SDPA（详见 code/README）。DUET 的 ray 2.10.0 已能安装和导入。
