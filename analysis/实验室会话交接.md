## 一、怎么开会话

1. **只用 `D:\6CJNM007`**：这是用户在实验室电脑上的专用文件夹（DEC-0013）。仓库、外部仓库、环境、缓存、权重、数据、运行产物和备份都放在这里，不写到 C 盘或其他目录。
2. **环境：方案 B，原生 Windows**（用户选定，DEC-0014；细节见 [code/README](../code/README.md)）：
   - 仓库克隆到 `D:\6CJNM007\idea_rearch`，克隆时加 `-c core.autocrlf=false`（外部仓库也一样），否则 .sh 脚本在 Git Bash 里无法运行；
   - conda 用 Miniforge，静默安装到 `D:\6CJNM007\miniforge3`，不运行 `conda init`；
   - Claude Code 在 Windows 上通过 Git Bash 执行命令，每条命令先 `source /d/6CJNM007/idea_rearch/code/env/windows_env.sh <环境名>`，它把缓存和临时文件指向 `D:\6CJNM007` 并激活 conda 环境；
   - 传给 Python 的路径写成 `D:/6CJNM007/...`。
3. **登录 GitHub**：`gh auth login`，或配置 SSH key。之后 Claude Code 每次提交都会立即推送；这里用的是本机的 git 账号，与云端会话的权限无关。
4. **启动**：在仓库目录运行 `claude`（或用 Claude Desktop 打开该文件夹）。想在手机或网页的 Claude Code 应用里查看，运行 `claude remote-control`。
5. **分支**：`main` 放文档和论文；实验在 `code/token-pruning`、`code/ts-forecasting` 上进行（见[研究流程](研究流程.md)“分支与提交”）。

## 五、已知问题

- FastV 官方 KV-cache 版在 eager 注意力下会报错，必须打 rotary 补丁，而且会重复写入 KV cache；用本项目的 `fastv_llava.py` 可以避免这些问题。
- VisionZip 不要用 `pip install visionzip`：PyPI 包里没有代码。要传入论文的预算 (54,10)/(108,20)/(162,30)，默认值 (191,30) 不是论文设置。
- SparseVLM 只能用 batch size 1；脚本路径写死为作者集群路径，需要先修改。
- iTransformer 的 run.py 种子写死为 2023；测试集 batch size 为 1，`drop_last` 不会丢窗口。
- WPMixer 官方测试 `drop_last=True`，超参数是在测试集上调出来的；对比时用全部窗口计分。
- DUET 测试时通道 mask 随机，但影响很小；种子之间的波动较大，至少跑 3 个种子。
- 在依赖较多的环境里装包时，setuptools 可能被升级而缺少 `pkg_resources`，WPMixer 内置的 pytorch_wavelets 依赖它；出现这个报错时执行 `pip install "setuptools<70"`。
- 原生 Windows 上的差异（来自代码核查，尚未在 Windows 上运行，详见 code/README）：
  - PyPI 的 Windows 版 torch 只有 CPU 版，必须先从 PyTorch 的 CUDA 源安装；
  - LLaVA 的评测 DataLoader worker 在 Windows 上取不到模块级 `args`，`run_eval.py` 已在 Windows 上把 worker 设为 0；SparseVLM 的官方脚本需要包装后运行；
  - TQNet 的 run.py 没有 `__main__` 保护，时序命令一律加 `--num_workers 0`；
  - flash-attn 不装；DUET 的 ray 需确认能安装。
