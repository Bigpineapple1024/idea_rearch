## A：当前领域

- **具体问题**：EXP-0011 的变体按“图像 token 的输入 embedding 与物体名 embedding 的余弦”选择，POPE F1 从 64.66 升到 83.63（F29）。但物体名要靠 POPE 的固定句式找出（`prompt_spans.question_spans`），一般题目没有这个结构（P8）。
- **算子**：查询向量 q。直接用题目全部 token 的均值时，模板词（Is、there、in、the、image、Answer the question using a single word or phrase、ASSISTANT:）占了绝大多数 token，q 偏向模板词；D2b 中题目句均值的命中只有 40.0%。
- **代价**：方法只能用在点名物体的题目上，第 ⑫ 步的普遍性检查（至少两个 benchmark）做不了。

## B：方法来源（信息检索的词权重理论）

- **原文位置**：Lee，IDF Revisited（SIGIR 2007，arXiv 0705.1161，ar5iv 全文已读），复述并推导了 Robertson–Spärck Jones（RSJ）权重与 Croft–Harper 的推导；Robertson 的说明页（staff.city.ac.uk/~sbrp622/idf.html）。Spärck Jones 1972 与 Robertson 2004 的原文 PDF 未读（需下载许可）。
- **原始问题**：检索时，查询里在很多文档中都出现的词区分不了相关与不相关的文档，不应和少见的词同样计权。
- **有效机制**：RSJ 权重 log[p(1−q)/(q(1−p))]（p、q 是词在相关、不相关文档中出现的概率）。没有相关性信息时，Croft–Harper 用两条假设把它化成 IDF：
  - CH-1：语料中大多数文档与查询无关，所以 q ≈ df/N；
  - CH-2：所有查询词在相关文档中出现的概率相同。
  - 结果是 log((N − df)/df) 加常数；Lee 的推导给出 log(1 + N/df)。
- **真正起作用的部分**：权重只由“这个词在多少文档里出现”决定；出现在所有文档里的词权重为 0。
- **必要条件**：①有一个与当前查询大多无关的文档集合，用来估计 df；②查询是词的集合（词之间独立）；③加权后的组合方式要能体现每个词的贡献（检索里是加权求和）。

## C：迁移案例

| 案例 | 怎么用 B | 输入输出 / 结构的改动 | 生效证据与限制 | 核对状态 |
| --- | --- | --- | --- | --- |
| BERTScore（Zhang 等，ICLR 2020，arXiv 1904.09675） | 两段文本的 token embedding 做余弦匹配，每个 token 的匹配分按 IDF 加权 | IDF 在测试语料（参考句）上算，不用标签；加一平滑 | 图像描述评价上明显有效（0.917 对 0.888），机器翻译上时好时坏；作者认为效果取决于文本领域 | ar5iv 全文已读第 3、5 节 |
| SIF（Arora 等，ICLR 2017） | 句向量 = 词向量的加权平均，权重 a/(a + p(w))，再减去共同成分 | 把“按频率降权”用在 embedding 平均上 | 文本相似度任务（原文未读） | 只读了代码仓库说明；原文需下载许可 |
| CLIP Surgery（Li 等，arXiv 2304.05653） | 图文相似度图减去各类别共有的成分 | 视觉-语言 embedding 上的“共同成分去除” | 可解释性与多标签识别上有效；只有一个文本时用空字符串代替 | ar5iv 全文已读第 3.3 节 |

- **B 与 C 的对比**：BERTScore 直接用 IDF、只改了“文档”的定义（测试语料中的句子）；SIF 把 IDF 换成平滑的频率倒数，并加了共同成分去除。两者都把 IDF 从“文档打分”搬到了“embedding 的加权组合”，这是本方案要做的同一件事。
- **哪些是生效的必要条件**：embedding 与匹配对象要在可比的空间里（BERTScore 用同一个 BERT；本项目的 F29、M11：LLaVA 的投影让图像 token 与词 embedding 可比）。

## 实现公式（2026-10-29 补：用户读仓库时没有找到 IDF 与可视性的精确公式）

下面写的是代码实际做的（code/token-pruning 7ba3657 的行号）。此前只在 [EXP-0014 记录](实验报告/EXP-0014_record.md)（IDF 一句）与 [EXP-0015 记录](实验报告/EXP-0015_record.md)（可视性三行）里有简写。

### IDF（`code/token_pruning/run_eval.py` 第 370～394 行：`prompt_ids_after_image`、`question_idf`）

- **文档集合**：被评测的那个题目文件本身（POPE、MME、VQAv2 test2、GQA testdev 等各自单独算），每道题是一篇文档，N = 题数。
- **每道题的词**：按 LLaVA 评测时完全相同的方式拼出 prompt（vicuna_v1 模板，`<image>` + 换行 + 题目文字），只取图像 token 之后的全部 token id：题目、说明句（例如 “Answer the question using a single word or phrase.”）和模板后面的部分都在内。
- **df(t)**：含有 token t 的题数（一道题里按集合计，出现几次都算一次）。
- **idf(t) = ln((N + 1) / (df(t) + 1))**：自然对数，BERTScore 式的加一平滑；题目文件里没出现过的 token 记为 ln(N + 1)。
- 每道题都有的 token（模板、换行、说明句）df = N，权重正好为 0（coco_dev3 上 22 个、POPE 上 21 个，check_query_idf.py）。
- 只用题目文字，不用答案、标签或图像；每次运行把 df 表写进 `<答案文件>.idf.json`（`run_eval.py` 第 679～683 行）。

### 题目查询与打分（`code/token_pruning/fastv_llava.py` 第 246～263 行）

- h_j 为题目第 j 个 token（图像之后的 token）在 LLM 输入层的 embedding，e_i 为第 i 个图像 token 进入 LLM 时的 embedding（投影层输出）。
- 查询 q = Σ_j w_j h_j / Σ_j w_j；图像 token 的分数 = cos(e_i, q)。
  - query_mean（A′）：w_j = 1；
  - query_idf（A′+B）：w_j = idf(t_j)；
  - attn_idf（A+B）：不用 embedding，改为打分层（K = 2 时为第 1 层）注意力中题目各 token 对图像 token 的行（各 head 平均），按 w_j = idf(t_j) 加权平均（第 286～291 行）。

### IDF × 可视性（query_vis，EXP-0015 起；`fastv_llava.py` 第 250～256、305～316 行）

- w_j = idf(t_j) × vis(t_j)；可见占比 **S = Σ_j idf(t_j)·vis(t_j) / Σ_j idf(t_j)**（Σ idf = 0 时 S = 0）。
- 在剪枝层要留 count 个（64 档、K = 2 时为 30，排除填充区之后）：**n_q = round(count × S)** 个按 cos(e_i, q) 分块轮流取；其余 count − n_q 个按强对照的分数（打分层注意力除以位置先验）分块轮流取，先填还空着的块。
- S = 0 时等于强对照 A；可视性全为 1 时，查询与 query_idf 相同（check_query_vis.py 自检）。按题目句式路由（IDEA-0003）时，被路由的题用这一查询，其余题直接用强对照。

### 可视性的估计（`code/token_pruning/make_visibility.py`；记录用 `run_eval.py` 第 462～485 行的 `--vocab-visibility-log`）

- **数据**：只用开发集 coco_dev 的 300 张 COCO 图（EXP-0015-R01 的记录运行），不碰 POPE、MME 的图。
- **每张图**：576 个图像 token 的输入 embedding e_i 与词表中 32000 个 embedding v_w（LLM 的 embed_tokens）都做 L2 归一化，c_{i,w} = cos(e_i, v_w)；对每个词记下 576 个值的最大值与平均值。
- **peak(图, w) = max_i c_{i,w} − mean_i c_{i,w}**：这个词在这张图上能不能挑出一块区域。
- **raw(w)** = peak 在 300 张图上的 95% 分位数（numpy 默认的线性插值）：至少在少数图上定位得很清楚。
- **vis(w)** = raw(w) 在全部 32000 个词中的百分位秩 = 从 0 起的名次（稳定排序）/ 31999，落在 [0, 1]。
- 输出 `code/output/EXP-0015/visibility/visibility.npy`（SHA256SUMS 的 sha256 b1af357f…），运行时用 `--fastv-visibility` 读入。估计有噪声：“▁the” 0.989、人名 “▁Graham” 0.989、“▁dog” 0.732、“▁left” 0.064（EXP-0015 记录）；在切分之外没有可检出的贡献（EXP-0016）。

## 预测、成功与停止

- **POPE**：A′+B 接近物体名查询（差不超过 2 个点，“an”/“imange” 题会稍差），明显高于 A′ 与 A；A+B 与 A 相差不超过 1 个点（F28：第 1 层注意力不看题目）。
- **MME**：方向不确定。被问物体明确的子任务（existence、count、position、color）预计好于 A；名字类（celebrity、artwork、landmark、posters）与文字类（OCR、text translation）可能更差。
- **成功**：POPE 上 A′+B − A′、A′+B − A 的配对区间都在 0 以上（原始标注与 RePOPE）；MME-P 上 A′+B − A 的区间不在 0 以下。两者都满足，才算“在两个 benchmark 上整体指标稳定提升（POPE）且不变差（MME）”。
- **停止 / 回退**：POPE 上 A′+B 不高于 A′ → B 在本系统中无效，回到第 ⑨ 步换方法（例如 SIF 的共同成分去除）。MME-P 明显低于 A → 方法限定在“点名物体的题目”，第 ⑫ 步改为检查按题目类型切换。
- **独立复验**：换预算（128）与第二个一般题目的 benchmark（需要下载，待用户许可）。
