## 研究问题

注意力打分不稳定、容易留下内容重复的 token；按多样性选又对所有 token 一视同仁，可能丢掉回答需要的区域。能否只用前向计算（不求导、不要标准答案），便宜地估计每个视觉 token 的“灵敏度”（输入有小扰动时输出变多少），并把它和多样性结合起来选 token？（p.1 摘要；p.1–2 §1）

## 方法与贡献

- **在哪里剪**：视觉编码器输出 N_v 个 token（记 X），经多模态投影层 M 得到 Z = M(X)。灵敏度在投影层上估计；选出 k 个之后，和文字输入一起送入 LLM（p.4 §3.3、Fig. 3 图注；p.13 C.2）。也就是在 LLM 之前剪一次。[AI] LLM 的每一层都只看到这 k 个。
- **灵敏度怎么算**（p.4 §3.3；p.5 Algorithm 1 第 4–8 行）：
  1. 采 m 个高斯随机方向 u_j，每个归一化为长度 1；
  2. 把每个 token 的特征 x_i 分别加、减 h·u_j，各过一次投影层，得到差 Δ_ij = M(x_i + h·u_j) − M(x_i − h·u_j)；
  3. 灵敏度 S(i) = m 个方向上 ‖Δ_ij‖/(2h) 的平均。比例常数不影响排序（AI）。
  - Algorithm 1 第 4–5 行是先采 m 个方向，再把整组 X 沿这些方向展开；按这个写法，所有 token 共用同一组方向（AI）。随机种子没有写（UN）。
  - 默认 m = 64、h = 0.01，所有实验都用这一组（p.5 §4；p.6；p.13 C.2）。
  - 作者解释为什么不在编码器上做：500 个 token、每个 64 个方向，要 2nm 次完整前向，约 6.4×10⁶ GFLOPs（p.3 §3.2）；投影层“只有几层”，开销可以忽略（p.4）。[AI] 更根本的原因是投影层逐个 token 计算，一个方向一次批量前向就能同时扰动所有 token。
- **命题 3.1**（p.4；证明在附录 B，p.12）：h 足够小时，S(x) 等于 E_u‖J(x)u‖ 加一个 O(h²) 的误差，J 是投影层在 x 处的雅可比矩阵。作者说它衡量“局部响应的大小”，不是梯度的方向（p.4）。
  - [AI] 投影层是逐个 token 作用的（M: R^dv → R^dl，p.4），所以 S(i) 只取决于这个 token 自己的特征：与题目无关，与图里其他 token 也无关。它量的是投影层输出变了多少，不是 LLM 的输出或答案变了多少。名字叫“零阶梯度估计”，实际用到的只是方向导数的长度。
- **选 token**（p.5 Algorithm 1 第 10–17 行与正文）：
  1. 把 S 在每张图内按最小值、最大值归一化到 [0, 1]，记 Ŝ；
  2. 贪心：多样性 Div(i, P) = 1 − max_{j∈P} cos(Z_i, Z_j)（P 是已选集合，为空时记 1）；得分 = Ŝ(i) × Div(i, P)；每次取得分最大的，直到选满 k 个。
  - 余弦算在投影层输出 Z 上（Algorithm 1 第 13 行）。
  - 与 DivPrune 的两处不同（p.5）：第一个 token，DivPrune 取“与其余所有 token 最远”的，本文取灵敏度最高的（集合为空时多样性都是 1，只看 Ŝ）；之后 DivPrune 只看多样性，本文看乘积。用乘法是为了不再加一个权重超参数（p.5）。
  - [AI] 归一化后灵敏度最低的 token 得分恒为 0；乘法让低灵敏度的 token 很难被选上。本文对 DivPrune 第一步的说法（“与其余所有 token 最远”）与本项目按 DivPrune 原文写的“最近邻最远”（EXP-0032 计划）字面上不完全一样，可能是同一件事的两种说法。
- **免训练**：作者称免训练、免校准、不用注意力，也不需要指定 LLM 或编码器的哪一层（p.5 §4；p.8 §5；p.13 C.1–C.2）。
- **是否用题目文字**：不用。Algorithm 1 的输入只有视觉 token X、投影层 M、k、h、m（p.5），全文没有按题目调整选择的步骤。[AI] 随机方向固定时，同一张图对任何题目都选出同一组 token。文中说的“与任务相关的线索”（p.1）指对输出影响大，不是与这道题相关。
- **LLaVA-NeXT 上的额外处理**：对 MM 投影层做低秩分解（k = 128），“进一步提高效率”（p.5 §4；p.13 C.2）。这个低秩投影层只用来算灵敏度，还是也用来产生送入 LLM 的特征，没写（UN）；若是后者，就改动了模型（AI）。
- **作者列出的三点贡献**（p.2）：
  1. 把灵敏度与多样性统一起来的免训练剪枝框架；
  2. 在投影层上做零阶灵敏度估计，只用轻量的前向计算，不需要反向传播，也不需要对整个编码器做扰动；
  3. 多个模型、多个基准上精度—效率更好，“剪掉最多 94.4% 的 token 仍保持精度”，端到端最多快 2.30×。

## 预算与计数口径

1. **“保留 N 个”是什么**：LLaVA-1.5 上 N = 192 / 128 / 64，即剪掉 66.7% / 77.8% / 88.9%（p.13 C.2；Table 1 表头）。N 是在投影层之后选出、送入 LLM 的视觉 token 数（p.4 Fig. 3 图注；p.5 Algorithm 1 的 k）。[AI] LLM 的 32 层都只有这 N 个，所以按本项目的层平均口径，ZOO-Prune-64 就是每层 64 个，和本项目的 DivPrune-64、VisionZip-64 直接可比。
2. **CLS**：全文没有提（全文未见）。LLaVA-1.5 的 576 个是 336×336 图像的 patch token（p.13 C.1），[AI] 候选应是这 576 个 patch，不含 CLS。而表中的 VisionZip-64 用的是 VisionZip 自己的设置：本项目的源码核验写明，它的 64 = 54 个主导 token（含 CLS）+ 10 个合并出来的上下文 token（[VisionZip 源码核验](PAPER-0006_VisionZip_源码核验.md) E-VZ-C08、E-VZ-C12；VisionZip 补充材料 Table 6）。本文没有讨论这一差别（UN）。
3. **合并 token**：ZOO-Prune 只选下标、不合并（Algorithm 1）。DivPrune 也不合并（按本项目对 DivPrune 的读法，EXP-0032 计划）。
4. **选中之后的顺序与位置编号**：Algorithm 1 按选中的先后返回下标；送入 LLM 时是否恢复原来的空间顺序、位置编号怎么给，全文未见（UN）。本项目的 DivPrune-64 按原顺序送入、位置编号连续（EXP-0032 计划）。
5. **与 FastV 一族怎么对齐**：全文没有定义在 LLM 内剪的方法“保留 N 个”怎么计（UN）。
   - 表中不剪枝一行和 FastV、SparseVLM、VisionZip 三行，Table B 的 9 列都与 VisionZip 原文 Table 1 的数字逐个相同（PAPER-0006 解析 p.5）。VisionZip 原文对 FastV、SparseVLM 只说沿用原设置，没有给 FastV 的 K、R，也没说按哪种方式计数（[VisionZip 源码核验](PAPER-0006_VisionZip_源码核验.md) E-VZ-C02；MODE_C-0002 的 E-RC-4）。
   - [AI] 所以本文的 FastV-64 没有确定的预算口径，不能和本项目层平均 64 的 FastV 一族比较。本项目的 FastV-64（K = 2，第 2 层起留 30 个，层平均 64.125）实测 POPE F1 36.19（EXP-0002-R11）、MME P+C 1288.15（EXP-0002-R10），与表中的 48.00、1256.00 都不同。
   - 正文“FastV 多留三倍的 token，也只有 87.75%”（p.5）是拿 ZOO-Prune-64 和 FastV-192 比（Table 1）；“三倍”取决于上面没有定义的计数。
   - 作者自己的 T2V 变体（Fig. 5、6）用第 3 层之后的注意力（p.7）；前 3 层留多少、按什么口径对齐，没写（UN）。
6. **LLaVA-NeXT 与 Qwen2.5-VL**：LLaVA-NeXT 的上限为 640 / 320 / 160 个（剪掉 77.8% / 88.9% / 94.4%）；照 VisionZip 的实现，图像最多切成 5 个子图，每个子图留 128 / 64 / 32 个；子图少时按比例减少，如 4 个子图时 160 档留 128 个（p.13 C.2）。Qwen2.5-VL 按保留 20%、10% 计（p.13）。Qwen2.5-VL 上“投影层”指哪一部分、灵敏度在哪里算，没写（UN）。
7. **FLOPs 与时延的口径**（p.14–15 D.2；p.8）：
   - 预填充 FLOPs 按 L(4n̂d² + 2n̂²d + 2n̂dm) 计（L 层，隐藏维 d，FFN 中间维 m，n̂ 为剪后的序列长度），沿用 DivPrune、FastV、VisionZip（p.14）。总代价的式子在解析中缺失。
   - ZOO 的额外 FLOPs，式 (18)：2·m_z·n·(d/k)·(D_v + d) − n·D_v·d，m_z = 64、k = 128 时等于 n·d²，约为不剪枝预填充的 0.3%（p.15）。[AI] 代入 D_v = 1024、d = 4096，这个等式正好成立；式中把投影层当作一个 D_v×d 的线性层，(d/k) 像是秩为 32 的分解。这是 LLaVA-NeXT（做了低秩分解）上的数字。
   - 时延：LLaVA-NeXT-7B、POPE、单张 L40S 上测预填充时间和端到端时延（p.8 Fig. 7；p.15 Fig. A），绝对数值只在图里（UN）。
   - LLaVA-1.5 上没有任何开销或时延数字（全文未见）；粗估见 E-ZO-19。

## 限制与替代解释

- **增益小、没有不确定性**：LLaVA-1.5-7B 64 档对 DivPrune 平均只多 0.78，单项在 −0.12～+0.94 之间（MME +1.19 分）（Table 1、B）；没有种子、重复与区间（E-ZO-26）。灵敏度用随机方向，作者自己也提到方差（p.6）。[AI] 参照本项目同一划分上的区间宽度（见「结果及不确定性」），GQA +0.69 这样的差距可能在噪声内。LLaVA-NeXT 上差距大一些（160 档平均 +3.0），但那里用了低秩投影层，消融也只在那里做。
- **对照大多是引用、版本不一**（E-ZO-9、E-ZO-10）：
  - 不剪枝、FastV、SparseVLM、VisionZip 抄自 VisionZip 原文。
  - SparseVLM 用的是旧版的数字：SparseVLM v4 自己报告 64 档 GQA 53.8、POPE 77.5、MME 1589（PAPER-0005 解析 p.6），本项目测得 GQA testdev 53.78（EXP-0022-R08）；本文表中是 52.70、75.10、1505.00。
  - DivPrune 与 MMTok 的表只差 SQA；PyramidDrop-64 一行的 VQAv2 69.20 与 GQA 41.90 并列，来源不明。
  - [AI] 本项目在 POPE、MME、GQA testdev 上测得的 vanilla 与 VisionZip-64（POPE F1 85.90、77.03；MME P+C 1865.49、1696.01；GQA 61.96、55.18；EXP-0002-R04、R17、R02、R35，EXP-0022-R06、R07）和表中数字（85.90、77.00；1862.00、1690.00；61.90、55.10）很接近，所以这几项上引用的数字可信；SparseVLM 的对照偏弱。
- **“灵敏度”与“对输出的影响”之间只有间接证据**（E-ZO-5、E-ZO-6）：命题 3.1 说的是投影层的局部放大倍数。它与“对模型输出的影响”（p.1 的动机）之间，只有两条间接证据：Fig. 2 中与“编码器输出处的灵敏度”的 Spearman 0.55 / 0.49，以及下游精度。没有和 LLM 输出（例如答案的对数概率）的变化直接比。

## 优点、缺点与核心总结

- **优点**：方法简单，只需投影层、不需要 LLM 前向或注意力图，能放进任何“在 LLM 之前选”的流程；与 DivPrune 只差一个乘上去的先验，消融（Table 4）把两项的作用分得比较清楚；覆盖 4 个模型、最多 9 个基准；FLOPs 与时延有报告（LLaVA-NeXT）。
- **缺点**：灵敏度与题目无关，只是 token 自身特征的函数，它为什么有用只有定性图；LLaVA-1.5 上对 DivPrune 的增益不到 1 分且没有区间；对照数字多为引用、口径未定义；LLaVA-1.5 的开销没报告；正文与表有几处不一致。
- **核心总结**：ZOO-Prune 是“DivPrune + 一个与题目无关、在投影层上算出的重要性先验”。它在本项目的层平均口径下与 DivPrune-64、VisionZip-64 直接可比，报告的 64 档平均比 DivPrune 高 0.78（LLaVA-1.5-7B）。它不碰本项目的路由、K = 1 与覆盖，但正好占了“在 DivPrune 底座上加与题目无关的重要性”这一步。

### 重叠（AI）

1. **DivPrune 底座本身**：ZOO-Prune 的多样性项就是本项目 DivPrune-64 的做法——在 LLM 之前、用投影层输出的余弦距离做最大最小贪心（p.5 Algorithm 1 第 13 行；EXP-0032 计划）。ZOO-Prune = 这个底座 + 一个与题目无关的重要性先验（相乘）+ 第一个取最重要的。理由：候选、特征、距离和贪心方式都相同，只差打分里的 Ŝ。
2. **“重要性 × 多样性”的思路**：[EXP-0033](../实验报告/EXP-0033_record.md) 的 X2（VisionZip 的 CLS 注意力取前 128 个作候选，再按多样性选 64 个）与 ZOO-Prune 是同一思路的不同结合方式（先筛后选，对相乘）。本文 Fig. 6 说注意力 + 多样性不如灵敏度 + 多样性（POPE；数字读不到，E-ZO-17）。
3. **对 T2V 注意力位置偏差的观察一致**（E-ZO-25）：可作为本项目“FastV 一族底座的弱点部分来自位置偏差”的旁证，但本文只有定性图。
4. **相对 VisionZip 的增益集中在是非题一类**：本文 64 档 DivPrune、ZOO-Prune 相对 VisionZip 的最大增益都在 POPE（+8.56、+8.86，全是“有没有”的是非题），其次是 GQA、VQAv2（Table 1）；本项目 DivPrune-64 的增益主要在 yes/no、计数题（F72～F74）。理由：方向相符；但本文没有按题型分解，这只是基准层面的对应。

### 可辩护的差别（AI，附理由）

1. **何时用题目文字**：ZOO-Prune 对所有题用同一个与题目无关的规则（E-ZO-4、E-ZO-7）；本项目的路由决定哪类题用题目文字，并有“同一种按题目选择，在不同答案类型上效果相反”的证据（F38、F39）。本文没有题型分析（E-ZO-22）。
2. **剪枝位置与层平均预算**：本文只在 LLM 之前剪；本项目研究了 LLM 内 K = 1 / K = 2 的放置在同一层平均预算下的差别。限制：本项目自己的结果是“多样性选择放到 K = 1 没有平均的帮助”（F72～F74），这与本文只在 LLM 之前剪并不矛盾，不能当作相对本文的优势。
3. **按题目定位后的覆盖**：本文没有。
4. **报告方式**：本项目有按图像重抽的区间和预注册，本文没有区间。这是方法学上的区别，不是方法贡献。
5. **开销**：本项目路由每题 +0.7%；本文在 LLaVA-1.5 上的开销没报告，粗估不小（E-ZO-19）。要实测后才能写。
6. **本项目的弱点**：本文有 4 个模型、最多 9 个基准；在 GQA testdev 上，本文报告的 DivPrune-64、ZOO-Prune-64 都高于本项目目前 64 档最好的配置（E-ZO-24，跨管线）。

### 新颖性威胁：它是否已经做了我们想做的事（AI）

- **路由、K = 1、覆盖 16**：没有。本文不看题目、不在 LLM 内剪、不做定位覆盖，这三项不受它威胁。
- **在 DivPrune 底座上加与题目无关的重要性**（乘到多样性上，或先放进最重要的几个）：已经做了。本文报告 LLaVA-1.5-7B 64 档平均比 DivPrune 高 0.78（Table 1）、LLaVA-NeXT-7B 160 档高 3.0（Table 3）。下一轮若以 DivPrune-64 为底座（DEC-0061），这一类改动不能单独作为方法贡献；EXP-0033 的 X2 只适合作现象检验。
