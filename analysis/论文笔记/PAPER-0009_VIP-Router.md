## 研究问题

平均准确率最高的剪枝方法，是不是对每个样本都最好？如果不是，能不能在推理之前用低成本特征，为每个样本从现有剪枝方法（以及“不剪”）中选一个？（p.1 摘要；p.2 §1）

## 方法与贡献

- **候选集合**：S = {Full, FastV, VisionZip, PruMerge+, DART}，Full 保留全部视觉 token（p.4 §3.2）。四种剪枝直接用 VTC-Bench 发布的实现和超参数，不做修改（p.6 §4.1）。
- **目标**：逐样本效用 = 是否答对（0/1）− 代价。Full 的代价记 1，剪枝方法的代价记保留比例 r（p.4 式 1）。在 Group A 上 Full 一定答对，所以 Full 的效用恒为 0；答对的剪枝方法得 1 − r，答错得 −r（p.16 A.1）。
- **路由器**：冻结的 CLIP ViT-B/32 图像编码器和 CLIP 文本编码器。图像取倒数第二层的 49 个 patch（去掉 CLS），取均值作全局图像特征；题目最长 77 个 token，用 EOS 作全局文本特征（p.4 §3.3；p.21 A.3.2）。两路各投到 256 维，过一层 4 头的“文本查询图像”交叉注意力，取 EOS 位置的输出（p.4 式 4；p.5；p.21）。拼成 [全局文本; 全局图像; r; ln r; 交叉注意力输出]，共 1538 维，再过两层 MLP（1538→512→5），输出五个候选的效用（p.5 式 5；p.21）。可训练参数 1,382,405 个（p.21），约为 Qwen2-VL 参数量的 0.017%（p.9）。
- **训练**：用离线得到的“每个候选是否答对”的标签，换算成效用目标，按候选分别标准化，用 Huber 损失回归（p.5 式 6；p.22）。只训练投影层、交叉注意力、LayerNorm 和 MLP；预览编码器和 MLLM 都冻结（p.5–6；p.22）。
- **推理**：预测五个效用，取最大者，用选中的方法跑一次 MLLM（p.5–6；p.20 算法 2）。
- **理论**（附录 A.1，p.16–17）：把选择问题化成估计各剪枝方法答对的条件概率；当所有剪枝方法的预测答对概率都低于 r 时选 Full（p.16 式 9）。作者明确说，这个分析不证明预览特征本身足够，够不够要靠实验（p.17）。
- **作者列出的三点贡献**：揭示逐样本的互补性；提出路由器；跨剪枝比例、跨模型、跨 benchmark 的实验（p.3）。

## 研究设计

- **主模型**：Qwen2-VL-7B（p.6 §4.1）。附录写明，数据来自 VTC-Bench 为 Qwen2-VL-7B-Instruct 发布的逐样本推理结果（p.20 A.3.1）。也就是说，主实验的标签不是作者自己跑出来的。
- **Group A**：每个剪枝比例单独构建，只保留“全 token 答对、同比例降采样图像答错”的题目（p.1 §1；p.6；p.20）。来源是八个 benchmark：GQA、MMBench、MMBench-CN、MME、POPE、MMStar、OCRBench、ChartQA（p.6）。
- **规模**：12,919 个图像—题目记录，共 33,091 个“记录—比例”样本（p.20）。按 benchmark:doc_id 的哈希做 70/15/15 划分，训练/验证/测试为 8,988/1,956/1,975 个记录（p.20–21），对应 23,099/4,952/5,040 个样本（p.21 Table 6）。同一记录不跨集合，但同一张图像可能跨集合（p.21）。
- **剪枝比例**：保留比例 r ∈ {0.25, 0.1111, 0.0625, 0.04, 0.01}，即削减 75%～99%（p.20）。所有比例共用一个路由器，r 作为输入（p.5 §3.4）。
- **对照**：四种固定方法；Best Fixed（在训练集上按所有比例合计的效用选一种方法，再固定用于所有测试样本和比例）；逐样本 Oracle（用测试标签逐样本选最好的，作者称为不可达的上界）（p.6）。指标：准确率、实际 token 代价、效用、OHR（路由器收回了 Best Fixed 与 Oracle 之间效用差的多少，p.6 式 7）。
- **训练配置**：AdamW，学习率 1e-3，权重衰减 1e-4，batch 256，最多 50 轮，先预热再余弦衰减，早停耐心 5，按验证集上“各比例宏平均效用”选检查点；FP32；种子 0–4，主表取五个种子的均值（p.6；p.22）。硬件是单张 H200（p.22 A.3.3）。
- **跨模型**：LLaVA-1.5-7B、LLaVA-OneVision-7B、InternVL3-8B、Qwen2.5-VL-7B。作者自己跑了全 token、降采样和各剪枝方法，按同一流程重建 Group A，每个模型单独训练一个路由器（p.9 §4.4）。
- **跨 benchmark**：ScienceQA-IMG、MMMU、RealWorldQA、SEED-Bench Image。目标集按同一流程重建 Group A，直接用 VTC-Bench 训练集上训好的路由器和 Best Fixed，不在目标集上训练（p.10）。
- **消融**：Table 5 分阶段消融，单次运行（p.10）；Table 3 改用 MLLM 自身特征，单次运行（p.8）；Table 7 换预览编码器，单次运行（p.22）。

## 结果及不确定性

- **效用**（Table 1，p.7）：Best Fixed 是 VisionZip。五个比例上效用从 32.54/36.83/31.17/29.05/24.82 提到 38.23/43.24/40.08/36.95/29.89；平均 30.88→37.68，相对 +22.0%（p.2；p.7）。OHR 为 17.58%～31.71%，宏平均 26.5%（p.7）。
- **准确率**（Table 2，p.7）：五个比例上为 66.91/57.65/49.62/44.29/37.48，每个比例都比 Best Fixed 至少高 9.37 点；平均 40.35%→51.19%，相对 +26.9%（p.8）。40 个“benchmark—比例”格子里有 30 个最好（p.8；p.24 Table 8）。
- **Full 的作用**：路由器选 Full 的比例依次为 4.92%、3.72%、3.51%、3.48%、6.66%（p.25 A.5.3）。在最坏假设下，Full 的贡献上界在五个比例上依次为 1.23、0.41、0.22、0.14、0.07 个效用点，五个比例平均最多 0.41 点，占平均增益的 6.1%（p.7；p.18 Remark 1）。
- **计算量**：算上路由开销后，在约 4.5 TFLOPs 以上的大部分区间优于固定方法；99% 档因为更常选 Full，实际代价和 FLOPs 上升，在同计算量比较下竞争力下降（作者用词是 less competitive；p.8–9 §4.3，Fig. 3）。没有看到挂钟延迟。
- **跨模型**（Table 4a，p.9）：LLaVA-1.5-7B 上 Best Fixed 是 PruMerge+，效用 33.91→38.97（OHR 26.15%），准确率 43.38→51.82，代价 0.095→0.128。其他三个模型的 Best Fixed 都是 DART，效用增益是 LLaVA-OneVision-7B +0.82（OHR 2.93%）、InternVL3-8B +0.55（4.17%）、Qwen2.5-VL-7B +4.86（20.52%）。作者概括为 0.55～5.06 点，并说增益大小依赖模型（p.9）。
- **跨 benchmark**（Table 4b，p.9）：效用增益分别为 +5.43（ScienceQA-IMG）、+2.07（MMMU）、+5.14（RealWorldQA）、+0.07（SEED-Bench Image）。
- **消融**（Table 5，p.10）：只用全局文本 35.81；只用全局图像 38.02；两者都用 38.07（这一阶段每个比例单独训练一个路由器）。合成一个共享路由器后降到 36.96；加入空间特征、交叉注意力和 EOS 后回到 38.09。作者据此说，单独的全局文本信号弱于全局图像（p.10）。
- **去掉 CLIP**：完全复用 MLLM 自身特征、不用交叉注意力的变体，不需要额外冻结参数，可训练参数 2.49M，效用 37.62（p.8 Table 3；p.9）。
- **错误诊断**（Table 9，p.26）：与 Oracle 选择不一致的决策中，约 28.9% 的后悔为 0（几种方法同分）；差距大的不一致占不一致的 40.9%，却贡献 63.5% 的后悔（p.25–26）。
- **不确定性**：主表只给五个种子的均值，没有标准差或置信区间；消融全是单次运行（p.7、p.10、p.22 的表注）。[AI] Table 8 每格的题数很少。75% 档各 benchmark 固定方法的准确率都是整数题数的比例，倒推测试题数约为 GQA 151、MMB 37、MMB-CN 30、MME 8、POPE 72、MMStar 34、OCRBench 31、ChartQA 68，合计 431，正好等于 Table 6 中 75% 档的测试数（p.21、p.24）。所以单格相差几个点，可能只差一两道题。

## 限制与替代解释

- **依结果筛样本**：Group A 只留全 token 答对、且“降采样答错”的题，所有数字都在这个子集上。[AI] 相对增益（+22.0%、+26.9%）在全集上会被稀释，不能直接比到常规报告的准确率。作者承认没有在未筛选的 benchmark 上评（p.11）。
- **基线偏弱但影响不大**：Best Fixed 用一种方法覆盖所有比例（p.6）。不过按比例各取最好的固定方法（作者称包络），路由器也每档都超过（p.7）。[AI] 这一点不改变主结论。
- **缺规则路由对照**：没有“按 benchmark 选固定方法”或“按题型选”的规则路由。[AI] Fig. 1(a) 显示 benchmark 层面已有明显互补（p.2），这类不需要学习模型的简单规则可能就拿到一部分增益（按 benchmark 选方法仍要用训练集的正确性标签，不是零标签）；论文无法区分路由器学到的是“样本特性”还是“这题属于哪个 benchmark”。
- **可能的信息泄漏**：划分不跨记录，但同一张图可跨集合（p.21）。只用全局图像就几乎拿到全部增益（38.02 对 38.09，p.10；前者是每个比例各训一个路由器，后者是共享路由器，都是单次运行）。[AI] 这可能部分来自同图不同题的记忆，或来自图像类型对 benchmark 的识别（图表、OCR 图像），未被检验。
- **Oracle 与 OHR 没有噪声基线**（见下一节的对照）。
- **统计**：无区间，消融单次，单格题数少（p.7、p.10、p.24；E-VR-15）。
- **计算**：默认要多跑一个 CLIP（p.8 Table 3）；99% 档在同计算量比较下竞争力下降（p.8–9）；没有挂钟延迟（UN）。
- **跨模型代价**：每换一个模型都要重跑全部候选拿标签、重新训练（p.9）；直接迁移策略通常失败（p.11）。
- **理论部分**：A.1 只说明“效用预测得准就能选得对”，作者自己说这不证明特征足够（p.17）。AI 使用声明里包含证明撰写（p.11）。

### 重叠（AI）

1. **核心立场相同**：单一剪枝准则对所有输入不是最优，应该按样本选。VIP-Router 已经提出并实证（p.2–3）。理由：两者都把“选哪种剪枝”当成逐样本的决策变量。所以本项目不能写“首次按样本或按题选剪枝策略”；草稿第二部分已把“首次按题型剪枝”列为不能写，VIP-Router 是理由之一。
2. **都用题目文字做决定**：VIP-Router 只用全局文本的学习路由器（p.10 Table 5 第一行），是本项目规则最接近的“学习版”。理由：两者的输入都只有题目，差别在于一个学、一个手写。
3. **候选都含 FastV 一族**：VIP-Router 的候选含 FastV（p.6，层号未给）；本项目的 A 与 A′+B+V 都建在 FastV 的第 2 层剪枝上。
4. **都观察到实际路由远低于 oracle**：VIP-Router 的 OHR 宏平均 26.5%（p.7）；本项目 test1 上路由 +1.15，对 oracle +6.93，约 17%（test1 是选规则用的数据；预注册的 test2 上是 +1.22 对 +6.90，约 18%）。两者量级相近，但指标不同（效用与准确率），不能直接比。

### 可辩护的差别（AI，附理由）

1. **零训练、零参数、零标签**。理由：VIP-Router 每换一个模型，都要重跑全部候选拿正确性标签并重训（p.9），作者还报告策略直接迁移到别的模型通常失败（p.11）。本项目的规则只看题目文字，换模型不需要标签。限制：规则是在 VQAv2 test1 上看过答题结果后选的，只在 test2 上确认过一次，所以“零标签”只指部署时不需要标签；规则在别的模型上是否成立，本项目没有验证（UN）。
2. **路由变量有可解释的机制**。理由：本项目把路由变量绑定到“题目点名的物体是话题，还是答案所在”，并有按答案类型的证据（F38、F39）。VIP-Router 没有题型分析，它的错误诊断只到特征空间近邻，作者自己说不能据此证明表征受限（p.26）。
3. **评测协议不同，本项目的数字更接近常规报告**。理由：VIP-Router 只在依结果筛出的 Group A 上评（p.11），指标是 Group A 准确率和自定义效用；本项目在 POPE、MME-P 全集上用标准指标；VQAv2 用的是验证集里新抽的本地子集，不是 test-dev，不能直接对应官方报告的数字。本项目给按图像重抽的区间，规则预注册。
4. **保留 token 数不随路由改变**。理由：本项目两条候选在同一层、同一预算，路由只改选哪些 token，实测每题耗时 +0.7%；VIP-Router 选 Full 会抬高实际代价（p.6；p.8–9），默认还要额外跑 CLIP（p.8）。
5. **候选本身是新的**。理由：VIP-Router 只在现成方法之间选；本项目的 A′+B+V（输入 embedding 空间的 IDF 查询）本身是新候选，路由是第二层贡献。
6. **本项目的弱点**：只有 2 个候选、1 个模型、1 种剪枝位置；VIP-Router 有 5 个模型、12 个 benchmark（Group A 版；p.6、p.9–10）。审稿人可能会问：学习式路由能不能比手写规则更好。

### Oracle 的说法（AI）

- VIP-Router 把逐样本 Oracle 称为不可达的上界（p.6），用 OHR 报告收回比例（p.7）；Fig. 1(b) 的“可解样本中超过三分之一被 Best Fixed 漏掉”也是同类统计（p.2）。论文没有检验 Oracle 中有多少来自结果的随机翻转，也没有“任意两种方法”或同一方法两次运行的 Oracle 作基线。
- 理由一：本项目测得任意两种方法的逐题 oracle 都有 +5～+9 点（VQAv2），说明这种上界主要反映“两路答对的题不同”，不等于可预测的互补。理由二：Group A 只留降采样答错的脆弱样本，翻转可能更多；VIP-Router 有 4 个剪枝候选，取最大值会更乐观。
- 推论：VIP-Router 的 OHR 分母（如 75% 档 64.91 − 32.54 = 32.37 个效用点）中，可能有很大一部分不可预测。26.5% 不能读成“还有 73.5% 可以挖”；反过来，如果分母松，26.5% 的收回比例并不算低。
- 他们附录里有一个相关但不同的观察：差距大的路由错误，其近邻（冻结全局特征空间，k = 10）的 oracle 标签更混杂：近邻一致率 0.385、熵 0.963，与 oracle 一致的决策是 0.436、0.885（p.26 Table 9）。作者只说两者相关，并说这不能证明完整路由器的表征受限（p.26）。这与“可预测部分有限”一致，但不是噪声检验。
- 写作建议：本项目报告逐题 oracle 时，同时给“任意两种方法”的 oracle 作基线，并指出 VIP-Router 的 OHR 也缺这一基线。用推断的语气写。

### 对写作与实验的影响（AI）

- **相关工作**：把 VIP-Router 写成“学习式、逐样本、在现成方法之间选”的路由；本项目写成“零训练的句式路由 + 何时该按题目词选 token 的证据”。注意 VIP-Router 没有引用 CLASP（E-VR-12），两者是本项目两个独立的上位先例。
- **不要直接比数字**：Group A 准确率和全集 F1、准确率不是一回事。可以引用的旁证只有方向性的：VIP-Router 在 LLaVA-1.5-7B 的 Group A 上，Best Fixed 是 PruMerge+ 而不是 FastV（p.9；论文没给 LLaVA-1.5 上各固定方法的单独数字，VTC-Bench 的 FastV 也不是本项目的 A），这与本项目 CL-10“FastV 一族底座在一般题目上较弱”方向一致，但子集和指标都不同，只能当背景。
- **一个低成本的补充对照（建议，未做）**：在 test1 上，用每题“A 与 A′+B+V 谁更好”作标签，训练一个只看题目文字的小分类器（例如词袋逻辑回归，CPU 即可），在 test2 上与手写规则比较。这相当于 VIP-Router Table 5 第一行在本项目两候选上的版本，可以回答“手写规则是否丢掉了很多可学的信号”。需要 test1、test2 上 A 与 A′+B+V 的逐题输出都已保存（是否齐全未核对，UN）。
- **预算对应**：只有 VIP-Router 的 88.89% 档在名义上对应本项目的 64 档；128、192 档在它的网格之外（按 LLaVA-1.5 的 576 个视觉 token 算，75% 档约 144 个；Qwen2-VL 的视觉 token 数可能随输入分辨率变化（推断，依据是 p.14 参考文献 [28] 的标题），不能直接这样换算）。
