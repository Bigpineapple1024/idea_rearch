## 研究问题

多数剪枝方法只问“留哪些 token”，于是可能留下一堆彼此重复的高分 token，而被剪掉的证据（小字、图表标记、背景）在留下的 token 里找不到代表。作者换个问法：一个 token 被剪掉之后，留下的原始 token 里由谁来代表它？能不能把剪枝写成“全部视觉 token 都要被留下的 token 代表到、并按题目相关性加权”的覆盖最大化问题，在同样的 token 数下好过打分类、合并类与集合类（多样性、覆盖）方法，尤其在剪得很狠的时候？（p.1 摘要；p.1 §1；p.3 §3.2）

## 方法与贡献

式 1–6 在解析中没有文字，下面按 p.3–5 的正文与 p.13 附录 B 的 Algorithm 1 复述。

1. **取特征**：图像经视觉编码器 f_v 与投影层 g，得到投影后的视觉 token V = g(f_v(X_v))，n 个、d 维（LLaVA-1.5 为 576 个）。相似度在投影层输出上算，也就是 LLM 实际收到的表示（p.3 §3.1、§3.3）。用视觉编码器的哪一层，本文没写，[AI] 应是沿用各模型自己的接法。
2. **覆盖效用**：两两余弦 M_ij；每一行减去该行的均值（M_ij − (1/n)·Σ_k M_ik），再截到不小于 0，得 A_ij（p.3 §3.3；p.13 Algorithm 1）。A_ij 读作“j 代表 i 比同一张图里的平均 token 好多少”（p.4 §3.4）。理由（SC）：投影层输出的余弦挤在很窄的范围里，不去均值时每个候选的增益都差不多，贪心分不出冗余与新信息（p.3）。
3. **题目需求权重（第一层注意力探针）**：套用模型自己的对话模板与处理器之后，以用户指令对应的文本位置为 query、视觉 token 的位置为 key，用第 0 个解码层的输入 LayerNorm 与各头的 W_Q、W_K 算缩放点积注意力，再对指令位置和全部头取平均，得每个视觉 token 的相关性 r_i（p.4 §3.3，式 4）。作者强调这不是跑完整个解码层得到的注意力图，而是剪枝之前的一次单层探针（p.4）。然后做最小—最大归一化 r̃_i ∈ [0, 1]，权重 w_i = exp(τ·r̃_i)；τ = 0 即不看题目，默认 τ = 0.3（p.4；p.5 §4.1）。[AI] τ = 0.3 时 w 只在 1～e^0.3 ≈ 1.35 之间，最相关的 token 只比最不相关的多约 35% 的需求，题目的作用是温和的。
4. **贪心选择**：目标 f(S) = Σ_i w_i·max_{j∈S} A_ij（p.4 §3.4 式 5），求和遍及全部 n 个视觉 token（“全部视觉 token 都是要被覆盖的需求”，p.1–2 §1；Algorithm 1 的写法）。p.3 §3.2 先用原始余弦写出同样形式的目标，作者称为 RCM（Representational Coverage Maximization，式 1–2）。每个 token 当前的覆盖 c_i 从 0 开始；每一步选使 Σ_i w_i·max(0, A_ik − c_i) 最大的候选 k，再令 c_i ← max(c_i, A_ik)，直到选满 m 个（p.4 式 6；p.13）。作者说非负效用与权重下目标是单调子模函数，贪心有 (1−1/e) 的近似保证（引 Nemhauser 等 1978，p.3）。[AI] 这就是加权的 facility location；全文没用这个词。
5. **送入 LLM**：按原来的顺序取出选中的原始投影 token V_S，与指令 token H_q 拼成 [V_S; H_q]，送进不改动的解码器；不合并、不改 token 的表示（p.3 §3.1；p.5；p.13）。解码之前只选一次（p.9 §7）。

- **剪枝位置**：在 LLM 之前（解码器的输入处）。探针借用第 0 层的参数，但只在剪之前算一次 Q·K，不让第 0 层处理全部 576 个；所有解码层看到的都是 m 个视觉 token（p.3 §3.1；p.4）。
- **免训练**：是。不改模型，不加任何训练过的部件（p.1 摘要；p.8–9 §6）；同一组设置用于所有模型、基准与预算（p.1–2 §1）。
- **用不用题目文字**：用，只经由第一层注意力探针，作为需求权重；不直接排序，也不改变总个数 m（p.4）（复核时改正：原写“也不决定预算”；p.4 写 τ 越大，越把“representational budget”（名额）往与题目相关的区域倾斜，所以题目权重会影响名额怎么分，只是不改总数）。
- **默认配置**：去均值的相似度、第一层注意力相关性 τ = 0.3、求和聚合（p.5 §4.1；p.19 附录 E）。
- **未写明（UN）**：探针里是否加 RoPE；softmax 在哪些 key 上归一化（只在视觉 token 上，还是连同系统提示与文本）；“用户指令”是否包括回答格式的提示语；选中 token 的位置编号；LLaVA-NeXT 多张子图的预算怎么分（Table 8 说相似度在 2,880 个 token 的源序列上算，[AI] 像是全图一起选）。
- **作者列出的三点贡献**（SC，p.2）：①把剪枝重新表述为 RCM，判据从“留下者重不重要”换成“在目标 VLM 的表示空间里需求有没有被覆盖”；②提出免训练的 CoverPruner，为当前指令挑原始投影 token，不需要外部定位；③多个 VLM、多个压缩率上平均增益明显，并发现相关性用来加权覆盖比用来给 token 排序更有效。

## 预算口径

- **“保留 N 个”指什么**：对 CoverPruner 自己，N 是送进 LLM 的视觉 token 个数（[V_S; H_q] 送进不改动的解码器，p.3 §3.1），所以每个解码层都是 N 个。按本项目的 32 层平均口径，CoverPruner-64 就是 64，与在 LLM 之前剪的方法同一口径（AI，换算）。全文没有“层平均”的说法。
- **CLS**：全文没有提到 CLS。CoverPruner 在投影层输出的 n 个视觉 token 里选，LLaVA-1.5 的 n 是 576（p.5 Table 1 表头 “All 576 Tokens”）。[AI] LLaVA-1.5 送进 LLM 的 576 个本来就不含 CLS（LLaVA 只取 patch 特征，[源码核验](PAPER-0006_VisionZip_源码核验.md) E-VZ-C08）。
- **合并 token**：CoverPruner 不合并（p.3 §3.1）。合并类（ToMe、PruMerge、TRIM）与 VisionZip 的合并 token 怎么计数，全文没写（UN）。[AI] 若表中的 VisionZip 是原版（它的数字与原文相同，E-CP-19），VisionZip-64 进 LLM 的是 54 个主导 token（含 CLS 本身）加 10 个合并出来的上下文 token（[PAPER-0006 笔记](PAPER-0006_VisionZip.md)；[源码核验](PAPER-0006_VisionZip_源码核验.md) E-VZ-C06、C08）。
- **与 FastV 一族怎么对齐**：只说“相同的预算”“各方法参数按公开 / 默认配置”（p.5 §4.1）。FastV、PDrop、SparseVLM、DART 在 LLM 之内剪，表中的 64 是“第 K 层之后留 64 个”、按层平均，还是按 FLOPs 对齐，K 取多少，都没写（UN）。[AI] 若是 FastV 默认的“第 2 层后留 64 个”，它的 32 层平均约为 (2×576 + 30×64) / 32 = 96，多于 CoverPruner 的 64，这种比较对 CoverPruner 不利而不是有利；若按层平均对齐，第 2 层后只留 30 个，与本项目的 FastV-64 相同。本项目在后一种口径下测得 FastV-64 的 POPE 为 36.19（EXP-0002，[改进内容](../专题分析/所有论文在baseline骨架的改进内容.md) 第 39 行），与表中的 35.5 接近，但这不足以判断表中的口径。
- **FLOPs 与时延**：只有 LLaVA-NeXT-7B、POPE、320 个这一张表（p.7 Table 5）：不剪枝 41.7 TFLOPs、prefill 246 ms、decode 52 ms；SparseVLM 4.5 T、71 ms、25 ms；DivPrune 4.2 T、38 ms、22 ms；CoverPruner 3.9 T、33 ms、20 ms。FLOPs 的计算公式没写（UN）。剪枝本身的开销另列在 Table 8（ms/例，在解码器 prefill 之前，p.19），不在 Table 5 里。LLaVA-1.5-7B 上没有时延或 FLOPs 的比较，只有开销：64 档合计 0.143 ms/例（p.19 Table 8）。[AI] 两处存疑：①同是在 LLM 之前留 320 个，DivPrune 与 CoverPruner 的 FLOPs（4.2 对 3.9 T）和 prefill（38 对 33 ms）不同，没有解释；②说 prefill 按 token 报告，但不剪枝时的 246 ms 若是每个 token，近 2,900 个 token 的一张图 prefill 就要十多分钟，更像整段序列的时间。
- **与本项目的换算（AI）**：本项目 64 档 = 32 层平均 64：FastV K = 2 在第 2 层后留 30 个；K = 1 在第 1 层起留 47 个（层平均 63.5）；在 LLM 之前剪的方法每层 64 个。表中 CoverPruner、DivPrune、VisionZip、MMTok 四个按各自的设计都在 LLM 之前减到 64 个（VisionZip 在视觉编码器里压缩；DivPrune 原文 p.8 Table 3 默认在第 0 层剪，即进 LLM 之前；MMTok 原文 p.3–4 在投影层之后、进 LLM 之前选），所以这四行与本项目“在 LLM 之前剪的方法每层 64”同一口径。各方法的位置本文没写，这是按原文推断。

### 消融（LLaVA-1.5-7B，64 个，TextVQA / POPE，单次）

- **相关性怎么用、从哪来**（Table 4，p.7）：不剪枝 58.2 / 85.9；按第一层注意力取前 m 个 51.9 / 73.0；覆盖 + CLIP 相关性 47.3 / 83.8；覆盖 + LLM 词向量相关性 55.2 / 85.6；覆盖 + 第一层注意力（默认）55.6 / 86.1。作者据此说排序与覆盖不能互换：同一信号用来排序时 POPE 远低于不剪枝，放进覆盖当权重则回到不剪枝的水平（SC，p.6–7 §4.3；p.8 §5）。CLIP 与 LLM 词向量两种相关性怎么算，没写（UN）。
- **τ**（Table 9，p.19 E.3）：τ = 0（不看题目）54.93 / 85.5；τ = 0.3 为 55.62 / 86.1。作者说在这个范围内对 τ 不敏感（SC），但表中只有两个值。
- **相似度空间**（Table 10，p.19 E.4）：投影前的编码器特征 48.3 / 81.5，投影层输出 55.6 / 86.1（+7.3 / +4.6）。
- **去均值**（p.19 E.2）：用 LLM 词向量相关性、τ = 0.3 时，TextVQA 54.79 → 55.23；POPE 没报。
- **聚合方式**（Table 11，p.20 E.5）：两行在解析中交错，见 E-CP-13。作者说 Top-K 均值只在 TextVQA 上比不加权的求和略好、POPE 不变，所以不作默认；concave-over-modular 明显更差，作为负结果报告（p.19–20）。
- **[AI] 增益拆分**：①“排序 → 覆盖加权”这一步其实同时换了两样东西。完全不看题目的覆盖（τ = 0）已有 54.93 / 85.5，比按注意力排序（51.9 / 73.0）高 3.0 / 12.5；再加题目权重只多 +0.69 / +0.6。所以 Table 4 支持的主要是“覆盖好于按注意力排序”，“权重好于排序”本身的贡献小。②τ = 0 的覆盖与 Table 1 中 DivPrune-64（54.5 / 85.5）很接近（跨表，假定协议相同）：这两个基准上，CoverPruner 相对 DivPrune 的增益（+1.1 / +0.6）大半来自题目权重，覆盖目标本身只多约 0.4（TextVQA），POPE 上没有差别。VQAv2、GQA 上没有消融，那里的 +1.8 / +0.9 来自哪一部分不知道（UN）。
- **[AI] 一处难解释的数字**：覆盖 + CLIP 相关性的 TextVQA（47.3）比完全不看题目（54.93）低 7.6。按 w = exp(τ·r̃)、τ = 0.3，权重只在 1～1.35 之间变化，这么大的跌幅很难由权重本身造成；可能这一组用了别的 τ 或别的设置，原文没说明。

### 效率（p.7 Table 5；p.19 Table 8）

- Table 5 的数字见「预算口径」。作者说 prefill 快 7.5 倍、decode 快 2.6 倍、FLOPs 少 10.7 倍，F1 还从 86.8 升到 87.3（p.7 §4.4）；按表算 246 / 33 = 7.5、52 / 20 = 2.6、41.7 / 3.9 = 10.7，一致。
- Table 8（ms/例）：LLaVA-1.5 相似度 0.052、探针 0.031，选择 0.092 / 0.060 / 0.038，合计 0.175 / 0.143 / 0.121（128 / 64 / 32）；LLaVA-NeXT-7B 相似度 0.940、探针 0.190，选择 0.742 / 0.391 / 0.233，合计 1.872 / 1.521 / 1.363（640 / 320 / 160）。相似度与探针只算一次，各预算共用（p.19）。各行加和与合计一致（AI 核算）。[AI] 64 步贪心必须一步接一步做，只用 0.060 ms 意味着每步不到 1 微秒，一般要把整个循环合成一次 GPU 调用才做得到；实现方式没写（UN）。

### 定性（p.8 Fig. 4、§4.5；p.15 附录 D；p.16–18 Fig. 5–7；SC，图在解析中看不到）

- 保留的 token 按内容疏密分配：天空、草地、路面这类重复区域少留，文字、被问的物体、人和车多留；比 FastV、SparseVLM 覆盖全图更全，剪掉 94.4% 时最明显；被问的物体上留得更多，同时其余部分也留一些（p.8；p.15）。

### 不确定性

- 全文没有区间、没有运行次数；消融都是单次，只在 64 个、两个基准上（E-CP-21）。
- [AI] 单个基准上 0.1～0.5 分的差（例如 64 档对 MMTok：GQA +0.1、POPE +0.3）在常见测试集的规模下分不出来。

## 限制与替代解释

- **基线数字的来源与 MME 口径**：本文没写基线是重跑还是引用（p.5 §4.1）。部分数字与原文相同，MME 一列却与原文不同（E-CP-19）。[AI] CoverPruner 的平均分领先有相当一部分来自 MME（E-CP-18）；若各方法的 MME 不是在同一协议下测的，Acc. 的排名会受影响。与本项目最相关的 VQAv2、GQA 两列，64 档只比 DivPrune 高 +1.8 / +0.9、比 MMTok 高 +0.7 / +0.1，比 Acc. 给人的印象弱。
- **与 FastV 一族的预算对齐不明**（E-CP-4）：[AI] 这不影响“CoverPruner 好于 FastV 一族”的方向（若 FastV 一族前 K 层看全部，它们用的算力更多），但影响 FastV-64 这一行能否当作“层平均 64 的 FastV”引用。
- **“排序对加权”的结论混了两件事**：Table 4 从“按注意力排序”到“覆盖 + 注意力权重”同时加了覆盖目标和权重；不看题目的覆盖（τ = 0）已拿到大部分增益（E-CP-9、E-CP-10）。[AI] 贡献③应读成“覆盖好于按注意力排序；题目权重在覆盖之上再加一点”。
- **题目的作用很小**：τ = 0 与 0.3 只差 +0.69 / +0.6（E-CP-10），权重最多差 1.35 倍。[AI] CoverPruner 主要是一个不看题目的覆盖选择器，再加一点题目权重；“按指令条件化”的说法要按这个量级理解。
- **第一层注意力的位置偏差没有讨论**：本项目测到 LLaVA-1.5 早层的注意力有一条与内容无关的位置曲线（[F15、F16](../已发现的实验现象.md)）。[AI] 探针分数可能也带着这条曲线；τ 很小时它的影响被压住。“按第一层注意力取前 m 个”在 POPE 上只有 73.0，一部分可能来自位置偏差，而不只是“排序不如加权”（替代解释，未检验）。
- **“剪得越狠增益越大”的替代解释**：32 档的对照里没有 MMTok（E-CP-6）；而且在很少的 token 下，把 token 撒开的选法往往比集中在少数显著区域的选法强。本项目在 POPE 64 档测到同分布的随机选择（60.14）远好于 FastV（36.19）（EXP-0002，[改进内容](../专题分析/所有论文在baseline骨架的改进内容.md) 第 39 行）。[AI] 对打分类的大差距，有一部分是“撒开 对 集中”，不一定是“表示覆盖”本身。
- **正文与表不符**（E-CP-17）。
- **时延与开销的口径**（E-CP-14、E-CP-15）：FLOPs 公式没写；同为 320 个时 DivPrune 与 CoverPruner 的 FLOPs 不同；prefill 的“按 token”口径存疑；开销小得一般要把贪心循环合成一次 GPU 调用才做得到（AI）。
- **没有按题型的分析**（E-CP-21）：作者自己把更细的按能力分析列为后续工作（p.9 §7）。
- **挑选的例子**：Fig. 5 专门挑了剪枝后答对、不剪枝答错的题（p.16）。[AI] 这种翻转在任何两种设置之间都会出现一些，不能说明覆盖本身优于不剪枝。
- **作者自述的局限**（E-CP-20，p.9 §7）：闭源 API 模型用不了；小物体、OCR 细节、精确计数、空间关系上较弱；相似度随 token 数平方增长；视频的时间冗余；解码前只选一次；需要更细的分析。[AI] “精确计数较弱”与本项目“DivPrune 的增益主要在 yes/no 与计数题”不矛盾：前者是相对不剪枝，后者是相对 VisionZip。

### 重叠（AI）

1. **与 DivPrune 底座几乎同一个框架**：同在 LLM 之前、同用投影层输出的余弦、同是贪心的集合选择。CoverPruner 的 τ = 0 版本就是“换了目标函数和相似度校准的 DivPrune”。在它的表里 CoverPruner 比 DivPrune 高 VQAv2 +1.8、GQA +0.9（64 个），这是以 DivPrune-64 为底座（DEC-0061）的下一轮最直接的对手。
2. **“底座 + 题目”已经有人做**：以 DivPrune 为底座再加题目信号，例如 EXP-0033 计划里的 X3（被路由的题先按题目查询取 round(64 × S) 个，再按最大—最小多样性补满），与 CoverPruner 的“覆盖 + 题目需求权重”是同一思路的不同做法。连同它引用的 CDPruner（按指令的条件多样性）与 MMTok（文本—视觉覆盖 + 视觉—视觉覆盖），“免训练、在 LLM 之前、按题目的多样性 / 覆盖选择”已有至少三篇先例（p.2 §2）。
3. **题目信号同类**：本项目的题目查询（输入层词向量与投影 token 的余弦）与它对照里的“LLM 词向量相关性”同属 LLM 输入空间；它的数据显示这类信号放进覆盖里与第一层注意力差不多（55.2 / 85.6 对 55.6 / 86.1，Table 4）。
4. **都不让题目信号单独决定全部名额**：它的 Table 4 中只按第一层注意力取前 m 个，POPE 只有 73.0；本项目的 A′+B+V 也只让 n_q 个名额按题目选、其余按强对照，路由又只对部分题用题目。

### 可辩护的差别（AI，附理由）

1. **何时用题目**：CoverPruner 对所有题一样加权，没有按题型检验（E-CP-21），作者自己把更细的按能力分析列为后续（p.9 §7）。本项目的路由依据是按答案类型的证据：题目点名的物体就是答案时有利，点名的物体只是话题时有害（IDEA-0003）。这一点它没有做。限制：本项目的证据是在 FastV 一族上得到的，在 DivPrune / 覆盖底座上是否仍然成立，要新的开发与确认运行。
2. **剪枝位置的经验事实**：CoverPruner 没有测剪枝位置。本项目有“同一层平均预算下 K = 1（47 个）好于 K = 2（30 个）”（F56）与“多样性选择放到 K = 1 没有平均的帮助”（F72～F74）。可以作为放置的经验事实写，不能写成方法贡献（[草稿](../论文主张与证据_草稿.md) 已规定 K 不是贡献）。
3. **硬定位**：本项目的定位框（IDEA-0005）在它的框架之外（它强调不需要外部定位，p.2）。但定位后覆盖在 VisionZip 底座上不成立，这一条现在不能当作优势。

### 能借鉴的（AI，都需要新的运行，由用户决定）

1. **加权覆盖替换最大—最小**：在本项目的 DivPrune 实现上只换目标函数（加按行去均值、截零），先用 τ = 0。同特征、同位置，能回答“它相对 DivPrune 的增益在我们的流程里还有没有”。
2. **第一层注意力探针**：剪枝前用第 0 层的输入 LayerNorm 与 W_Q、W_K 算指令对视觉 token 的注意力，开销小（LLaVA-1.5 上 0.031 ms/例，Table 8），不必让第 0 层看全部 576 个。条件：RoPE、softmax 范围、指令位置的范围要自己定（UN），并检查位置偏差（F15、F16 那样的曲线）。
3. **“同一信号，排序对加权”的对照**：把本项目的题目查询分别用作排序、用作需求权重，并加上 τ = 0 的覆盖作第三组，这样能把“覆盖的作用”和“权重的作用”分开（它的 Table 4 没分开）。
4. **软路由**：在覆盖底座上，被路由的题用较大的 τ（或用本项目的 IDF × 可视性查询作权重），其余题 τ = 0。这把句式路由从“二选一的流程”变成“题目权重的开关”。是否已有人做过，本次只读了这一篇，不知道（UN），要查新。
5. **软的框**：把 IDEA-0005 的定位框改成“框内 w 大、框外 w 小”的需求权重，而不是硬挪 16 个名额。
6. **K = 1 的干净对照**：FastV K = 1 的排序用的是第 0 层的注意力，它在剪之前就能像探针一样算出来。“同一排序、在 LLM 之前每层留 64 个”对“K = 1、第 1 层起留 47 个”，可以把“第 0 层看全部 576 个”这件事单独分出来。它的 Table 4 第二行（在 LLM 之前按第一层注意力取前 64 个：51.9 / 73.0）是附近的一个点，但它的信号是指令位置的平均，不是最后一个 token。

### 新颖性威胁（AI）

- **高**：“在 LLM 之前做多样性 / 覆盖选择、再加题目信号”这类方法本身（CoverPruner，以及更早的 CDPruner、MMTok），包括“以 DivPrune 为底座加题目查询”（如 EXP-0033 的 X3）；“相关性放进集合目标当权重，而不是用来排序”的说法（它的贡献③、p.8 §5，并引 Li 等 2026 的同类说法）。

(a) 剪枝后留下的视觉 token 的位置编号（position ids / RoPE 位置）：全文未见。全文没有出现 position ids、RoPE、重新编号、插值这类说法。只有两处与“顺序”有关，都不是位置编号：p.3 §3.1 写保留“an ordered subset V_S”；p.13 附录 B Algorithm 1 末行写 “Return V_S in the original visual-token order”，即按原来的视觉 token 顺序排好再送入解码器。另外 p.4 §3.3 说探针在剪枝之前、“after each MLLM has placed visual and text tokens into its native input layout”（用各模型自己的输入排布）算 Q·K，这讲的是探针，不是剪枝后的位置编号。选中 token 在解码器里用原始位置编号还是连续编号，全文没写（UN）。

(b) 定位类任务评测：全文未见。8 个 LLaVA 系列基准（VQAv2、GQA、SQA-IMG、TextVQA、POPE、MME、MMBench、MMBench-CN，p.5 Table 1）和 10 个 Qwen2.5-VL 基准（HallBench、MME、VQAv2、ChartQA、AI2D、RealWorldQA、CCBench、OCRVQA、SQA-IMG、POPE，p.7 Table 3）里没有 RefCOCO / RefCOCO+ / RefCOCOg，没有输出框坐标、目标检测或 visual grounding 的评测，也没有相应结果。与此相关的只有三处，都不是定位评测：p.2 贡献②写“without external localization”（指方法本身不需要外部定位模块）；p.9 §7 Limitations 把 “grounding” 列在“后续需要做的更细分析”里（OCR、计数、grounding、空间推理、幻觉、时间定位），说明作者自己没有做；p.18 Fig. 7 图注里的 bounding boxes 是在 GQA 的示意图上标出与题目对应的关键区域，用来看保留的 token 有没有覆盖这些区域，不是模型输出的框，也不是定位指标。
