## 研究问题

现有的视觉 token 剪枝大致两类：按注意力挑“重要”的 token，会留下很多彼此重复的 token；按 token 之间的相似度去掉重复的，又不看用户的问题。能不能在一次选择里同时照顾“彼此不重复”和“与问题相关”？（p.1 摘要；p.2 §1、Fig. 1）

## 方法与贡献

- **设定**：MLLM 由视觉编码器、投影层、LLM 组成；视觉 token H_v = 投影层(编码器(图像))，共 n 个；剪枝就是只留 m 个（m < n）（p.4 §3.1）。
- **第 1 步，相似度核**：用视觉 token 两两之间的余弦相似度构成 DPP 的核矩阵 L（p.4 §3.2）。正文只说“视觉特征”。在 LLaVA 上是 CLIP 视觉编码器的特征还是投影层输出，没写明：§3.1 把 H_v 定义为投影层输出，§3.3 又把 CLIP 特征也记作 H_v（UN）。层号没写（UN）。
- **第 2 步，指令相关性**：每个视觉 token 与一个指令向量算余弦，得到长度为 n 的相关性 r，再做 min-max 归一化，压到 0～1（p.5 §3.3）。
  - 视觉编码器带配套文本编码器的模型（原文举 CLIP、SigLIP，引用 LLaVA、LLaVA-NeXT、LLaVA-OneVision）：视觉 token 用视觉编码器的特征，指令向量用配套文本编码器的特征。[AI] LLaVA-1.5 同样用 CLIP，按此归入；Fig. 3 也说相关性图是用 LLaVA-1.5-7B 算的（p.5）。
  - 只有视觉编码器的模型（Qwen2.5-VL、InternVL3）：视觉 token 用投影层输出，指令向量取 LLM 中这条指令所有 token 嵌入的平均。
  - 没写的（UN）：CLIP 取哪一层、是否经过 CLIP 的投影头；文本向量取哪个位置；指令包括哪些文字（只有问题，还是连同“用一个词回答”之类的提示）；超过 CLIP 文本长度上限时怎么处理；“LLM 中的 token 嵌入”是否就是输入层的词向量。
  - [AI] LLaVA 用的是 CLIP 倒数第二层的 patch 特征，它本身不在 CLIP 的图文共同空间里，要和文本向量算余弦，多半要再经过 CLIP 的投影头；LLaVA 也不带 CLIP 文本编码器，要另外加载。
- **第 3 步，条件核**：用相关性“调制”原来的核，得到条件核；子集的对数概率同时包含特征相似度与指令相关性（p.5 §3.4）。公式在解析文本里缺失。
  - [AI] DPP 文献里常见的写法是 L̃ = diag(r̃)·L·diag(r̃)。这时 log det(L̃_S) = Σ_{i∈S} 2·log r̃_i + log det(L_S)，即“所选 token 相关性的乘积”乘以“它们彼此不重复的程度”。附录 C.4 由式 (8) 推出 α = θ/(2(1−θ))，用来变换 r̃（p.20），与这种写法相合；照此推算，主实验相当于 θ = 2/3。要对照 PDF 的式 (7)–(8)。
- **第 4 步，求解**：DPP 的最大后验求解是 NP 难的，改用 Chen 等（2018）的快速贪心：每一步加入使行列式增益最大的 token，用 Cholesky 分解增量更新，复杂度 O(nm²)；CUDA 并行后每个样本额外不到 10 ms（p.5 §3.4；p.14–15 附录 A、Algorithm 1）。
  - 作者说这个贪心有 (1 − 1/e) 的近似保证（p.5）。[AI] 这类保证一般要求目标函数单调，log det 一般不单调，论文没有说明条件。
  - [AI] 按 Algorithm 1，第一个选中的是核对角线最大的 token；若核是上面的写法，L_ii = 1，第一个就是相关性最高的 token。
- **剪在哪里**：在 LLM 之前。留下的 m 个视觉 token 与文本 token 一起送进 LLM（p.4 Fig. 2；§3.1）。不需要注意力分数，所以能与 FlashAttention 一起用（p.2 §1）。留下的 token 按什么顺序、用什么位置编号送进 LLM，没写（UN）。
- **是否免训练**：是，不训练、不微调，即插即用（p.1 摘要；p.2 §1；p.9 §5）。
- **是否用到题目文字**：用。所有题都用同一种方式（p.5 §3.3），没有按题型切换。
- **可选的平衡因子 θ**：附录 C.4 加了一个 θ，调节相关性与多样性的比重；最优值随 benchmark 变，主实验不用它（p.20–21，Table 10）。
- **作者列出的三点贡献**（SC，p.2–3）：①提出 CDPruner，即插即用、与模型无关，最大化条件多样性；②用 DPP 重新表述剪枝问题，同时考虑特征相似度与指令相关性，实现随指令变化的剪枝；③在多个 benchmark、多种剪枝比例上达到最好。

## 预算口径

- **“保留 N 个”指什么**：CDPruner 与在 LLM 之前剪的对照（PruMerge+、TRIM、VisionZip、DART、DivPrune），N 都是送进 LLM 的视觉 token 个数，每一层相同（p.4 Fig. 2；p.6 Table 1 表头“保留 64 个（剪掉 88.9%）”，88.9% = 1 − 64/576）。[AI] 所以这些方法的“64”就是本项目口径下的层平均 64，与本项目的 VisionZip-64、DivPrune-64 相同。
- **CLS 与合并 token**：CDPruner 只挑选、不合并（p.4–5 §3）。[AI] 按 §3 的描述，它也不用 CLS；它用在了需要 [cls] 的方法用不上的 Qwen2.5-VL 上（p.8）。LLaVA-1.5 每张图 576 个视觉 token（p.15 B.1.1），[AI] 即 24×24 个 patch，不含 CLS。VisionZip 的主导 / 上下文 token 怎么分、PruMerge+ 合并后的 token 怎么计，全文没写（UN）。[AI] 表中 VisionZip-64 与本项目按 54 个主导 + 10 个上下文的实测几乎相同（POPE 77.0 / 77.03，MME 1365.2 / 1364.22，GQA 55.1 / 55.18；EXP-0002-R17、R35，EXP-0022-R07），大概率也是 54 + 10。
- **与 FastV 一族怎样对齐**：全文只写 FastV 在第 2 层之后剪掉注意力最低的 token（p.18 B.3.1），没有写“保留 N 个”是第 2 层后的个数还是层平均（UN）。两条间接证据都指向层平均（AI）：
  - 表 5（LLaVA-NeXT-7B）的 KV cache：不剪枝 2880 个对应 1440.0 MB，即每个视觉 token 0.5 MB（32 层，4096 维，半精度）。FastV、PDrop、SparseVLM 是 160.3 / 160.2 / 161.2 MB，约等于层平均 320 个；若 FastV 在前 2 层保留全部 2880 个、之后留 320 个，应约为 240 MB。160.3 MB 正好对应 K = 2、第 2 层后留 150 个（(2×2880 + 30×150)/32 = 320.6 个）。13B 的表 9 同向（250.8 MB，约 321 个）。
  - 表 1 的 FastV-64 / 128 与本项目层平均口径的实测几乎相同：POPE 35.5 / 36.19、68.2 / 68.29，MME 973.5 / 979.58、1368.9 / 1363.21（本项目 EXP-0002-R08～R11，K = 2，第 2 层后留 30 / 98 个）。若“64”是第 2 层后留 64 个，POPE 应明显高于本项目留 30 个时的 36.19。
  - PDrop、SparseVLM 的分段日程没写（UN）。本项目实测过 SparseVLM 的名义预算与实际层平均不一致（名义 64 档实际 82.25 个，experiment-results 的 C-0002-5）。表中 SparseVLM-64 的数字低于本项目实测（POPE 69.7 对 77.67，MME 1190.4 对 1279.59，GQA 52.0 对 53.78；EXP-0002-R40、R41，EXP-0022-R08），版本或设置可能不同（UN）。

### 不确定性

- 所有数字都是单次运行，没有方差或区间（UN）。[AI] 很多关键差距在 1 分左右（如 64 档 GQA 上 DPP 只比 DivPrune 高 0.1），单次运行分不清是否是噪声。本项目的经验：开发集上 +0.5～+1.4 的差别在新数据上大多消失（F59）；MME-P 一个答案的变化就移动约 1～5 分（DEC-0060）。
- Acc. 与 Rel. 都是 10 项的平均，Rel. 允许单项超过 100%（如 VizWiz、POPE），会掩盖单项的方向：64 档 CDPruner 在 MMB-CN 上比 VisionZip 低 2.2、SQA 上低 0.9（AI）。
- VQAv2 test-dev 要提交官方服务器评分，MM-Vet 由 ChatGPT 打分（p.17），两者的波动都没有报告（AI / UN）。

## 限制与替代解释

- **对照数字的来源**：重跑还是引用，全文没写（p.18 B.4 只写评测用 LLaVA 官方实现）。[AI] 不剪枝、VisionZip、FastV 与本项目实测几乎相同，说明评测口径接近；SparseVLM 明显低于本项目实测（E-CD-19），版本或设置可能不同，对 SparseVLM 的比较要打折扣。
- **FastV 一族的放置**：只测了原版 FastV（第 2 层之后剪，p.18），按推断是层平均口径（E-CD-16）。[AI] 本项目发现同一层平均预算下 K = 1 比 K = 2 好得多（F51、F56），FastV 一族加上去位置先验、分块等修正后能接近或超过 VisionZip-64（F56、F69）。所以“注意力类方法在 64 档下降超过 25%”（p.6–7）主要说明原版 FastV（K = 2）弱，不能当作“LLM 内的注意力不能用来剪枝”的证据；这句话对 SparseVLM（87.1%）也不成立。
- **统计**：全部单次运行，没有区间；Table 10 的“逐项取最好”在评测集上选（E-CD-12）。
- **公式缺失**：条件核的确切形式、主实验对应的 θ，只能从文字和 C.4 推断（E-CD-13、E-CD-26）。
- **相关性的实现细节**：CLIP 特征的层与投影头、指令文字、长度上限都没写；LLaVA 版要另外加载 CLIP 文本编码器，它的显存与时间没有单独报告（UN / AI）。
- **效率口径**：表 5 中三种在 LLM 之前剪的方法时间、FLOPs、KV cache 完全相同，DPP 的额外时间（每样本不到 10 ms，约为 38 的四分之一）是否计入不清楚；ms/token 的含义不清（UN）。
- **文字与表格不一致**：摘要、引言的四个数字（E-CD-18）；§4.2 的“下降 3.4%”与表中 97.0%（E-CD-7）。
- **POPE 超过不剪枝的解释**：作者猜想剪枝可能减轻幻觉（p.7），没有检验。[AI] 替代解释：F1 对答 yes 的比例敏感，按题目相关性选 token 会让模型更常答 yes。本项目在 POPE 上看到按题目相似度选 token 会增加负样本上的误报（F30、F41），GQA 上 yes/no 的增益有一部分来自改正偏向 no（DEC-0038）。CDPruner 只报 F1，没有报 yes 比例、精确率与召回，两种解释分不开（UN）。
- **因果说法**：“DivPrune 在 InternVL3 上掉得多，是因为不考虑指令相关性”（p.19 C.2）、“更大的 LLM 带来更准的注意力”（p.19 C.1）、“Qwen2.5-VL 掉得多是因为投影层里已经压缩过”（p.8）都是作者的解释，没有对照检验（SC）。
- **证据形式**：没有失败例子；定性图只有 POPE 的点名物体题（Fig. 3、5），是挑出来的例子；没有按题型的分析（E-CD-24）。VizWiz 的解释（p.7）没有数据。

## 作者自述的局限

- 只能用于能在推理时拿到视觉 token 的开源模型；ChatGPT、Gemini、Claude 这类黑盒模型用不上（p.21 附录 E）。
- Qwen2.5-VL、InternVL3 等较新的模型对剪枝更敏感，掉得比 LLaVA 系列多；作者认为原因是这些架构里已有 pixel unshuffle 一类的视觉 token 压缩，把在这类架构里高效推理列为未来工作（p.21 附录 E；p.8 §4.5）。
- VizWiz 的题目信息少，条件引导作用有限（p.7 §4.2）。
- θ 的最优值随 benchmark 变，是否引入并调这个超参数，由使用者按需要决定（p.20–21 C.4）。
- 社会影响：降低部署成本；不能防止 MLLM 被滥用（p.21 附录 F）。

### 与按题目句式路由（IDEA-0003）的关系（AI）

- CDPruner 对所有题用同一种相关性条件，没有按题切换（p.5）。但它自己的材料里有三处与路由的出发点一致：θ 的最优值随 benchmark 变（Table 10），逐个 benchmark 取最好能再加 0.3 Acc.；TextVQA、MMB-CN 的最优 θ 是 0，即不用相关性更好；VizWiz 的题目信息少，条件引导不起作用（p.7）。也就是说，“题目相关性不是对所有题都有用”这个观察不新（与 CLASP、VIP-Router 一样）；本项目能辩护的是按句式逐题切换、零训练、在新数据上确认，以及按答案类型的证据。
- 两边“题目相关性怎样进入选择”不同，这会决定路由在强底座上还有没有用：
  - 本项目的 A′+B+V 把 n_q 个名额硬分给与题目最像的 token，K = 2 时第 2 层后只有 30 个，在问被点名物体属性的开放题上有害（F38、F39）。
  - CDPruner 把相关性当作乘进 DPP 核的权重，仍受多样性约束，而且 64 个都在 LLM 之前。按 Table 10 与 Table 1 推算，加相关性后 VQAv2 +0.8（VQAv2 里开放题不少），只有 TextVQA、VizWiz、MMB-CN 略降（E-CD-13）。
  - 所以“题目相关性对开放题有害”可能只在“硬分名额、名额很少”时成立。换成 CDPruner 式的软结合与 64 个的底座后是否还在，没有证据（UN）。这是下一轮最该先回答的问题。

### 与 K = 1 的关系（AI）

- CDPruner 只在 LLM 之前剪，没有测 LLM 内的放置；它的 FastV 对照是原版 K = 2，按推断用的是层平均口径（E-CD-16）。所以“同一层平均预算下，预算花在哪几层”这个问题，CDPruner 没有涉及。
- 本项目发现 K = 1（留 47）好于 K = 2（留 30）（F51、F56）。CDPruner 表中 FastV 一族在 64 档的低分（GQA 46.0、POPE 35.5）主要反映原版 K = 2 的弱，引用时不要写成“LLM 内剪枝不行”。
- 本项目还发现同样的多样性选择放到 K = 1 没有平均的帮助（VQAv2 −1.51、GQA +0.88；任务说明），与 DivPrune 的 Table 3 同向（[查新补充](../专题分析/查新补充_覆盖与多样性_2026-10-26.md)）。CDPruner 对此没有证据。K = 1 不受 CDPruner 威胁，也得不到它的支持。

### 与覆盖 16 的关系（AI）

- CDPruner 的“多样性”在特征空间里算（token 特征的余弦），不看空间位置，没有框，也没有固定名额。本项目的覆盖是空间的（A 的分块轮流取；覆盖 16 把名额挪进定位框）。两者不是一回事。
- 本项目在 VisionZip 底座上测到，按区域多留不比按逐 token 相似度多留好，GQA 上反而低 0.78（DEC-0054，EXP-0029 的 Q3）。这与 CDPruner 只用逐 token 相关性就有效不矛盾。
- K = 1 路由 + 覆盖 16 在 GQA testdev 上 57.22（EXP-0027-R05），与 CDPruner 同一划分，比它报告的 58.6 低 1.4（不是复现，见上表）。

### 与 DivPrune 底座（DEC-0061）的关系（AI）

- CDPruner 本身就是“多样性底座 + 指令相关性”：底座用 DPP（全局多样性）而不是 DivPrune 的最大-最小，再乘上相关性。它报告两步都有收益（Fig. 4）；按 Table 10 推算，64 档 DPP 比 DivPrune Acc. +0.6，相关性再加 +0.8（E-CD-13）。
- 本项目实现的 DivPrune-64 比 VisionZip-64 高 +2.20 / +1.63（VQAv2 dev2 / GQA val400），增益主要在 yes/no、计数题（任务说明）。CDPruner 表 1 的方向相同：DivPrune-64 比 VisionZip-64 在 VQAv2 +1.7、GQA +2.4、POPE +8.5，而在 MME（−30.5）、MMB-CN（−3.1）、MMVet（−1.3）、TextVQA（−1.0）上更低，优势集中在是非题多的 benchmark。
- 本项目 K = 1 时多样性选择比按 CLS 注意力排序高约 2 分（任务说明），与 CDPruner、DivPrune“多样性好于按重要性排序”的方向一致。
- 所以，若下一轮在 DivPrune-64 上加本项目的题目查询，最接近的前人工作就是 CDPruner，审稿人一定会要求和它比。剩下的差别只有三条：①按句式路由（只对一部分题用题目）；②查询来源（LLM 输入层的 IDF × 可视性加权平均，对 CLIP 文本向量）；③多样性算法（最大-最小对 DPP）。其中③对 CDPruner 有利（它报告 DPP 更好）。

### 能借鉴什么（AI）

1. **DPP 贪心**（Algorithm 1，p.15）：实现短、每样本不到 10 ms，可以作为 DivPrune 之外的第二个多样性底座；先在本项目开发集上看 DPP 与最大-最小的差（CDPruner 自己推算出的是 Acc. +0.6）。
2. **相关性乘进核、再用 θ 调强度**：给路由提供了连续的旋钮。不路由的题 θ = 0（纯多样性），路由的题 θ > 0，就是本项目路由在 DPP 底座上的自然版本；还可以检验“按题选 θ”是否好于 CDPruner 的单一 θ。
3. **查询来源的干净对照**：在同一个 DPP 框架里只换相关性的来源——CLIP 文本向量（CDPruner 原版）、LLM 指令嵌入的平均（CDPruner 的另一支）、IDF × 可视性加权平均（本项目）——能单独说明本项目查询的贡献。
4. **相关性的 min-max 归一化**：让相关性成为 0～1 的乘子；本项目的余弦若要乘进核，也要类似处理。
5. **外部参照**：表 1 的不剪枝、VisionZip-64、FastV-64 / 128 与本项目实测几乎相同（E-CD-19），可以把它当作本项目评测流程（GQA testdev、POPE F1、MME-P）的外部校准。

### 新颖性威胁：它是否已经做了我们想做的事（AI）

- **已经做了（威胁高）**：在 LLM 之前、免训练地把“与题目相关”和“彼此不重复”放进同一次选择。本项目不能把“题目相关 + 多样性 / 覆盖”的组合当作贡献；在 DivPrune 底座上加题目相关性，本身就接近 CDPruner。
- **部分做了（威胁中）**：用“文本向量与图像 token 的余弦”作相关性。对没有配套文本编码器的模型，CDPruner 已经用“LLM 中指令 token 嵌入的平均”对投影层输出算余弦（p.5），这是本项目查询去掉 IDF × 可视性加权后的样子。IDF × 可视性加权、在 LLaVA 上用 LLM 输入空间（它对 LLaVA 用 CLIP），全文没有。
- **没有做（威胁低）**：按题目句式决定用不用题目相关性；按答案类型的分析；K = 1 的放置；空间覆盖与定位框。这些仍可能是本项目的贡献，但都要以 CDPruner 为对照来证明。
- **数字上的差距**：GQA testdev（同一划分）64 档，CDPruner 报告 58.6，本项目最好的已确认配置 57.22；POPE 64 档 87.5 对 82.74；VQAv2 相对 VisionZip-64 +3.0 对 +0.19。现在没有依据说“比最好的免训练方法强”。

## 本项目已引用说法的核对

### DEC-0016 的说法

- 原文（[version-evolution](../version-evolution.md) 第 22 行）：物体框分析后，“‘题目相关 + 覆盖’的组合已被 CDPruner（NeurIPS 2025，检索摘要级）实现，候选 1 的新颖性降为低”。
- 核对结果：**部分成立**。
  - 成立的部分：CDPruner 确实在同一次选择里同时用了题目相关性和多样性（p.1 摘要；p.4–5 §3.2–3.4）。怎么用的：①每个视觉 token 与指令向量算余弦，min-max 到 0～1，得到相关性；②视觉 token 两两余弦相似度构成 DPP 核；③用相关性调制核，子集的对数概率同时含两者；④贪心求解，选出 m 个。两者在一个目标里连续地权衡，不是先按一个挑、再按另一个补，也不是分开的两份名额（不同于 CLASP 的 K1 / K2 和本项目的 n_q / A）。消融显示两部分都有贡献（p.9 Fig. 4；Table 10）。
  - 要限定的部分：
    - 它的“覆盖”是特征空间的多样性（不选彼此相似的 token），不看位置，没有空间分块、没有框，也没有强制的名额。本项目在 DEC-0016 前后说的覆盖是空间的（6×6 分块轮流取，[第 7 步排序](../第7步_改进方向排序.md)里写成“强制覆盖”）。“题目相关 + 强制覆盖 / 空间覆盖”这一组合，CDPruner 没有做。
    - 对 LLaVA，相关性来自 CLIP 文本编码器，不是 LLM 的注意力，也不是 LLM 输入层的词向量（p.5 §3.3）。
    - 对所有题一视同仁，不按题型切换。
    - “NeurIPS 2025”：全文 v2 只写 “Preprint. Under review.”，无法核实（UN）。
  - “候选 1 的新颖性降为低”：对“题目相关 + 多样性”这个组合本身成立；对本项目后来的输入层 IDF × 可视性查询、按句式路由、按答案类型的证据不适用（全文都没有）。

## 与当前项目的关系

- **定位**：CDPruner 是“在 LLM 之前、免训练、指令相关性 + DPP 多样性”的代表，与只有相关性的 TRIM、只有多样性的 DivPrune / DART 同在它的表 1 里。论文的相关工作里不写“首次把题目相关与多样性结合”，也不写“首次文本引导的剪枝”。
- **主表**：GQA testdev 与 CDPruner 同一划分，可以把它报告的数字放进“文献报告值”一栏，注明未复现、实现不同；VQAv2 划分不同，只能比相对 VisionZip-64 的差。POPE F1、MME-P 的口径对得上（E-CD-19）。
- **下一轮（DivPrune 底座）**：CDPruner（或按论文实现的 DPP + 相关性）应作为必须比较的对照。用官方代码要用户许可下载；按论文自己实现，要先对照 PDF 的式 (7)–(8) 与 Algorithm 1，并确定 CLIP 特征的层与投影头。
- **一个低成本的检验（建议，未做）**：在 DivPrune / DPP 底座上比较三种方案：全部不加相关性、全部加同样强度的相关性（CDPruner 式）、只对路由题加（本项目式），并按题型看“题目相关性对开放题是否有害”。这能直接回答路由在强底座上还有没有用。需要新的开发运行，不在本笔记范围。
- **写作提醒**：CDPruner 的 POPE 报告值高于不剪枝；本项目发现按题目相似度选 token 会增加负样本误报（F30、F41），CDPruner 只报 F1。引用时不要把它的 POPE 当作“减少幻觉”的证据，也不要把它表中原版 FastV 的低分当作“LLM 内剪枝不行”的证据。
