## 研究问题

在视频大模型里，按注意力剪视觉 token 如果放在很浅的解码层，高压缩时效果会大幅下降。作者问：为什么浅层的注意力不可靠？能不能不训练、用简单的校正，让“在第一个解码层就按注意力剪”变得可靠，从而省下大部分预填充的计算？（p.1 摘要；p.2–3 §1）

## 方法与贡献

- **位置**：在 LLM 之内剪，不在 LLM 之前。实验里在第一个解码层剪（原文 “we apply pruning at the first decoder layer”，p.12 §5.1）。进入 LLM 的是全部视频 token，剪后留下的这组 token 送进更深的层（p.10）。按 TFLOPs 推算，第 0 层看全部，第 1 层起只留 R 比例的 token，相当于 FastV 的 K = 1（AI，见「预算口径」）。Fig. 3 的图中文字有 Layer 0、Layer k（p.6），方法写成可放在一般的第 k 层（AI）。
- **第一步，段内互看（SegM，p.7–8 §4.1）**：
  - 把同一帧的视觉 token 取平均，得到每帧一个向量；相邻两帧的余弦相似度与阈值 τ_seg（= 0.9，p.12）比较，据此切段（公式缺失，“相似度低于阈值处切开”是 AI 的读法）。切出的是连续、不重叠的几段帧。
  - 在注意力里，视觉 token 只能看同一段内的视觉 token（块对角的掩码），段与段之间完全隔开（p.7）。
  - 作者的理由：浅层里视觉 token 之间交流不足，一些信息少、范数大的 token 会拿到很高的注意力（作者称注意力塌缩）；限制在段内，能让局部信息先聚起来（p.2–3；p.7–8）。
  - 用哪一层的特征：H_v 是送入解码器的视觉 token（p.5 §3），所以切段用的应是 LLM 输入的视觉 token（AI）。SegM 用在哪几层，正文没有明说（UN；AI：剪枝之前的第 0 层）。
- **第二步，位置偏差校正（PosC，p.8–9 §4.2）**：
  - 排序用的分数是最后一个文本 token 对每个视觉 token 的注意力（沿用 FastV 等的做法，p.8）。最后一个文本 token 在题目之后（AI：按因果注意力，它看得到整道题），所以分数会随题目变化；全黑视频上的偏差也是对这个 token 算的（p.9）。这是全方法里唯一用到题目文字的地方。
  - 作者认为浅层注意力带有与内容无关的位置偏差：RoPE 随距离衰减，使序列末尾（视频的后几帧）的 token 分数偏高；FastV 高比例剪枝时留下的大多来自序列末尾（p.3；p.8 Fig. 4）。
  - 估计偏差：把一段全黑的视频送进模型，所有视觉 token 都一样、没有信息，这时最后一个文本 token 对各视觉 token 的注意力 b 只反映位置编码带来的偏差（p.9）。
  - 校正：从原注意力里减去 λ × b，λ 控制强度（p.9 的公式，Fig. 3 标为 Eq.5；λ = 0.6，p.12）。校正只用于排序，不改 token 的值（p.9）。
  - 代价：作者说只要一次轻量推理，每个剪枝步一次，之后各层的注意力仍可用 FlashAttention（p.9）。是每道题都用这道题的文字跑一次，还是全局只跑一次，没写清（UN）。注意力是否对各头取平均，没写（UN）。
- **第三步，剪枝（p.9 §4.3）**：在校正后的分数上，对整段视频的全部视觉 token 取前 K 个（不是每帧各取）。作者把选中的这组 token 叫 register token，它们分布在各段里。
- **第四步，去重与补足（RegD，p.9–10 §4.3）**，在每段内做三件事：
  1. 预过滤：未选中的 token 若与某个选中 token 的相似度超过 τ_filter，就并进与它最像的那个选中 token；其余未选中的 token 留给第 3 步。
  2. 去重：选中的 token 按顺序比较，相似度超过 τ_merge 就并进前面的 token，否则成为新的比较起点（原文同时用了“相邻”和“新的起点”两种说法，是与前一个比还是与当前起点比，读不清）。
  3. 补足：去重使个数变少；为了保持预设的个数，把剩下的未选中 token 按顺序聚类（与当前簇的相似度超过 τ_cluster 就加入，否则开新簇），给每个簇心算一个多样性分数（同时看它与选中 token 的平均相似度和簇的大小，β 平衡两者；β = 0.008，p.10、p.12），按分数从高到低补回。
  - 正文没写的：τ_filter、τ_merge、τ_cluster 的取值；相似度用哪一层的特征、是不是余弦；“并进”是平均还是加权；簇心是簇的第一个 token 还是均值；保留 token 的位置编号怎么处理（都 UN；作者说更多细节在补充材料，p.12）。
- **免训练**：是。摘要、Fig. 1、贡献 2、§4 开头与结论都这样写（p.1、p.2、p.4、p.7、p.14）。三个超参数按经验定，并对所有实验固定（p.12）；用哪些数据定的，没写（UN）。
- **是否用到题目文字**：用到，但只通过最后一个文本 token 的注意力（第二、三步）；SegM 与 RegD 只看视觉 token 之间的相似度（p.7、p.9–10）。没有按题型的处理。
- **作者列出的三点贡献**（p.4，SC）：（1）指出浅层剪枝失败的三个因素：注意力塌缩、位置编码偏差、选中 token 之间的冗余；（2）提出即插即用、免训练的框架，含段内互看、位置偏差校正、去重；（3）在不同视频模型（举例 LLaVA-OneVision、Qwen2.5-VL）和多个 benchmark 上优于其他压缩方法。

## 研究设计

- **模型**：LLaVA-OneVision-7B、LLaVA-Video-7B、Qwen2-VL-7B、Qwen2.5-VL-7B（p.11–12 §5.1）。除非另说，按各模型的官方配置（p.11）；所有方法输入分辨率相同、算力可比（p.12）。LLaVA-OneVision 每个视频取 32 帧、每帧 196 个 token，共 6272 个（p.12）；其他三个模型的帧数与 token 数没写（UN）。
- **benchmark**：MVBench、LongVideoBench、MLVU、VideoMME（VideoMME 另分短 / 中 / 长三档）；视频从 10 秒到 2 小时，合计一万多道题（p.11）。Table 2 没有 MLVU（p.11）。全部是视频问答，没有图像 benchmark（E-SH-7）。
- **对照**：8 个免训练方法（p.11）。FastV（从第 2 个解码层起按注意力剪）、PDrop（从第 4 层起分段剪）、Feather（第 2 层去掉位置编码、均匀采样后剪）、FrameFusion（逐层按相似度与注意力剪，用平均保留比例换算等效 R）、DyCoke（进 LLM 之前按时间合并）、STTM（时空合并）。VisionZip（在 LLM 之前按视觉编码器剪）与 HoliTom（LLM 外 + LLM 内两段）只在 Table 3 作底座：ShaRP 接在 VisionZip 后面，或替换 HoliTom 的 LLM 内一段。对照数字是作者重跑还是引用，没有逐一说明（UN；AI：R 都按 TFLOPs 重新设过，像是重跑的）。
- **预算**：LLaVA-OneVision 上，FastV 一类的保留比例约为 25% / 20% / 15% / 10%，各方法按 TFLOPs 对齐分成四组（p.12；Table 1）；其他三个模型各只有一组（Table 2）。
- **实现**：LMMs-Eval 框架，NVIDIA A40（p.12）。λ = 0.6、β = 0.008、τ_seg = 0.9（p.12）。
- **消融**：只在 LLaVA-OneVision、R = 23.5% 上（p.14 Table 5）。
- **统计**：全文没有重复运行、随机种子、标准差或区间（全文未见）；解码方式没写（UN）。

## 预算口径

- **“保留比例 R”指什么**：Table 1 的注说 R 是各方法视觉 token 的保留比例（p.10），正文没有说是哪一层的。ShaRP 进入 LLM 的是全部视频 token（LLaVA-OneVision 为 6272 个，p.12），在第一个解码层之后才剪，所以它的 R 不是“LLM 输入的个数”，也不是层平均，而是剪后各层留下的比例（AI，依据是下面的推算）。
- **与 FastV 一族怎么对齐**：按可比的 TFLOPs 分组（Table 1、2 的注；p.12）。同一组里各方法的 R 不同，例如 11 TFLOPs 一组 FastV 25%、PDrop 28.5%、ShaRP 28.2%（p.10）。FrameFusion 逐层剪，作者用它的平均保留比例当等效 R，TFLOPs 记“-”（p.10–11）。
- **TFLOPs 的口径**：只算视频 token（p.10 Table 1 注），公式与细节在补充材料（未取得）。本笔记用 FastV 的公式（每层 4nd² + 2n²d + 2ndm，见 FastV 的[解析全文](../../literature/processed/PAPER-0004/FastV-arxiv-2403.06764.md) §4.2）和 Qwen2-7B 的配置（d = 3584、前馈层宽 18944、28 层；不在全文中，是本笔记的外部知识；LLaVA-OneVision-7B 的语言模型是它）推算（AI）：
  - 不剪：6272 个 token 过 28 层 = 40.77，表中 40.8；
  - FastV 25%：前两层 6272 个、其后 26 层 1568 个 = 11.00，表中 11，即 K = 2；
  - ShaRP 28.2%：只有“第 0 层 6272 个、其后 27 层约 1769 个”才得 11.00；若像 FastV 那样前两层全看，则是 12.10；
  - 其余三组：FastV 算得 9.31 / 7.66 / 6.04（表中 9.31 / 7.66 / 6.03），ShaRP 算得 9.33 / 7.68 / 6.08（表中同上），相差不超过 0.05（复核时改正：原写 ShaRP 第三组 6.07、“相差不超过 0.04”；第二人用同一公式复算 14.1% 一档为 6.076，与表中 6.03 差 0.05；R 只有三位有效数字，末位可能有 ±0.01 的出入）；
  - DyCoke 在 LLM 之前合并，25% 时 28 层都是 1568 个 = 8.71，表中 8.7。
  - 结论（AI）：ShaRP 的 R 是“第 0 层看全部、第 1 层起每层留的比例”，即 FastV 的 K = 1；表中的 TFLOPs 是理论值，不含去偏那次推理和 RegD 的计算。只核了 LLaVA-OneVision；其他三个模型的 token 数全文没写，没有核。
- **换成层平均（AI）**：按 28 层平均，ShaRP 四组约为 30.8% / 26.2% / 21.7% / 17.2%，FastV 约为 30.4% / 25.7% / 21.1% / 16.4%，与 FrameFusion 的等效 R（31% / 26% / 21% / 16%）都很接近。所以 Table 1 的分组按“层平均保留比例”也大致对齐，只是 R 这一列混用了“剪后比例”和“平均比例”两种口径。
- **Table 3 的“20%/12.4%”“15%/7.5%”**：正文没有定义（UN）。（AI）按同样的公式，VisionZip + ShaRP 一行读作“进 LLM 时留 20%、第 1 层起为原来的 12.4%”正好约 4.3 TFLOPs；HoliTom 两行按同样的读法只有约 2.6，读法不明。
- **CLS 与合并 token**：全文没有提到 CLS（UN）。RegD 把相似的未选中 token 并进选中 token、把相邻重复的选中 token 合并，再按预设个数补足（p.9–10），所以被并进去的 token 不另计数，留下的个数等于预设值（AI，由 p.10 保持预设个数的说法推出）。合并的具体算法与保留 token 的位置编号，没写（UN）。
- **时延的口径**：Table 4 是 A40 上实测的 prefill 时间（到第一个 token）与 generate 时间（生成整个回答）（p.12–13）；样本数、batch、用哪个 benchmark、是否含去偏那次推理，没写（UN）。
- **与本项目口径的对应（AI）**：
  - 本项目“层平均 64”按 ShaRP 的口径相当于 K = 1、R = 47/576 ≈ 8.2%，层平均 11.1%，比 ShaRP 测过的最低一组（层平均约 17%）压得更狠；128（22.2%）约等于 ShaRP 的 7.66 TFLOPs 组，192（33.3%）略高于 11 TFLOPs 组。
  - 按 FastV 的公式和 LLaVA-1.5-7B 的配置（d = 4096、前馈层宽 11008、32 层；外部知识）算，本项目三种 64 档（LLM 之前 64 个、K = 1 留 47 个、K = 2 留 30 个）的视觉 token FLOPs 约为 0.3232、0.3230、0.3284 TFLOPs，相差不到 2%。所以本项目的层平均口径与 ShaRP 的按 TFLOPs 对齐基本等价。

## 限制与替代解释

- **只在视频上**：所有结论来自视频问答。（AI）视频帧之间冗余大，6272 个 token 留 14% 仍有约 880 个；本项目单图 576 个留 47 个（8.2%），难度不同。单图时 SegM 只有一段，不起作用（E-SH-22）。去偏与去重补足在图像上是否有效，全文没有证据（UN）。
- **R 这一列混了两种口径**：ShaRP、FastV、Feather 是剪后各层留下的比例，FrameFusion 是平均比例（p.11）。同 TFLOPs 下 ShaRP 的 R 比 FastV 高，是因为它少算了一层全量（第 0 层全看，对比 FastV 前两层全看），不是“多留了 token 而不多花算力”（E-SH-9，AI）。
- **增益来源没有完全拆开**：ShaRP 对 FastV 的优势同时包含“提前一层剪、多留 token”和三个模块。交叉读表看，未去偏的第一层剪枝（55.8）不如 FastV（56.6），所以优势主要来自模块，尤其是去偏（E-SH-15，AI）。没有“把模块用在 K = 2”的对照，也就不知道提前到第一层本身是否必要（UN）。
- **消融不全**：缺只用 SegM、只用 RegD 的行；RegD 的预过滤、去重、补足三步没有分开。其中“把相似的未选中 token 并进选中 token”本身就给保留的 token 加了信息（类似合并），可能是 RegD 增益的一部分（AI）；只有一个模型、一个比例（p.14）。
- **超参数**：三个超参数按经验定，没说用什么数据（p.12）；（AI）如果就在这四个 benchmark 上调的，结果会偏乐观。另外三个阈值没给（UN）。
- **对照的设置**：PDrop 为了对齐算力被压到很低的比例（6.03 TFLOPs 时 1.5%），作者自己也说这样会掉分（p.12）；DyCoke、STTM 的 TFLOPs 与组内不同（8.7、10.5，p.10）；FrameFusion 没给 TFLOPs（p.10–11）。HoliTom 这样更强的方法只在 Table 3 里作底座出现，而它单独在 4.3 TFLOPs 下已高于 ShaRP 单独在 9.31 TFLOPs 的结果（AI，口径未核）。
- **开销**：TFLOPs 是只算视频 token 的理论值（p.10），按 E-SH-9 的推算，不含去偏的那次推理、段内掩码和 RegD 的相似度计算（AI）；时延是否包含这些，没写（UN）。剪枝那一层要算显式的注意力分数（作者只说之后的层兼容 FlashAttention，p.9）。
- **机制证据**：三个因素主要靠可视化（Fig. 2、4、6）和一句定量（p.3）；“去偏后浅层注意力对准与题目相关的区域”没有定量检验，例如换题目后选出的 token 变了多少（AI）。
- **统计**：单次、无区间（全文未见）；方法之间的差多在 0.3～1.5 分（AI）。
- **表与摘要的小出入**：E-SH-19、E-SH-20。
- **作者自述的局限**：全文未见。全文没有局限一节，结论（p.14–15）只总结方法与结果。

### 与路由、K = 1、覆盖、DivPrune 底座的关系（AI）

1. **句式路由（IDEA-0003）**：ShaRP 对所有题用同一流程，题目只通过最后一个文本 token 的注意力进入排序（p.8–9），没有题型，也没有按题型的结果。它既不是路由的先例，也提供不了“哪类题该按题目选 token”的证据。Fig. 4 的例子问帽子颜色（p.8），正是本项目路由交给强对照的开放题；ShaRP 对这类题只有 Fig. 4 和 Fig. 6（p.13，问徽章上的动物）两处个例，没有这类题的数字（复核时改正：原写“只有这一张图”，Fig. 6 左侧也有一道问具体对象的例题）。本项目把题目信号放在输入层，理由是浅层注意力几乎不随题目变化（CL-1）、把 IDF 权重放在注意力上无效（CL-5）；ShaRP 则认为去偏后的浅层注意力会对准题目相关的区域，但只有定性图。两边设置不同（视频、Qwen2 系语言模型、黑图相减），不能直接说矛盾；CL-1 是否在去位置之后测的，本笔记没有核对。
2. **K = 1**：ShaRP 在第一个解码层剪，按 TFLOPs 推算是第 0 层看全部、第 1 层起少留（E-SH-9），与本项目的 K = 1 相同；它与 FastV（K = 2）在同 TFLOPs 下比较（Table 1），与本项目在同一层平均下比较 K = 1 与 K = 2 是同一种做法（两种口径相差不到 2%，见「预算口径」）。但方向不同：本项目 K = 1 路由比 K = 2 路由在确认集上高 +2.87 / +1.33（CL-11）；ShaRP 的视频数据里，未去偏的第一层剪枝（55.8）比 FastV 的第 2 层剪枝（56.6）低（E-SH-15）。可能的原因（未检验）：视频 6272 个 token 的位置偏差更重（作者说 FastV 留下的多来自序列末尾，p.3）；本项目的 K = 1 用的是去位置 + 分块的 A，不是原始注意力。所以 CL-11 应写成“本项目的设置与打分方式下的事实”，不要推广。
3. **覆盖 16**：本项目把不路由题的 16 个名额挪进题目查询定位的框里（F69 的配置）。ShaRP 没有按题目定位的区域；最接近的是 RegD 的补足，从未选中的 token 里按多样性挑，不看题目（p.10）。没有重叠，也没有可借的证据。
4. **DivPrune 底座（DEC-0061）**：ShaRP 只在 p.2（编号）和相关工作（p.4）里提到 DivPrune（复核时改正：原写只有 p.4），没有与它比，也没有图像结果，所以不能说明两者谁强。与本项目 F72～F74 的关系：
   - 本项目把同一种多样性选择放到 K = 1（第 0 层看 576 个、第 1 层起留同一顺序的前 47 个，见 EXP-0032 计划），没有平均的帮助（−1.51 / +0.88）。ShaRP Table 3 的“VisionZip 先留 20%、第 1 层起再按去偏注意力 + 去重剪到 12.4%”，同 TFLOPs 比只用 VisionZip 留 12.8% 高 1.8（视频）。两者不矛盾：本项目的 K = 1 变体只改了放置，留哪些 token 与 LLM 之前的选择相同，没有用到第 0 层算出的任何信息；ShaRP 的第二段用了第 0 层的注意力并做了去重，放置与选择一起改了。所以 ShaRP 的结果不能当作“第 0 层多看本身有用”的证据。
   - ShaRP 的 RegD 是“先按重要性选、再去重、补多样性”。本项目 K = 1 时多样性选择比 CLS 排序高约 2；ShaRP 的 RegD 在去偏之上再加 0.5（Table 5）。方向一致：预算小时，选中的 token 彼此不要太像（设置不同，只是旁证）。
   - ShaRP 把 DivPrune 归为只看视觉相似度的一类，并主张按题目注意力的方法能聚焦与题目相关的内容（归类见 p.2、p.4；主张见 p.2、p.5 §2.2，SC；复核时改正：原写“p.2、p.4”，p.4 没有找到“聚焦题目相关内容”的说法，p.5 §2.2 有“保留与任务相关的信息”）。这可以作为“在 DivPrune 底座上为被路由的题加题目相关名额”的一条文献理由，但它本身没有与 DivPrune 比较的证据。

### 新颖性威胁（AI）

- **句式路由、题目定位的覆盖**：没有威胁。ShaRP 不分题型，也没有按题目定位的区域（p.8–10）。
- **K = 1 的放置**：ShaRP 已经在第一个解码层剪（视频），本项目也已不把 K = 1 当贡献（CL-11），这一点只需引用。ShaRP 没有报告“同一打分下 K = 1 对 K = 2”的比较，所以 CL-11 的比较本身不是 ShaRP 做过的；但它仍只能作为预算计法的事实，不能写成新发现。
- **用内容为空的输入估位置偏差**：ShaRP（全黑视频、相减）与 FEATHER 都是先例；本项目 A 的去位置（纯灰图、相除）已不作贡献（CL-2）。
- **下一轮若在 DivPrune 底座上做“合并未保留的 token”或“LLM 外先多留、第 1 层再剪”的两段式**：ShaRP 的 RegD 与 Table 3、VScan 都是相近工作，新颖性低，只能当工程改进或对照。
- **总体**：ShaRP 没有做本项目想做的事（图像上按题型分流、题目定位、DivPrune 底座上的路由）。它主要影响 K = 1 与去偏两处的措辞。

### 能借鉴什么（AI，都未检验）

1. **吸收式合并（RegD 的第一步）**：在 DivPrune-64（或 K = 1 的 47 个）选出之后，把与某个保留 token 很像的未保留 token 并进与它最像的保留 token，个数不变。对应本项目的说法：K = 1 的 47 个缺少 VisionZip 那 10 个合并而成的上下文 token（F62、M17）。代价小（不加 token，可先在 CPU 上看会并进多少）。合并怎么做 ShaRP 没写（UN），要自己定；本项目在 VisionZip 上发现过合并后幅值变大的问题（[改进内容](../专题分析/所有论文在baseline骨架的改进内容.md)的 baseline 选择表），要先处理。新颖性低（VisionZip 的上下文 token、ShaRP 的 RegD 都是合并）。
2. **两段式（同一层平均）**：LLM 之前 DivPrune 留 m 个，第 1 层起再按某种信号留 n 个，满足 (m + 31n) / 32 = 64，例如 m = 95、n = 63，或 m = 126、n = 62。ShaRP Table 3 在视频上是正例。第二段的信号按 CL-1、CL-5 不宜用浅层注意力，可以用路由下的题目查询。新颖性低（VScan、ShaRP Table 3）。
3. **去偏的另一种算法**：ShaRP 是减去 λ 倍的黑图注意力，本项目 A 是除以灰图上的平均分数（EXP-0008）。只在需要回答“为什么用相除”时补一个对照。
4. **一个诊断**：本项目 K = 1 时，去位置之后的第 0 层注意力是否随题目变化（同一张图换题目，看保留集合的 Jaccard，沿用 EXP-0006 的做法）。既可回应 ShaRP 的定性说法，也决定两段式的第二段能不能用注意力。
5. **预算的写法**：ShaRP 只说 TFLOPs 的细节在补充材料，读者无法核对；本项目论文里可以写出 FastV 的公式和 token 数，以及“层平均与 FLOPs 对齐相差不到 2%”的计算。
