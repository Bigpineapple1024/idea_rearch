## 研究问题

剪得很狠（例如只留 64 个）时，怎样在固定的视觉 token 预算里，同时留住题目需要的局部证据和补充的全局上下文，并让两者的比例随输入变化？（p.1 摘要；p.2 §1）

作者的出发点：按注意力剪，偏向显著区域；按相似度剪，偏向全局覆盖；两者结合的方法在高压缩下仍难兼顾（p.2；p.3–4 §2）。

## 方法与贡献

FSR 作用在视觉编码器输出的 N 个视觉 token 上，从中定出 K 个交给 LLM（p.4 §3.1）。分三步。

- **第一步 Focus：选局部证据（p.4–5 §3.2）**
  - 显著性 s_i：视觉编码器“某个选定层”里 [CLS] 对各 token 的注意力；注意力图写作 A ∈ R^{H×(N+1)×(N+1)}，H 是头数。用哪一层没写；各头怎么汇总在公式里，读不到（UN）。
  - 题目相关性 r_i：用预训练的 CLIP 文本编码器把题目 q 编成向量 t，r_i 是视觉 token 与 t 的余弦；写明沿用 CDPruner（Zhang et al. 2025b）。视觉一侧用哪层特征、是否先投到 CLIP 的图文共同空间，没写；题目是否连选项一起编码、超过 CLIP 文本长度上限时怎么办，也没写（UN）。
  - 两个分数各自归一化到 [0, 1]（怎么归一化没写；CDPruner 原文用的是最小—最大归一化，AI）。融合分数 ϕ_i = r̂_i^α · ŝ_i^β（p.12 正文），默认 α = 3、β = 1（p.7）：相关性取三次方，再乘显著性。p.5 只说 α、β 调节两者的权衡。
  - 名额 K_F：按 ϕ 从大到小排，取“累计达到总量 Z = Σϕ_i 的 ρ 倍”所需的最少个数，ρ 默认 0.9；这 K_F 个记作 F（p.5）。所以 K_F 随样本变化。K_F ≥ K 时怎么办，没写（UN）。
- **第二步 Scan：补全局上下文（p.5–6 §3.3.1）**：作者叫它条件上下文采样（CCS）。K_S = K − K_F。从 A = F 出发，每次把与 A 差别最大的 token 加进来，重复 K_S 次，S = A \ F。作者说这是把 F 当作固定初始中心的最远点采样，距离 d = 1 − cos（p.6 §3.3.2）。“特征空间”指哪层特征没写（AI：按 §3.1 的记号，应是编码器输出）。
- **覆盖保证（p.6 §3.3.2，SC）**：引贪心 k-center 的经典结果（Hochbaum & Shmoys 1985），说 F ∪ S 的覆盖半径（每个没选的 token 到最近的已选 token 的距离的最大值）有界，并说 CCS “接近全局最优”。式子读不到，常数未知（UN）；对这一说法的意见见 E-FS-17。
- **第三步 Refine：合并（p.6 §3.4）**：F 保持不变。每个被丢的 token 找 S 里最相似的锚点；只取相似度最高的 M = κ|S| 个（κ 默认 1）；把它们按 ϕ_i 加权并入各自的锚点，锚点自己的初始权重是 ϕ_j。最后 Ṽ = F ∪ S，正好 K 个。
- **在哪里剪**：视觉编码器之后、进 LLM 之前，一次定下（AI：§3.1 把 V 定义为编码器输出；Fig. 4（p.5）的流程是编码器 → 三步 → LLM；全文没有在 LLM 层内剪的步骤）。在投影层之前还是之后，没写（UN）。
- **是否免训练**：是。“fully training-free, plug-and-play … without modifying any model weights”（p.7）；贡献 1 也这样写（p.2）。
- **是否用题目文字**：LLaVA-1.5、LLaVA-NeXT 上用（CLIP 文本编码器，p.5）。Qwen2.5-VL 上不用：Focus 改用视觉 token 自注意力图的汇总，题目项去掉，理由是没有文本编码器（p.9 §4.2.3）。视频模型上怎么做，没写（UN）。
- **默认超参数**：α = 3、β = 1、ρ = 0.9、κ = 1（p.7）。α、β、κ 有消融（p.11–12，Fig. 5），ρ 没有（DE：消融只写了这三项）。超参数在哪套数据上定的，没写（UN）。
- **作者列出的贡献（p.2，SC）**：
  1. 受人类视觉启发、免训练的 FSR，在固定预算内按输入动态分配局部证据和全局上下文，而不是用固定的局部/全局规则；
  2. 一套完整流程：双路打分（局部证据）、条件采样（全局上下文）、聚合模块（补纹理）；
  3. 大量实验表明 FSR 一致优于已有剪枝方法，提升来自更好地平衡局部与全局。
- **动机**：人答视觉问题时先聚焦、再扫视、再把周边信息汇总（p.2；p.4 §3.1，Fig. 3）。这是类比，论文没有检验（AI）。

## 预算口径

- **“保留 N 个”指什么**：Table 1、5 写 “Retain 192 / 128 / 64 Tokens (↓ 66.7% / 77.8% / 88.9%)”（p.7、p.11）。FSR 的 K 是交给 LLM 的视觉 token 个数（p.4 §3.1；p.6 §3.4）。FSR 在进 LLM 之前一次定下，LLM 每层看到的都是 K 个，所以按本项目的口径，层平均也是 K（AI）。论文没有用“层平均”的说法。
- **CLS**：满额写作 “All 576 Tokens”（p.7），即 24 × 24 个 patch，不含 CLS；CLS 只用来打分，不送进 LLM（AI，与 LLaVA-1.5 的输入一致；§3.2 的注意力图是 N + 1 维，选择的集合 V 是 N 个）。
- **合并 token**：合并后的锚点各算 1 个，合并不增加个数（p.6 §3.4：“without increasing the token budget”；“exactly K_F + K_S = K tokens”）。
- **与 FastV 一族怎么对齐**：FastV、SparseVLM、DART 在表里也写“保留 64 个”，但它们在哪层剪、剪后留几个、怎样与 LLM 之前剪的方法对齐，全文没写（UN）。
  - Table 7 里同为“64”，FastV 的 FLOPs 是 3.610 T，FSR 是 2.291 T，多 58%（p.12）。所以 FastV 的“64”不是按计算量对齐的（AI）。
  - 按“FLOPs 与层平均视觉 token 数成直线关系”插值（576 个 ↔ 9.042 T，64 个 ↔ 2.291 T；常数项不影响结果），FastV 的 3.610 T 约合层平均 164 个（AI，粗估）。这既不是 64，也不是“第 2 层后留 64 个”时的 96 个。
  - 可 FastV 的 KV cache 是 32.1 MB，与每层 64 个（32.0 MB）相当。两列对不上，FastV 的设置和测法不明（UN）。
- **FLOPs、时延的口径（Table 7，p.12；p.10 §4.3）**：LLaVA-1.5-7B，保留 64 个，单张 RTX 3090。列有 FLOPs（T）、MACs（T）、Prefill 与 Decode（单位写 ms/token）、KV cache（MB）、显存（GB）、Score（MMB-EN 准确率）。MACs 约为 FLOPs 的一半（DE）。
  - 没写：是否计入视觉编码器和 CLIP 文本编码器、文字 token 取多长、按多少样本平均、测了几次（UN）。
  - KV cache 满额 288.0 MB = 576 × 0.5 MB，正好是 32 层 × 4096 维 × K、V 两份 × 半精度，只算视觉 token（AI）。
  - Prefill 的 “ms/token” 是怎么除的不清楚（UN）；“预填充 3.9 倍”等于 3.056 / 0.788（AI 复算）。
- **其他模型**：LLaVA-NeXT 固定 672×672 输入，2880 个，保留 960 / 640 / 320（p.8，写明沿用 CDPruner 的设置）。Qwen2.5-VL 与视频只给削减比例（p.9–10）。LLaVA-NeXT 的多块子图是分块剪还是合起来剪，没写（UN）。

## 限制与替代解释

- **对照来自不同来源（AI，E-FS-15）**：多数格子与 CDPruner 原文相同，MME 与 VisionZip 原文相同，FastV-128 一行拼了两种设置。p.7 说统一了 prompt、后处理和指标，对引用来的格子无法保证。FSR 与对照之间 1 分以内的差别，可能来自流程不同。
- **“一致优于”只在 Avg 上成立（AI，E-FS-9、E-FS-16）**：64 档九列里 FSR 单独最好的只有两列；GQA、POPE 上几乎每档都是 CDPruner 更高。FSR 一贯更高的是 TextVQA、MMVet。这种整齐的分列也可能部分来自评测流程（CDPruner 的格子多半引自其原文，只有它自己那一行像是重跑的），不全是方法差别。
- **Avg 不可复算，又被 MMVet 拉动（AI，E-FS-18）**：去掉 MMVet，64 档 FSR 与 CDPruner 的 Avg 相差在 ±0.2 个百分点以内；改用 CDPruner 原文自报的 MMVet，64、128 档的 Avg 差别缩小到 0.4 个百分点以内。FSR 的 MMVet 在 128 档比不剪还高 3.2，说明这一列噪声大。
- **没有不确定性、可能在评测集上调参（AI）**：没有方差、区间、重复；超参数看起来就在评测基准上定。0.3～0.4 个百分点的 Avg 差别在这种条件下不算可靠的提升。
- **覆盖保证说得过满（AI，E-FS-17）**：
  - 1 − cos 不满足三角不等式（例：两两夹角 60° 的三个单位向量，0.5 + 0.5 < 1.5），经典 k-center 的 2 倍界不能直接套用。改用单位向量的欧氏距离（与 1 − cos 单调对应，最远点采样选出的点相同），2 倍界成立；换回 1 − cos 是 4 倍。
  - 界是相对“F 固定时再加 K_S 个点的最优解”，不是所有 K 个子集里的全局最优；p.6 的 “near globally optimal” 说过了。
  - 特征空间的覆盖半径与答题准确率没有直接关系。
  - 论文的式子读不到，也许它已按别的距离写，待对照 PDF。
- **Focus 选到的是什么，没检验（AI）**：CLIP 的 CLS 注意力常常集中在少数几个 token 上（VisionZip 称为主导 token；本项目 IDEA-0007 用的就是这种分数）。乘上 r̂³ 之后，ϕ 的总量可能大半落在很少几个 token 上，这也能解释为什么 ρ = 0.9 时 Fig. 1 只有 9～15 个 Focus。若如此，Focus 主要是“显著、且与题目有点相关”的少数 token，不一定是题目问到的局部证据。论文只有 Fig. 1、Fig. 2 的例子。
- **题目项的作用没有分开检验（AI）**：Qwen2.5-VL 上没有题目项，FSR 仍高于 HoloV（p.9–10），那里的收益来自别的部分。LLaVA 上题目项的作用只体现在 Fig. 5 的“只用显著性”一档，数值读不到；“只用相关性”一档又改了指数。
- **FastV 对照不代表按层平均对齐的 FastV（AI）**：FSR 表中 FastV-64 的 GQA 46.0、POPE 35.5，设置不明（E-FS-11）。本项目同一层平均预算下的 FastV 一族强对照 A，在 GQA testdev 上与 VisionZip-64 只差 −0.58（[EXP-0022](../实验报告/EXP-0022_record.md)）。不能用 FSR 的表推断“FastV 一族远弱于 LLM 之前的方法”。
- **效率口径窄**：只在 64 档、一个模型、一张卡上测；FastV 的 FLOPs 与 KV 自相矛盾（E-FS-11）；CLIP 文本编码器的开销没有单列；时延没有重复测量。
- **划分与指标没写（UN）**：绝对数字不能直接和本项目的本地子集比。GQA 上 VisionZip-64 两边接近（表中 55.1，本项目 testdev 55.18，EXP-0022），是目前唯一的锚。
- **动机只是类比（AI）**：人类视觉的三阶段只是启发，没有实验把它和方法联系起来。

### 四个对象逐一看（AI）

- **路由**：FSR 不路由，对所有题一样处理；它的“动态”只是 K_F 随分数分布变化（p.5）。Fig. 1 里存在题反而只分到 9 个 Focus（p.2），这只是例子，和本项目“存在题、计数题最该按题目选”的证据不冲突，也不支持。FSR 全文没有题型分析（E-FS-14）。对本项目的路由没有新颖性威胁，但审稿人可能把 FSR 的“按样本自动分配”当作路由的替代方案，需要正面比较。
- **K = 1**：FSR 只在 LLM 之前剪，与 K 无关。它表中的 FastV 设置不明，不能用来支持或反驳本项目的 K = 1 结论。
- **覆盖 16**：两者都把一部分预算专门给“题目相关的地方”。FSR 是逐 token、名额随样本变，后面用多样性补；本项目是画方框、固定挪 16 个，框内外按底座自己的规则取。本项目在 VisionZip 上的覆盖没有成立（CL-14），而 VisionZip 的底分是显著性（主导 token）；FSR 是在多样性上补。所以“逐 token 的题目相关 + 多样性底座”这条路，本项目的负结果没有覆盖到。
- **DivPrune 底座**：FSR 的 Scan 就是以 Focus 集为种子的 DivPrune 式最远点采样；FSR 在相关工作里也把 DivPrune 写成 max-min 多样性选择（p.3）。表中 FSR − DivPrune 在 64 档为 GQA +0.7、VQAv2 +1.3、POPE +0.2；CDPruner − DivPrune 为 +1.1、+1.3、+2.0。可以当作“在多样性底座上加题目相关性”的文献先验：大约 1 分（各行可能来自不同流程）。

### 重叠与新颖性威胁（AI）

1. **“题目相关 + 多样性”的组合已经有人做了**。FSR 等于“用题目相关 × 显著性挑少数种子，再从种子出发做 DivPrune 式的最远点采样，最后合并”；CDPruner 更早，FSR 写明沿用它的相关性算法（p.5）。所以下一轮如果在 DivPrune-64 上加“题目相关的名额”（DEC-0061 的自然下一步），最接近的前人工作就是 FSR 和 CDPruner，不能写成“首次把题目相关性与多样性结合”。这是 FSR 对本项目最大的威胁：它没做本项目已经做成的事，却已经做了本项目下一轮最可能做的事。
2. **按样本动态分配局部、全局名额**：FSR 是“按题目、按样本分配预算”的先例，但是逐 token 的，不画框。区域级的先例更像 HoloV（FSR 把它描述为按分区分配，p.4；HoloV 原文本笔记未读）、F³A、CROP。
3. **合并**：Refine 是本项目后备方向“上下文合并”（DEC-0040）的直接先例；VisionZip 的上下文 token 合并也是。
4. **在 LLM 之前用题目文字选 token** 本身不新：FSR、CDPruner 用 CLIP 文本编码器（TRIM 也是，据 CDPruner 原文附录的介绍）；F³A 在输入 embedding 上做过（IDEA-0005 的查新）。
5. **没有威胁的部分**：按句式路由；按答案类型的证据（何时该按题目词选 token）；FastV 的 K = 1；本项目的负结果（放大、VisionZip 上的覆盖、CLS 排序）。

### 可辩护的差别（AI，附理由）

1. **路由与按题型的证据**：FSR 对所有题一样处理，动态分配的证据只有两个例子（p.2、p.5）。本项目有“题目查询对 yes/no、计数有利，对点名物体的开放题有害”的预注册证据（CL-7、CL-8）。理由：这正是 FSR 缺的“什么题该多给题目相关的名额”。
2. **不加模型**：FSR 要 CLIP 文本编码器（p.5），本项目只用 LLM 自己的输入 embedding。限制：两种题目相关性本项目没有在同一底座上比过（UN）。
3. **对齐和对照更干净**：FSR 表里 FastV 一族的设置不明（E-FS-11），对照多半是引用（E-FS-15）；本项目在同一流程里跑，按层平均对齐，有区间。这是方法学上的区别，不是方法贡献。
4. **本项目的弱点**：FSR 报告的 64 档数字高于本项目已确认的最好结果（GQA 58.2 对 57.22）；本项目只有一个模型，FSR 有五个图像模型和视频。

1. **“按句式播种”的三臂对照**：在 DivPrune-64 上比较 (a) 原样 DivPrune；(b) 每道题都先放题目查询最相似的若干个作种子，再做 max-min（FSR 式，但种子用本项目的输入层查询，不用 CLIP）；(c) 只对被路由的题播种（本项目式）。(c) 显著好于 (b)，才能说路由在多样性底座上有用；否则贡献只能落在“不加模型的题目查询”上。改动只在 DivPrune 的初始集合（即 FSR 的 CCS，p.5–6）。需要 GPU 运行，按 paper-plan 的预算。
