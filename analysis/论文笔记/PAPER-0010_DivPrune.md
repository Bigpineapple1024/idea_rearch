## 研究问题

不训练、不用校准数据，只留下很少的视觉 token 时，怎样选才能让留下的 token 仍然代表整张图？作者认为按注意力选会留下彼此相似的 token，剪得越多越吃亏，于是改为选“彼此最不相似”的一组（p.1 摘要；p.2 §1、§2.3）。

## 方法与贡献

- **问题怎么写**（p.3 §3.2–3.3）：从 M 个视觉 token 中选 M̃ 个，目标是剪枝前后模型输出的差别最小（式 2）。作者把它换成“最大-最小多样性问题”（MMDP）：在所有 M̃ 个的组合中，挑“组内最近的两个 token 之间的距离”最大的那一组（式 3）；距离用余弦距离（式 4）。式 2～4 本身在解析全文里看不到（UN）。
- **用什么特征、在哪一层**（DE）：视觉编码器的特征经投影层变成 M 个视觉 token，记为 E_v（p.3 §3.1）；Algorithm 1 直接在 E_v 上算（p.4）；作者说 LLaVA-1.5 的视觉 token 是 4096 维（p.5 §4.2）。所以默认用的是投影层输出，在送进第一个解码层之前剪，作者称 Layer 0（p.8 §4.6）。
- **每一步怎么算**（Algorithm 1，p.4）：
  1. 已选列表为空；候选集 = 全部视觉 token。
  2. 第一个：对每个候选，求它到其他候选的最小距离（最近邻的距离），取这个值最大的那个（“最近邻最远”），移入已选列表。
  3. 之后每一轮：对每个剩下的候选，求它到已选各 token 的最小距离，取这个值最大的那个移入；直到选满 M̃ 个。
  4. 开始时用一次矩阵乘法算好距离矩阵，后面不再重算（p.4）。
  5. 没选中的视觉 token 丢掉；选中的与文本 token 一起送进 LLM（p.4）。
  - 并列时取哪个、用什么数值精度：全文未写（UN）。
- **在 LLM 之内的用法**（DE）：也可以对某个解码层输出的、视觉 token 对应的隐藏状态做同样的选择，再送进后面的层（p.4 §3.3 末）。Table 3 的 Layer 1～3 是这种用法（p.8）；每行用哪一层的输出，没有逐行写（UN）。
- **免训练**（DE）：不训练、不需要校准集，即插即用（p.2）。
- **是否用题目文字**（DE）：不用。Algorithm 1 的输入只有 M̃ 和视觉 token（p.4）。[AI] LLaVA 常用的模板把图像放在题目前面，因果注意力下视觉 token 的隐藏状态看不到题目，所以 LLM 之内的变体实际上也与题目无关（全文没讨论）。
- **“精确解”**（SC，p.4）：解析全文写“we obtain exact solution for the problem”，又说两种用法都得到所选 token 的最高多样性。[AI] Algorithm 1 是每次加一个的贪心，一般不保证这类问题的最优解（常见的结论是：距离满足三角不等式时，贪心结果不差于最优值的一半）；这句可能是原文措辞或解析的问题，需要对照 PDF p.4。
- **作者列出的贡献**（SC，p.2）：① 把剪枝写成 MMDP，最大化所选 token 的多样性、减少冗余；② 免训练、免校准数据、即插即用；③ 在 16 个图像与视频数据集上评测，剪 80% 以上时提升明显；④ 降低显存与时延，同时在多数数据集上与原模型相当。p.2 还说适用于任何 LLM 结构和视觉编码器、兼容 KV 缓存（SC）；实验中的模型都用 CLIP 编码器（p.4）。

## 研究设计

- **模型**（p.4 §4.1）：LLaVA 1.5-7B、LLaVA 1.5-13B、LLaVA 1.6-7B（LLaVA-NeXT）、LLaVA-NeXT-Video-7B（脚注为 DPO 版）。视觉 token：LLaVA 1.5 为 576 个；LLaVA 1.6 随切块变化，是 1.5 的 3～5 倍；视频模型每帧 144 个，取 8 帧共 1152 个（p.4）。

- **对照**（p.4 §4.1）：即插即用的 FastV、PruMerge、VTW（VTW 默认要用校准集选层；作者在需要时关掉校准，按算力选层）；另比一个用校准集的 FitPrune、一个要微调的 M³；Table 1 还有微调的 PruMerge-LoRA（p.6）。**全文没有 VisionZip 和 SparseVLM**，参考文献（p.15–17）里也没有。

## 预算口径

- **“保留 N 个”指什么**：全文不用“保留多少个”，而用剪枝比例和 TFLOP 比例。主表的 DivPrune 剪 90.2%（p.12），576 × 9.8% ≈ 56.4 个（AI）；Table 1、Table 5 中 DivPrune 与 M³（S = 56）的 TFLOPs 完全相同（0.512、0.416，p.6、p.9），推断进 LLM 的是 56 个（AI）。因为在第一个解码层之前剪，32 层每层看到的都是这 56 个，所以“进 LLM 的个数”就等于本项目的层平均个数（AI）。LLaVA 1.6 与视频模型用同样的剪枝比例（p.7），视频约 1152 × 9.8% ≈ 113 个（AI）。
- **CLS、合并 token**：全文没有提 CLS（DE）。[AI] LLaVA-1.5 的 576 个视觉 token 是 24 × 24 的 patch，不含 CLS，所以候选里本来就没有 CLS。DivPrune 不合并，没选中的直接丢掉（p.4）。会合并的 PruMerge 不能固定比例，作者让 DivPrune 按 PruMerge 的比例来选（Ours\*），TFLOP 一栏写 Variable（p.6）；合并后的 token 怎么计数，没写（UN）。
- **TFLOPs 怎么算**（p.5）：按 FastV [4] 的公式估计（式子看不到），变量是解码层数 T、剪枝前后的序列长度 µ = N + M 与 µ̃ = N + M̃（N 为文本 token 数）、隐藏维 d、前馈中间维 m；报告的是剪枝后 / 不剪枝的比例。[AI] 从变量看只算 LLM 的解码层，不算视觉编码器、投影层和 DivPrune 自己的选择。各方法按目标比例调超参；不能细调的方法取“刚超过目标的最小比例”，作者说这可能让对照略占便宜（p.5）；PruMerge 的可变比例按每个数据集的平均序列长度折算（p.6）。
- **与 FastV 一族怎么对齐**（DE + AI）：按 TFLOPs 对齐，FastV 用 K = 3（p.12）。[AI] 按 FastV 的公式反推（32 层、隐藏维 4096、前馈维 11008；后两者是 LLaVA-1.5-7B 的结构，全文只写了 4096）：原模型 3.228 TFLOPs 约对应 621 个 token（576 个视觉 + 约 45 个文本）；DivPrune 的 0.512 约对应每层 101 个（视觉约 56 个）；FastV 的 0.514 意味着前 3 层看全部、第 3 层之后视觉 token 只剩约 1 个，正好是 R = 0.001 × 576 ≈ 0.6；13B（40 层）上同样反推为第 3 层后约 13 个，正好是 0.023 × 576。所以这里的 R 是保留比例（与 FastV 原文“剪掉 R%”的意思相反），7B 表里的 FastV 实际是“前 3 层看图、之后几乎不看”，和 VTW（第 4 层后撤掉全部视觉 token）几乎一样，两者的分数也几乎一样（GQA 38.73 对 38.94，MMB 20.62 对 21.31，p.6 Table 1）。同样的算力下，FastV 若用 K = 1 或 K = 2，约可留 39 或 20 个，论文没有试。
- **TFLOPs 与层平均的关系**（AI）：在 LLaVA-1.5-7B 上，注意力的平方项很小（全长时约占 3%），所以“TFLOPs 相同”约等于“各层视觉 token 数的总和相同”，也就是本项目的层平均口径；前几层看全长的方法因平方项略吃亏（K = 3 时约少 2 个 token，K = 1 时不到 1 个）。比例的数值随文本长度变：同一组超参在 Table 1 写 15.63%、Table 3/4 写 19.61%、Table 5 写 13.29%（E-DP-14）。另外 Table 1 中 TFLOP 与比例本身对不上（0.512 / 3.228 = 15.86%，表中 15.63%），原因未写（UN）。
- **时延、显存**（DE）：只在 LLaVA-NeXT-Video-7B 上、用 VideoChatGPT 的 499 个样本测（p.8 §4.5；p.7 Table 2）。LLaVA-1.5 上没有时延或显存数字。
- **与本项目 64 / 128 / 192 档的对应**（AI）：表里只有一档（约 56 个），比本项目的 64 档少约 8 个；128、192 档没有表格数字。按上面反推的文本长度粗算，64 / 128 / 192 个约对应 TFLOP 比例 17% / 27% / 37%，都在 Fig. 1 的横轴范围（≤ 45%，p.7）内，但解析全文看不到曲线上的数（UN）。

### 本实现与论文的差别（逐项）

1. **第一个 token 的取法**：与论文一致（Algorithm 1 第 3–11 行）。并列时的取法论文没写。
2. **所用特征与层**：DivPrune-64 用投影层输出、在 LLM 之前选，与论文一致。K = 1 的变体（`fastv64k1_div`）在同样的投影层输出（LLM 的输入 embedding）上选，第 0 层看全部 576 个、第 1 层起留前 47 个；论文的 Layer 1 用解码层输出的隐藏状态（p.4），**这是一处差别**（本项目有意为之，为的是把放置与特征分开）。
3. **距离**：本实现 d = 1 − cos；论文写余弦距离，式子看不到。对结果没有影响（见核对表第 3 行，AI）。
4. **距离矩阵只算一次**：一致。
5. **保留的顺序与位置编号**：本实现按原来的 patch 顺序送入、位置编号连续；K = 1 变体保留原来的位置编号（同 FastV）。论文都没写；按 Algorithm 1 的字面，返回的是按选中先后排列的列表。**可能的差别**，影响未知（UN）：如果官方实现按选中先后送入，图像 token 的位置顺序会被打乱。
6. **填充区**：都不排除，与论文文字一致。[AI] 最大最小规则本身会压低填充区的个数：填充区的 patch 彼此很像，选中一个之后，其余的到已选集合的距离接近 0，很难再被选上；所以不排除填充区的影响可能很小。实际个数见 EXP-0032 的记录（本次导出中还没有结果）。
7. **CLS**：都不含（AI，见核对表第 9 行）。
8. **预算个数**：本实现 64 个（剪 88.9%），论文主表约 56 个（剪 90.2%），本实现多约 8 个。论文按 TFLOPs 对齐，本项目按层平均对齐，两者约等价（AI）。
9. **K = 1 变体的个数**：本实现 47 个（层平均 63.5）；论文 Layer 1 的个数没写，按同算力推算约 39 个（AI）。
10. **数值精度与官方代码的其他细节**：论文没写，代码未下载，未知（UN）。

## 限制与替代解释

- **FastV 对照的配置**：按 TFLOPs 对齐后，7B 上的 FastV 是 K = 3、第 3 层后约 1 个视觉 token（E-DP-10），与 VTW 几乎相同。[AI] “FastV 在高剪枝率下崩溃”在这张表里主要反映这个配置，不代表 FastV 用 K = 1 或 K = 2（同算力约留 39 或 20 个）时的水平；论文没有试别的 K。本项目 FastV 一族的最好配置（K = 1 路由）在 64 档与 VisionZip-64 持平或略好（F56）。
- **对照集偏窄**：没有 VisionZip、SparseVLM 等在 LLM 之前或之内的强方法（E-DP-7）。[AI] “state-of-the-art”只相对这几个对照。与 PruMerge 的比较（按它的比例，Ours\*）是表中最公平的一组，DivPrune 在 11 项中 10 项更高（p.6）。与微调的 M³ 比，作者说“相当或更好”（p.7），读表是 M³ 在 7B 上 11 项中 9 项更高（AI）。
- **机制证据有循环**：最小距离直方图比的是 DivPrune 直接优化的量（E-DP-17）；t-SNE 是个别样本的图。[AI] 它们说明“选得更分散”，不说明“更分散所以答得更好”。Table 4 中随机低 5.68 是更直接的证据，但只有一次抽样、四项平均。
- **放置消融混了三件事**：Table 3 中越晚剪，之后能留的越少（约 56 → 39 → 21 → 2～3 个，AI），所用特征也从投影层输出变成隐藏状态（p.4）。[AI] “Layer 0 最好”不能直接读成“多样性选择应该放在 LLM 之前”，也可能主要是个数少了。
- **只有一档预算有表**：约 56 个；其他比例只在 Fig. 1、Fig. 4 的曲线上（看不到数）。作者说在较高的 TFLOP 比例下各方法都接近原模型，FitPrune 略好（p.7）。[AI] 在 128、192 档，DivPrune 的优势可能变小。
- **统计**：单次、无区间、无种子（E-DP-18）。
- **评测设置不清**：VQAv2 的划分、TextVQA 是否给 OCR 词都没写；原模型的 TextVQA 46.08、VQAv2 76.65 低于常见报告（E-DP-12）。不同论文间的数不能直接比。
- **TFLOP 比例前后不一**：同一组结果写成 15.63% 或 19.61%（E-DP-14）；Table 1 中 TFLOP 与比例本身也对不上（见「预算口径」）。
- **通用性的主张超出实验**：作者说适用于任何 LLM 结构和视觉编码器（p.2），实验只有 CLIP 编码器的 LLaVA 系列（p.4）；“降低时延与显存”只在视频模型上测过（E-DP-16）。
- **“精确解”**：与贪心算法不符（E-DP-6），需对照 PDF。
- **对要看细节的题掉得多**：TextVQA 相对降 21.9%，描述、OKVQA、MME、SEEDB 降 10%～17%，而 POPE 不降（见上文的计算）。[AI] “铺开”的选法照顾整体，不一定保住某个小区域或文字；这与本项目“DivPrune-64 的增益主要在 yes/no、计数题”的方向一致。

全文没有局限一节（DE）。作者写到的例外只有：较高 TFLOP 比例下 FitPrune 略好（p.7）；按 PruMerge 比例时 SQA 不如 PruMerge（p.6）；TextVQA 上不如 M³ 与 PruMerge（p.10）；预填充比 FastV、VTW 慢约 6%～7%（p.8）。

### 和路由、K = 1、覆盖、DivPrune 底座的关系（AI）

1. **路由（IDEA-0003）**：DivPrune 完全不看题目，不是“按题目句式路由”的先例。但它会改变路由的余地：本项目测到 DivPrune-64 比 VisionZip-64 的增益主要在 yes/no、计数题，正是路由送去按题目选的题型；论文自己的表里，对放置和选法最敏感的也是 POPE 这类是非题（Table 3、4）。所以以 DivPrune 为底座时，被路由题上的提升空间可能变小。EXP-0033 的 X3（`div64_qroute`）正在检验，计划写的预测是“被路由的 yes/no 题上略高于 DivPrune-64、整体变化小”。论文表里掉得多的是要看细节的题（TextVQA 等），这可能是题目引导在 DivPrune 之上还有余地的地方；但本项目以前测到按题目词选在 VQAv2 的 other 题上有害（PAPER-0008 笔记引用的 64 档 A′+B+V − A：other −4.03），所以不能直接推出。
2. **K = 1**：论文的 Layer 1 就是本项目的 K = 1。论文同算力下 Layer 1 比 Layer 0 低 1.90、比 Layer 2 高 3.45（四项平均）；本项目 F51（FastV 一族 K = 1 比 K = 2 高 +3.31 / +1.15）方向相同，EXP-0032（多样性放到 K = 1，VQAv2 −1.51）在 VQAv2 上也与论文一致。共同的解释是：同样的层平均预算下，越晚开始剪，之后能留的越少。所以“同算力下比较在哪一层剪”已有人报告（对多样性选法），论文素材库中 F51 一条写的“按层平均预算比较 K = 1 与 K = 2 是否已有人报告未查清”有了部分答案；论文没有改 FastV 的 K。
3. **覆盖 16**：DivPrune 的“铺开”在特征空间里，不涉及空间位置，也不看题目；本项目的覆盖 16 是在题目定位的框里按空间铺开。不构成威胁。定位后覆盖在 VisionZip 上不成立（IDEA-0006），在 DivPrune 底座上还没测。若要试，DivPrune 的第二阶段可以“以给定的几个为起点接着选”（EXP-0033 的 combo.py 已有这种写法），把框内 token 作为起点、再按多样性补满，预算不变（建议，未做）。
4. **DivPrune 底座（DEC-0061）**：论文主表约 56 个，本项目用 64 个，与 CoverPruner 等按 64 个比较的表一致。本项目的 DivPrune-64 是“按 Algorithm 1 的本实现”，不是论文自己的数字。论文没有 VisionZip 对照，本项目的 +2.20 / +1.63 是自己的校准，方向与查新补充摘录的 CoverPruner 表（DivPrune − VisionZip：VQAv2 +1.7、GQA +2.4；HTML 摘录，未对照 PDF）一致。

### 新颖性威胁（AI）

1. **按题目句式路由**：DivPrune 没做，不构成威胁。
2. **K = 1 的放置**：不新。DivPrune 的 Table 3 已有同算力的 Layer 1（查新补充另有 ShaRP）。本项目已把 K 只当作预算计法的事实（论文主张与证据_草稿的 CL-11），与此一致。
