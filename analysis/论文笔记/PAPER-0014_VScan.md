## 研究问题

已有方法要么在视觉编码器输出层按 [CLS] 注意力剪（与题目无关），要么在 LLM 早层按与题目的相关性剪。作者问两件事：只看编码器输出层的 [CLS] 注意力，够不够保住答题要用的视觉信息？LLM 早层是不是剪 token 的好位置？据此设计一个分两段、免训练的方法（p.1 摘要；p.2–3 §1；p.3–4 §3）。

## 方法与贡献

- **整体**：两段，免训练（p.2 图 1 注与 §1；p.6 §4）。第一段在进入 LLM 之前（作者叫视觉编码阶段），与题目无关；第二段在 LLM 中间层，按与题目的相关性再剪（p.2 §1；p.6–7 §4.1–4.2）。作者说第一段留下的是“语义重要且空间上分散”的 token（p.2）。
- **全局扫描**（p.6 §4.1）：在编码器输出层（LLaVA-1.5 是倒数第二层）按 [CLS] 对各 token 的注意力，取最高的一批，沿用 FasterVLM [70] 与 VisionZip [64] 的做法。阈值 τ 按注意力的分位数设，使留下的个数正好是目标个数（AI：相当于取前 k 个）。没有 [CLS] 的模型（Qwen-2.5-VL）改用每个 token 从其他 token 收到的平均注意力（p.6）。编码器这一段各注意力头怎么合并，公式没解析出来（UN；LLM 那一段写明是各头平均，p.7）。
- **局部扫描**（p.6 §4.1）：把图像分成互不重叠的窗口，名额在窗口之间平均分，每个窗口里按浅层 l 的 [CLS] 注意力取最高的。l = 6（LLaVA 系列）、l = 8（Qwen-2.5-VL）（p.8 §5.1）。窗口有几个、多大，全文未见（UN）。
- **两者怎么拼**：默认全局、局部各占一半；为了不重复，先选局部，再从其余 token 里选全局（p.6 及脚注 1；作者说这个先后对结果影响不大，没给数字）。第一段留下的比例记为 R1。
- **合并**（p.6–7 §4.1，式 4）：每个没选上的 token 按余弦相似度找最相似的已选 token；全部分完组后，组内取平均，作为这个已选 token 的新表示（沿用 ToMe [6] 的平均合并）。合并是并进已选 token，不新增 token，所以个数不变（AI，依据是 p.6–7 的描述）。余弦用的是哪一层、哪种特征（隐藏状态、key 还是投影后的向量），全文未见（UN）。
- **LLM 中间层剪**（p.7 §4.2）：在第 k 层算最后一个指令 token（与 FastV 用的同一个位置，p.4 引 [12]）对全部视觉 token 的注意力，各头平均，留最高的 R2。默认 k = 16（LLaVA 系列，32 层）、k = 14（Qwen-2.5-VL-7B），Qwen-2.5-VL 3B、32B 取正中间那一层；默认 R2 = 33.3%，R1 随目标预算调整（p.8 §5.1）。这一步剪掉的 token 不合并（全文只写了“选”，AI）。
- **与 KV 缓存、FlashAttention 兼容**（p.7）：剪在 token 写入缓存之前；第 k 层的注意力在标准层外用普通注意力另算一遍，所以层内仍可用 FlashAttention。
- **在 LLM 之前还是之内剪**：两处都剪。第一段在编码器跑完、进 LLM 之前；第二段在 LLM 第 16 层。编码器本身没有少算：局部扫描用第 6 层的分数，全局扫描与合并都要用到输出层的全部 token；附录 B.2 的 FLOPs 也只算 LLM 层（AI，依据 p.6–7、p.22）。
- **是否免训练**：主方法免训练（p.2、p.6）。附录 A.4 另报告了带 VScan 微调的版本（p.20 Table A3），不是主方法。
- **是否用到题目文字**：第一段不用（§5.3 称之为与题目无关，p.11）；第二段只通过第 16 层最后一个指令 token 的注意力间接用到题目，不直接用题目里的词（p.7）。
- **作者列出的三点贡献**（p.3）：①分析视觉信息在整个模型（编码与解码两段）中怎样变化，为剪枝设计提供依据；②提出两段式、免训练的 VScan，同时减少视觉冗余和与题目无关的 token；③在 16 个 benchmark 上，在紧预算下稳定优于现有方法。

## 预算口径

- **“保留 N 个”是层平均**：LLaVA-1.5 主表的 192 / 128 / 64 是“在 LLaMA 全部 32 层上平均保留的视觉 token 数”，对应剪掉 66.7% / 77.8% / 88.9%（p.8 §5.2）。
- **VScan 自己怎么分**：64 档进 LLM 之前留 96 个，到第 16 层剪到 32 个，平均 (16×96 + 16×32)/32 = 64（p.21 B.1；p.8 §5.1 的 R1 = 16.7%、R2 = 33.3%）。按“R2 固定 33.3%、调 R1”的规则推算，128 档是 192 → 64，192 档是 288 → 96（AI；全文只写了 64 档的例子）。Table 7 的 KV 缓存比例与这一推算相符：按两档反推，每题都约有 63 个非视觉 token（AI，见 E-VS-15）。
- **所以 LLM 的输入个数不等于 N**：64 档 VScan 进 LLM 的是 96 个，是 VisionZip-64 的 1.5 倍；后 16 层只有 32 个，是它的一半（AI，据 B.1）。
- **CLS**：VScan 用 [CLS] 的注意力打分；[CLS] 本身是否作为一个 token 送进 LLM、是否算在 96 个里，全文未见（UN）。对照：本项目读 VisionZip 代码时看到，VisionZip-64 是 [CLS] + 53 个主导 token + 10 个上下文 token，[CLS] 算在 64 里（[VisionZip 笔记](PAPER-0006_VisionZip.md) E-VZ-1；[已发现的实验现象](../已发现的实验现象.md) F57）。
- **合并 token**：VScan 把未选 token 并进已选 token，不另占名额（AI，据 p.6–7）；VisionZip 的 10 个上下文 token 要占名额（同上）。
- **与 FastV 一族怎么对齐**（p.21 B.1）：
  - 对 VisionZip 这类在 LLM 之前剪的方法：按“全部 LLM 层的平均保留数”对齐，作者说这大致对应推理复杂度与速度。
  - LLaVA-1.5 主表（Table 2）里的 FastV、SparseVLM：作者说它们原论文的数字按“最终 token 数”报告，比 VScan 占便宜；因为没能完全复现，仍直接抄原论文（SC）。
  - Qwen-2.5-VL 与 Video-LLaVA 的实验里，FastV、PDrop 是按层平均重跑的（标 †）。例：FastV 要平均 11.1%，就从第 2 层起只留 5.2%，(100%×2 + 5.2%×30)/32 = 11.1%（DE）。这与本项目 K = 2、留 30 个的计法相同（576 × 5.2% ≈ 30；AI）。PDrop† 的分段日程怎么定，全文未见（UN）。
  - LLaVA-1.5 的 Table A4 中，FastV 的 FLOPs（1.253 / 0.836 / 0.421 T）符合按层平均对齐，它的 POPE（60.7 / 57.2 / 44.5）与 Table 2 抄录的 FastV（64.8 / 59.6 / 48.0）不同，看起来是重跑（AI）；PDrop、VisionZip 的 POPE 与 Table 2 相同（p.21 Table A4；p.9 Table 2）。哪些重跑、哪些抄录，全文没说（UN）。
- **FLOPs 口径**（p.22 B.2）：照 PDrop，只算 LLM 解码层在预填充阶段处理视觉 token 的理论 FLOPs；每层是带因果掩码的自注意力加 FFN，n_k 是第 k 层的视觉 token 数，d 是隐藏维度，m 是 FFN 中间维度。公式本身没解析出来。按每层 4nd² + 2n²d + 3ndm（乘加算一次）、d = 4096、m = 11008、32 层算：n = 576 正好得 3.817 T；64 档 VScan（16 层 96 个 + 16 层 32 个）得约 0.416 T，VisionZip-64 得约 0.4155 T，FastV（2 层 576 个 + 30 层 30 个）得约 0.421 T，都与表中一致（AI，本笔记的计算）。所以表中的 FLOPs 不含视觉编码器、文本 token、解码阶段，也不含扫描、合并和第 16 层另算注意力的开销（AI）。
- **时延口径**（p.12 §5.4 Table 7）：处理 POPE 全部样本的总时间和预填充时间（秒）。硬件、batch、是否开 FlashAttention，都没写（UN）。只说 LLaVA-NeXT-7B 的 11% 档开 FlashAttention 后，时间从 488 秒降到 473 秒（p.12；原文叫 inference time，488 对应 Table 7 的预填充那一列，AI）。

### 重叠（AI）

1. **两段式**：“进 LLM 前压缩 + LLM 内按题目再剪”已被 VScan 做过。本项目早已知道（DEC-0008 淘汰 C4），不再作为方法主张。
2. **层平均口径**：VScan B.1 用同样的计法，连 FastV 第 2 层后留 30 个的对齐都一样（p.21）。本项目不能说这个口径是自己提出的；反过来可以引 B.1 作先例。要注意 VScan 自己的 LLaVA-1.5 主表并没有对 FastV 一族做到这一点（E-VS-6）。
3. **早层位置偏差**：VScan 已经写了（E-VS-13）。本项目的 F16 是定量的补充，不能写成首次发现。F54 中“居中框覆盖”在 FastV 上有用（+1.14 / +0.50，K = 2）、在 VisionZip 上没用（F57），与 VScan“早层偏向底部、深层转向中部”的描述方向一致。
4. **同一层平均下怎么在各层分配 token**：VScan 的 Table 1（剪在哪层）和 Table 6(a)（两段比例）已经在问这个问题。本项目的 K = 1（576 → 47）是同一类问题里的另一个点，不能把“同样预算下的深度分配”写成新问题；能写的是 K = 1 这个具体点及其在 64 档的结果。
5. **按窗口或分块保证空间覆盖**：VScan 的局部扫描与 A 的 6×6 分块轮流取思路相近，“分块保证空间覆盖”本身不新。
6. **第一段的出发点**：都认为 [CLS] 注意力偏向显著物体（VScan 图 2 左，p.4；本项目 EXP-0028：VisionZip 的 53 个主导 token 平均 26.4 个落在题目点名的物体上，F57）。VScan 的补救是局部窗口加合并，DivPrune 的补救是特征多样性。

### 可辩护的差别（AI，附理由）

1. **按题型路由**：VScan 对所有题用同一组 R1、R2、k（p.8），没有按题型分配（Study 3 只比较了 GQA 与 POPE 两个 benchmark，p.5–6；E-VS-23）（复核时改正：原写“没有题型分析”）。本项目按题目开头分流，并有按答案类型的证据（F38、F39 等，见 IDEA-0003）。
2. **题目在 LLM 之前就进入选择**：VScan 的第一段与题目无关，第二段只在第 16 层通过注意力用到题目。本项目的题目查询在输入层词向量空间直接算余弦。VScan 只在构造对抗子集时用过 CLIP 的“按题目选 token”（A.1，p.18），那不是方法的一部分，也没有全集上的结果。
3. **K = 1**：VScan 只测了 k = 2～24，并主张避开早层（p.6）；本项目 K = 1 在 64 档好于 K = 2（F51）。理由：两者条件不同。VScan 的 Table 1 先用全局扫描减到 288 / 144 个，层平均 216 / 108 个，是宽松预算；本项目从 576 个直接到层平均 64。而且在层平均 64 下只在 LLM 内剪时，最多只能让前 3 层看全部 576 个（第 3 层起留 11 个；4 层就超过 64）；想在第 16 层剪，必须先在 LLM 之前减到 128 个以内（AI 计算）。所以 VScan 的“晚剪”与本项目的 K = 1 不在同一个设计空间里，不矛盾，但论文中要正面说明。
4. **评测方式**：本项目的对照都自己跑，给按图像重抽的区间，确认集预注册；VScan 在 LLaVA-1.5 上抄对照数字、单次、无区间（E-VS-6、E-VS-9、E-VS-23）。这是方法学上的区别，不是方法贡献。
5. **按题型拆分的证据**：VScan 只有 benchmark 总分；本项目有“题目信号对哪类题有利、对哪类有害”的拆分（F38、F39、F43）。

### 新颖性威胁（AI）

- **两段式**：高（已知）。
- **同一层平均下的深度分配、早剪与晚剪的比较**：中。VScan 已在同一口径下比较过剪的层（Table 1）和两段比例（Table 6a）。本项目 K = 1 的结论（早一层、多留 17 个更好）是 VScan 没测到的点，方向又与 VScan“往后剪更好”的主张相反，必须在论文中与 VScan 对照讨论，不能只引 FastV。
- **位置偏差的观察**：中（定性观察已有）。
- **按题型路由、题目查询、覆盖 16、以 DivPrune 为底座**：低，VScan 都没有做（E-VS-23）。VScan 是否已经做了我们想做的事：没有。它做了的是两段式、层平均对齐、位置偏差的观察和同口径下的深度分配比较。
- **对结果的威胁（比新颖性更大）**：VScan 报告 64 档比 VisionZip-64 高很多：GQA +3.2、VQAv2 +3.0、POPE +8.0（p.9 Table 2）。本项目现在的最好结果比自己跑的 VisionZip-64：GQA 合并 +2.16、VQAv2 合并 +0.19（F69）；DivPrune-64 开发集 VQAv2 +2.20、GQA +1.63。如果 VScan 的差距在本项目的环境里也成立，它在两个集上都会高于本项目现在的最好结果。限定：VScan 表中的 VisionZip 是抄的，单次，划分未知；本项目的 VisionZip-64 在 VQAv2 上相对 vanilla 的比例（92.3%）与 VisionZip 原文一致（见 CLASP 笔记的对照），说明 VisionZip 那一侧大致可比，但 VScan 一侧没有在本项目环境里跑过。POPE 上，VScan-64 的 85.0 也高于本项目 K = 2 时期 A′+B+V-64 的 82.74（F1，CLASP 笔记）。审稿人很可能要求与 VScan 比。

### 能借鉴什么（AI，都未做）

1. **在 DivPrune 底座上试“前重后轻”**：LLM 之前用 DivPrune 留 96 个，第 16 层留 32 个，层平均仍是 64。这是 VScan Table 6(a) 那一行在本项目底座上的版本：VScan 自己的数据里，同一编码阶段选择下，“96 → 32”比“64 个均匀”GQA 高 1.6、MME 高 47（p.11，单次）。第 16 层的打分可以比较两种：最后一个指令 token 的注意力（VScan）与题目查询（只对被路由的题）。作为方法主张不新，作为“底座怎么用预算”的实验有用；可以与 DivPrune-64、K = 1 的 DivPrune（任务说明：VQAv2 −1.51、GQA +0.88）放在一起比。先要确定保留 token 的位置编号怎么处理（VScan 没写）。
2. **后层不留视觉 token，把名额挪给前层**：VScan Table 1 里第 24 层起全不留只低 0.5 / 0.3（宽松预算；按本笔记对错位表格的读法，E-VS-10），Table 6(a) 里第 16 层起全不留时 MME 最好（1720）、GQA 最差（52.7）。放到 K = 1 上：第 24 层起不留，第 1–23 层可以留 64 个（(576 + 23×64)/32 = 64）；第 16 层起不留，第 1–15 层可以留 98 个（AI 计算）。F51 说这个预算下“留的个数比打分层更重要”，方向上支持多留。按题型：VScan Study 3 说 yes/no（POPE）的预测约在第 16 层稳定、开放式（GQA）约在第 20 层（p.6），提示被路由的 yes/no、how many 题可以更早停掉视觉 token，开放式题晚一点。限定：MME 与 GQA 的差别不只在题型；单次运行；需要代码支持第二个剪枝点。
3. **合并**：在 DivPrune 或 K = 1 上把没选上的 token 并入最相似的已选 token（VScan 式 4），不增加个数。可以检验 F62 中“VisionZip 的 10 个上下文 token 合并了其余信息”的推测。VScan 没有单独测合并，所以这是没验证过的部件。
4. **测第 16 层的注意力是否随题目变**：本项目测过第 0–2 层几乎不随题目变（CL-1）。VScan 的第二段依赖“中间层的注意力与题目相关”，但没有测（全文未见）。用 CL-1 的同一方法测第 16 层，成本低，能回答“题目信号该在输入层词向量里取，还是在中间层的注意力里取”。
5. **写作**：B.1 的口径说明可以直接引作“层平均口径”的先例；同时指出 VScan 自己的 LLaVA-1.5 主表对 FastV 一族没有做到同口径。
