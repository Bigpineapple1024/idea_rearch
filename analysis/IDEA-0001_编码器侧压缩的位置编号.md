## 问题与预测

- **要验证或排除的问题**：编码器侧压缩时，位置编号方式是否影响准确率；若有影响，是哪一个因素造成的。
- **假设与可推翻结果**：见 yaml 中的 H1/H2。A/B/C 三组差异都在噪声范围内，就推翻“位置编号对编码器侧压缩重要”。
- **直接证据、推断与未知**：
  - 直接证据：VisionZip 压缩位置，FastV 与 SparseVLM+ 保留位置（DE）；SparseVLM+ 把保留位置当作改进（SC）。
  - 推断：M3 的两个方向。
  - 未知：真实模型中的效应大小和方向。
- **研究性质**：探索性（pilot）。新颖性：已检索到的工作中，保留原始位置只出现在 LLM 内剪枝（FastV、SparseVLM+）中；编码器侧压缩的位置编号尚未查到专门研究。检索只到摘要级，需补读。
- **生效条件**：baseline 复现通过，即 vanilla 与官方值相差 ≤1 个点、VisionZip 与论文值相差 ≤1 个点；且 EXP-0002 的损失分解没有把本包排到 C2 之后太远（排序见路线总览）。

## 可执行设计

- **baseline**：LLaVA-1.5-7B + VisionZip（commit 8f86b55c），预算 (54,10)、(108,20)、(162,30)；LLaVA commit c121f043；评测脚本见 code/token_pruning/。
- **三组（只改 LLM 中视觉 token 和后续文本的 position id，其余完全相同）**。设图像起始位置为 s，CLS 在三组中都放在 s：

| 组 | dominant patch 的位置 | contextual token 的位置 | 文本起始位置 | 对比含义 |
| --- | --- | --- | --- | --- |
| A（VisionZip 原样） | s+1, s+2, …（连续） | 接在 dominant 之后连续 | 紧接视觉 token | 对照 |
| B（保留原始空间位置） | s+1+原始 patch 下标 | s+1+其中心 token 的原始下标 | s+577 | 空间间隔 + 远文本距离 |
| C（连续，但文本距离与 B 相同） | 同 A | 同 A | s+577 | 只改文本距离 |

  B vs C：文本距离相同，只差空间间隔（检验 H1）。A vs C：视觉位置结构相同，只差文本距离（检验 H2）。解码时位置从最后一个 prompt 位置继续递增。

- **单变量**：三组只改 position id。合并方式、CLS 等其他变量留给 IDEA-0002。
- **主指标与阈值**：POPE 准确率差值 ≥0.5 个点，或 MME 感知总分差值 ≥20 分，同时 95% 置信区间不含 0，才视为有实际意义（阈值依据：LLaVA 系列论文中方法间常见差距，属主观设定，执行前可调整但须冻结）。
- **局部诊断**：在 POPE 前 200 题上，记录最后一个文本 token 在每层对全部视觉 token 的注意力总量（需要显式注意力，诊断运行单独进行，不计入延迟）。
- **潜在损失与成本**：B/C 组序列的位置编号变大，但长度不变，计算量与 A 组相同。
- **重复**：贪心解码是确定性的，不同种子不产生差异；用题目层面的 bootstrap 估计不确定性。
- **独立验证**：若 POPE/MME 出现差异，再用 GQA（testdev-balanced）验证，不在同一测试集上反复调参。
- **执行命令**：position id 改写需要在 `code/token_pruning/` 中新增一个 LLM forward 包装（与 fastv_llava.py 的做法相同），**尚未实现**；按流程在 EXP-0002 复现通过后再写，并先用 smoke_test 风格的 CPU 测试检查位置编号。
- **预算**：最多 30 次运行，约 10 GPU 小时；超出就停下复盘。

## 预先制定的解释规则

| 情形 | 支持 / 削弱什么 | 仍不能排除什么 | 下一步 |
| --- | --- | --- | --- |
| B 或 C 优于 A，且超过阈值 | 支持“位置编号对编码器侧压缩重要”；B vs C、A vs C 指出是哪个因素 | 只在 LLaVA-1.5 / CLIP-L 上成立 | GQA 独立验证，再看 LLaVA-NeXT；进入方法章节 |
| B 或 C 劣于 A，且超过阈值 | 支持“压缩位置反而有利”（H2 方向），解释 VisionZip 为何不保留位置也表现好 | 原因可能是注意力分布以外的因素 | 用注意力诊断确认机制；作为分析结论写入论文 |
| 局部诊断有变化（注意力总量不同），但准确率无差异 | 位置改变了注意力，但没有改变结果 | 主指标不够敏感 | 看子项和生成长度，然后转到 IDEA-0002 |
| 三组都无差异 | 当前设置下位置编号不重要，C1 削弱 | 更低预算（如 32）或其他模型上可能不同 | 记录为边界结论，转 IDEA-0002 |
| 实现失效或运行不完整 | 无结论 | — | 先用 CPU 测试确认 position id 确实按设计生效，再重跑 |

成功 / 停止 / 回退标准：18 次主运行完成即决策；最晚在 EXP-0002 完成后 3 周内给出结论。超过 30 次运行或 10 GPU 小时仍无结论就停止并复盘。
