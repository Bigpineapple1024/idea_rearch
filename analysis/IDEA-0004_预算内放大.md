## 要解决的问题

路由把开放式题（VQAv2 的 other 类，GQA 的 what、which、who 等）全部交给强对照 A。A 选 token 几乎不随题目变化：同一张图换题目，保留集合的 Jaccard 为 0.945～0.957（F15、F28）（2026-10-29 完整阅读补注：这个区间不是 A（去位置 + 分块 + 排除填充区）自己的值，实验记录里没有单独给出 A 的这项 Jaccard。0.945～0.957 来自 FastV 原版（0.948 / 0.957，EXP-0006）、只去位置（0.957，EXP-0008）和只覆盖（0.945，EXP-0010-R01）；最接近 A 的去位置 + 覆盖是 0.934（EXP-0010-R02）；F28 的第 1 层各行是 0.928～0.980。“几乎不随题目变化”的结论不变）。64 档上，开放式题比 vanilla 低约 10 分，比 VisionZip-64 低约 4 分（F43）。

EXP-0023 的诊断（test1，事后探索）：

- 答案若是另一个物体，它多半与话题物体重叠（57%），落在周围一圈的只有 26%（F44）；
- 题目查询（A′+B+V）输给 A，主要发生在它把答案物体上的 token 挤掉的题上（−17.84，F45）；
- 颜色题受剂量限制：话题物体上保留的 token 越多越准（36.0 → 49.2 → 67.9）；A 比 vanilla 低 17.7 分（F46）。

所以开放式题缺的是被问区域的**细节与覆盖**：30 个 token 里落在被问物体上的太少、太粗，问题不在看错了地方。

## 方法

### 1. 定位（不增加模型前向）

- 用 IDEA-0002 的题目查询 q：题目各词输入 embedding 的加权均值，权重为 IDF × 可见性。
- 算 576 个图像 token 的输入 embedding 与 q 的余弦，取非填充区最高的 8 个，围出正方形框：
  - **边长**：这 8 个的行列跨度，下限取 8 与“原图 336 像素所占的边长”中的大者（640 像素的图为 13，500 像素为 16），上限 16。这样裁剪图不会被放大到超过原图自己的分辨率。（2026-10-29 完整阅读补注：代码里“原图 336 像素所占的边长”按 ceil(24×336 / 长边) 计算（fastv_llava.zoom_box），500 像素的图是 ceil(16.13) = 17，被上限 16 截断，上面写的“500 像素为 16”是截断后的值；长边小于 504 像素（24×336/16 = 504）的图，裁剪图仍会被略微放大，500 像素时裁剪约 333 像素、放大约 1%，480 像素时约 5%。IDEA-0004 已结束，影响很小。）
  - **位置**：中心是按分数加权的中心；框限制在图像的内容带里（至少一半在图像内的行列），带比框窄时缩小框，所以裁剪图是正方形，不带补边。
  - **例外**：只有极扁的图（内容带比 8 个 patch 还窄）才允许裁剪图带补边，这时各种取法都跳过补边 token。
- 按 LLaVA 补成正方形的几何（expand2square），把框映射回原图像素。

### 2. 放大（zoom）

- 从原图裁出这个框，按 LLaVA 的同一流程重新过视觉编码器与投影层，得到 576 个细节 token。
- 取其中 n = 16 个，插在 576 个原图 token 之后、题目文字之前。两种取法：
  - **池化（pool）**：裁剪图的 24×24 个 token 按 4×4 分块求平均，每个块均值覆盖裁剪图的十六分之一。颜色等题需要物体表面的统计。
  - **lattice（grid）**：取 4×4 个网格点上的 token。
- 剪枝阶段只保留 keep − n 个原图 token，n 个放大 token 不参与剪枝，所以剪枝后的视觉 token 总数仍是 keep。层平均多 n·K/32（K = 2 时 +1.0），被放大的题多一次视觉编码。

### 3. 覆盖（cover，对照）

- 不重新编码。框内名额 = A 自己在框内的个数 + cover（16），按 A 的规则（除以位置先验后的注意力分数，分块轮流）在框内取，其余从框外补齐。
- 用来区分：放大有效，是因为“重新编码看得更细”，还是只因为“把名额挪进了被问的区域”。

### 4. 预算杠杆（K = 1）

- 在第 1 层剪枝、保留 47 个：层平均 63.5，与 K = 2 保留 30 个的 64.1 相当。深层多 17 个 token。
- 这是 FastV 的超参数，不是本模块的贡献。设计评审认为它是最可能带来大增益的改动，所以一起测。放大也在 K = 1 上测：31 个原图 token + 16 个放大 token，层平均 64.0。

### 5. 作用范围

- 开发集上放大配置对全部题运行（s_min 0）。“只放大不路由题”的版本由拼接得到：本运行在不路由题上的答案，加同 K 路由在被路由题上的答案。这是精确的，因为各题的预填充互相独立。
- 运行前、只用题目文字的事实（`zoom_share.py`，不读答案）：不路由的题中 99% 满足 S ≥ 0.2，所以原定的门槛 0.2 几乎不起作用；不路由的题占 48.7%（VQAv2 dev2）、54.9%（GQA val400）。

### 实现

- `fastv_llava.py`：
  - `zoom_box`（内容带、原图分辨率下限、居中选项、诊断信息）；
  - `zoom_pick`（跳过补边）、`zoom_pool`；
  - `_zoom`（在 `prepare_inputs_labels_for_multimodal` 之后插入）；
  - `fastv_forward` 的偏移与覆盖分支。
- `run_eval.py`：
  - `--fastv-zoom n`、`--fastv-zoom-pick {grid,query,pool}`、`--fastv-zoom-source {crop,full}`、`--fastv-zoom-centre`；
  - `--fastv-zoom-on {unrouted,all}`、`--fastv-zoom-box`、`--fastv-zoom-smin`、`--fastv-cover`；
  - `--fastv-zoom-log`：每题一条记录，含 S、框、裁剪像素、边长、跨度、框内的前 8 个、选中的位置、补边上的个数、覆盖的改动；
  - 逐层与保留 token 的记录里另记放大 token 数。
- `exp0002.py`：EXP-0024 的配置（见其计划）。
- **CPU 自检 `check_zoom.py`（56/56 通过）**：
  - 不放大、不覆盖时，与已提交的代码逐题相同（两个进程）；
  - 放大的题第 0 层多 n 个 token，第 2 层的视觉 token 仍为 keep；
  - 插入的 token 分别等于：
    - 裁剪图重新编码后选中位置上的值（lattice）；
    - 它的 6×6 块均值（池化）；
    - 原图 token 在内容行上的块均值（全图池化）；
  - 框就是题目查询指向的位置，居中框的边长与之相同；
  - 四种图像比例下框都是正方形、在内容带里、不小于原图分辨率边长；极扁的图上各种取法都跳过补边；
  - 覆盖的保留集合等于离线规则，框内个数等于 A 的个数 + cover；
  - 逐层记录把放大 token 算作视觉 token；
  - 参数组合的拒绝与配置核对。

## 方法来源（领域 B / C）

- **领域 B：主动视觉与中央凹注视（foveation）**。
  - 人眼先用低分辨率的周边视觉找到目标，再把高分辨率的中央凹转过去看。
  - 计算机视觉中的对应做法：AutoFocus（Najibi 等，ICCV 2019）先在低分辨率图上预测可能有小物体的区域，只在这些区域放大处理。
  - 起作用的部分：先粗定位，再只对少数区域花高分辨率的计算。
- **领域 C：多模态大模型的免训练裁剪**：见下一节。

## 相近工作与新颖性

来源：2026-10-25 设计评审代理的检索，只读摘要页与 HTML，未读 PDF，属于摘要级，写论文前要逐篇读原文。

- **没有找到完全相同的做法**：零训练、单视图模型、不加 LLM 前向，在固定的 LLM 视觉 token 预算内，对题目定位的区域重新编码。
- **每个部分都有很近的先例**：
  - **ViCrop**（ICLR 2025，arXiv 2502.17422）：免训练裁剪重新编码。
    - 它用 LLM 注意力定位，要多一次前向或梯度；裁剪窗口为输入分辨率的 1～2 倍；把裁剪图的 token 全部拼上，视觉 token 翻倍。
    - LLaVA-1.5 上 TextVQA 47.80 → 55.17、V\* 42.41 → 62.30，但 GQA 只 +0.5、VQAv2 只 +0.9。
  - **CROP**（EMNLP 2025，arXiv 2505.21233）：用微调的 Qwen2-VL-2B 预测区域，K = 2 时只留区域 token。同样大小的居中或随机区域会大幅下降，所以它的杠杆是定位质量。
  - **F³A**（arXiv 2605.16359）：免训练、不加 LLM 前向。先粗定位证据，再局部细化，并保留覆盖、回收覆盖不足的区域，在固定预算内完成。与“覆盖”很近。
  - **FSR**（arXiv 2602.05809）：把固定预算分成 focus、scan、refine。
  - **跨裁剪图分配预算**：GlobalCom2、HiRED（LLaVA-NeXT 的多裁剪图输入）。
  - **训练出来的放大策略**：VisionThink（NeurIPS 2025）、ERGO（ICLR 2026）、AdaptVision。
  - **按文本—图像相似度选 token**：TRIM、CDPruner、AdaFV 等很常见。IDF × 可见性的查询是本项目自己的，但改动小。
- **可以成立的贡献（推断）是实证性的**：在相同的 LLM token 预算下，重新编码的裁剪 token 相对全局 token 的边际价值，以及它在哪些题族、物体大小上划算。
  - 这需要全图池化与居中框两个对照，否则结果只会被读成“预算内的 ViCrop”或“定位器更弱、免训练的 CROP”。
  - 覆盖单独看不新（F³A、FSR、CROP）。
- **补查（2026-10-25 16 点，EXP-0024 运行开始之前；只读网页正文，未下载 PDF；记录在 `D:\6CJNM007\tmp\exp0024\novelty_check_1025.md`）**：
  - F³A 读了 HTML 正文：只在原图的一次编码中选 token，没有裁剪或重新编码；模型是 Qwen3-VL、Qwen2.5-VL、InternVL3.5，没有 LLaVA-1.5。
  - FSR 读了 HTML 正文：Focus、Scan、Refine 三步都在一次编码中选择或合并 token，没有重新编码。它的表 1（LLaVA-1.5-7B、64 token，论文报告值）：VisionZip 的 GQA 55.1、TextVQA 55.5；DivPrune 57.5、54.5；CDPruner 58.6、55.1；FSR 58.2、55.7。
  - 3 次检索（其中 1 次 extended）没有找到“免训练、在固定的 LLM 视觉 token 预算内重新编码题目定位的区域”的做法。
  - 新看到、未读正文的相近工作：ET-Prune（arXiv 2608.01979，文字多的图上按证据动态分配预算）、RoRA（arXiv 2608.07088，按区域分配预算以恢复局部细节）。两者都是 TextVQA 上的直接对手；确认时要有一个“只在原图编码里重新分配预算”的强对照，本项目的覆盖 16 属于这一类。
  - **底座差距**：64 档的 CDPruner、DivPrune 报告的 GQA 比本项目的路由（EXP-0022：55.47）高 2～3 分。若放大有效，把它作为插件加在更强的剪枝器上是否仍有效，比“只在本项目的路由上有效”更有说服力（推断，未计划）。

## 风险

- **计算开销**：被放大的题多一次视觉编码器与投影层的前向，评审估计预填充多约 20%。论文中必须同时报告 LLM 视觉 token、视觉编码器 FLOPs 与每题秒数，不能只写“token 数相同”。
- **原图 token 变少**：K = 2 时原图只剩 14 个，可能损失全局信息（场景、关系题）。
- **位置题**：放大 token 不带它在原图中的位置；GQA val400 有 505 个 position 类题，单独报告。
- **定位失败**：框可能放错，例如物体很大、物体不在图中、题目不点名物体、读字题。
- **分布外输入**：LLaVA-1.5 训练时只见过一张图的 576 个 token。
- **多重比较**：开发集上比较 3 个候选、6 个变体，选出的配置必须在新数据上预注册确认（VQAv2 test3、GQA testdev）。
