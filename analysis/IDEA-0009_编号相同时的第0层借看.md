## 方法

- **peekc**：K = 1，DivPrune 的 61 个在第 0 层之前选好；第 0 层按整段提示原来的位置计算，每个 token 都看得到被剪的 515 个（只作 key / value）；第 1 层起只留系统提示、61 个 patch 与题目，**按 0、1、2…连续编号**（与 DivPrune 先剪后送时 LLM 看到的编号方式相同）；解码时生成的 token 看不到被剪的 patch。
- **nopeekc**（对照）：同样的 61 个、同样的编号（第 0 层原来的位置、第 1 层起连续），第 0 层谁也看不到被剪的 patch。peekc − nopeekc 只差借看，每一层的编号方式都相同。
- **DivPrune-61**（对照）：在 LLM 之前留同样的 61 个，从第 0 层起就连续编号。nopeekc − DivPrune-61 只差第 0 层的编号（原来的位置对连续）。
- **DivPrune-64**（底座）：按 FLOPs 约与 peekc 相等（被剪的只算 K、V 时 0.998 倍，同 EXP-0034）。

## 两种解释的预测（推断，只为事后对照，不是判据）

- **借看只是纠正稀疏编号的偏“是”**：第 1 层起连续编号后没有偏“是”可纠正，peekc − nopeekc 接近 0，是非题上可能为负（如 POPE，F95）；peekc − DivPrune-64 约 −0.5～+0.3。
- **题目 token 在第 0 层读到了留下的 token 没有的信息**：peekc − nopeekc 两个集都为正（约 +1～+2），peekc − DivPrune-64 也为正。
- 本项目倾向第一种（EXP-0036 的 POPE、MME 都指向纠正），但没有直接证据。

## 相近工作与新颖性
