# 从证据到发现、再回到证据

五个 skills 已从用户附件接入。按步骤执行的操作版见 [SOP：从论文到融合方案](SOP_从论文到融合方案.md)。入口与验证范围见[技能说明](../.claude/README.md)，原始协议见[五技能流程](../.claude/skills/5-skill-research-workflow.md)。文件安装不能替代实际执行。

## 1. 选择与复现 baseline

优先检索近两年引用较高、有源码且可复现的论文，同时检查任务匹配、数据许可、资源成本和评价协议。引用量注明来源及日期，并考虑发表时间，不能等同于质量。有较多衍生工作便于比较改造位置，但不是硬性前提。

固定代码 commit、依赖、数据、划分与指标，复现基线并记录全部运行和与论文的偏差。复现异常先定位环境、数据、配置与实现差异，再开始机制改造。

## 2. 五阶段证据闭环

| 阶段 | 输入 | 输出 | 核验重点 |
| --- | --- | --- | --- |
| Analyze Paper | 原文与解析材料 | ANALYSIS_PACKAGE | 问题、设计、材料、测量、结果与证据位置 |
| Deep Read（仅 Mode C） | 分析包、实验记录等材料 | MODE_C_PACKAGE | P/F/M/E、P×F、对象条件与替代解释 |
| Discover Innovation | 明确的连接点 C | IDEA_PACKAGE | 假设、预测、基线、对照、预算与解释规则 |
| 实际执行 | 已登记方案 | 原始数据与运行日志 | 实际配置、全部运行、偏差和异常 |
| Record Experiment | 方案与原始证据 | EXPERIMENT_RECORD | 事实、解释、待复验假设分开 |
| Squeeze Experiment | 记录及原始证据 | SQUEEZE_REPORT | 动态、错误、子组、边界、机制与稳健性 |
| 回流 Deep Read | 新 P/F/M/E 与反例 | 更新的矩阵及连接点 | 新假设不冒充验证结论 |

模板见 [templates](templates/README.md)，已按 research-pipeline-contract v1.0 对齐统一字段与各技能细化字段。深挖报告先回流 Mode C，再从更新后的连接点生成下一轮 Idea；实际执行独立于五个技能。

组合实验可来自明确连接点，也可探索无关联方法的组合。随机组合注明探索性质、兼容性、预算和对照；不能凭组合本身声称新颖性或因果关系。发现后独立复验，避免不断筛选同一测试集。

## 3. 1a–4b：机制分析与验证

| 阶段 | 动作 | 证据边界 |
| --- | --- | --- |
| 1a | 观察失败及其他实验的现象 | 保留原始证据，不只筛选符合预期的案例 |
| 1b | 分类，找共同模式 | 共同根因仍是候选解释 |
| 2a | 追问至模块、运算、算子 | 明确证据缺口和替代解释 |
| 2b | 建立逐层因果链 | 每条边标明验证状态 |
| 3a | 干预或替换疑似模块 | 尽量单变量，使用适当对照 |
| 3b | 拆解多项改动 | 独立性需验证；强交互时增加组合/因子对照 |
| 4a | 单模块和组合消融 | 量化收益、代价、波动与交互 |
| 4b | 对照原机制预测 | 不只看最终分数，还检查改善路径 |

证据不足就回到缺证据的环节。重复 1a–2b 有助于形成假设，不能只靠追问证明根因，也不要求“完全理解”才允许实验；用最小可区分实验推进。

## 4. 少走反复试错的弯路

- 优先核验已有研究中类似机制、结果和适用条件。
- 实验前写清主问题、局部与整体指标、损失、资源成本、阈值、重复和停止条件。
- 先检验单改动；怀疑交互时比较 baseline、仅 A、仅 B、A+B。
- 局部修复不必然带来整体净收益。指标不动也可能源于噪声、测量或交互，不能直接断定机制弊大于利。
- 结论区分：假设不支持、实现未生效、条件不满足、测量不足或证据不能区分；避免只有“没涨”。
- 不因沉没成本继续补丁。可以记录负结果的知识价值，但不能写成性能提升。
- 子组和错误切片分析注明探索性、多重比较及样本限制；新预测用独立运行或数据验证。

## 5. 跨领域方法迁移

1. 把领域 A 的问题落实到机制，检查是否跨数据集或场景存在。
2. 用底层机制寻找领域 B，核对原文而非只匹配关键词。
3. 明确 B 的原始问题、有效机制和必要条件，区分理论结论与实证范围。
4. 寻找领域 C 的迁移案例，比较适配与生效条件；没有 C 不禁止迁移，但要补验证。
5. 改造 A，使其满足 B 所需条件，登记成本和副作用。
6. 至少比较 A（原始）、A′（仅适配）、A′+B；可行时增加 A+B，检查适配是否必要。
7. 分别验证条件是否建立、目标现象是否改变、整体指标和成本是否可接受。

该路线主要面向应用研究，理论任务需另行适配。相同评价协议与充分重复下区分适配收益和方法收益。见[迁移模板](templates/跨领域迁移方案.md)。

## 6. 骨架、创新与写作

维护 baseline 已知结构、未知机制及文献对应改造位置。高频改造不代表没有创新空间，低频改造也不证明没有问题；依据直接证据、影响、可验证性和预算判断。

a–d 仅为内部描述：a 提出新问题并用新方案解决；b 用新方案解决已知问题；c 迁移已有方案；d 局部微调。不是会议录用标准或研究价值的充分排序。

意外现象可帮助发现新问题，跨领域同机制可帮助形成方案，但新颖性、有效性和证据质量要分别核验，不能仅凭流程生成论文贡献。
